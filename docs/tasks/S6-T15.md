### Ruling 1: a test that no step runs fails the checker

**How "reached" is computed.** It is read from the build's roots and from Zig tokens, in `scripts/check_layers.py`:

1. **The roots.** `BUILD_ROOTS` lists every `"src/....zig"` string `zig/build.zig` holds (seven), each with the step of
   `zig build test` it is the root of, or none: `core/core.zig` (core), `ops/operations.zig` (operations),
   `interfaces/interfaces.zig` (interfaces), `tests/root.zig` (tests), `core/fastmem.zig` (fastmem), and
   `interfaces/main.zig` and `interfaces/abi.zig` (none). The checker fails when the build names a root the table lacks,
   or the table one the build does not name. So a new test step cannot be added without being listed.
   *Corrected after the Verdict:* that held only for a new path string. Deleting a row of `test_roots`, dropping a
   `dependOn` or pasting one root into another row passed (Verdict finding 1). The steps are now read from the
   build's structure, and a real run is compared (below, "After the Verdict").
2. **What a test build compiles in a file.** A test build compiles every `test` of a file it holds and every
   container-level `comptime` block. A container-level declaration is compiled only when something compiled names it,
   because Zig analyses lazily. So an `@import` counts when it is written in a `test` or `comptime` block, or in a
   declaration of the same file such a block names, directly or through other declarations. For example, `_ = engine;`
   compiles `const engine = @import("engine.zig");`. A name after `.` is a member, not one of the file's
   declarations.
3. **The reach.** From each step's root, the checker follows those imports, `.zig` paths only, from file to file. An
   import through a module (`@import("core").fold_test`) is **not** followed: a Zig test build runs the tests of its
   root module's files only, and the module `core` is not the `tests` step's root module.
4. **What counts as a test.** Every `test` declaration of a file counts: `test "name"`, `test name` and `test {}`, a
   test in a nested `struct` included (Zig runs it once the struct is compiled; scratch probe). Comments, strings,
   multiline strings and `@"test"` give no `test` token. *Corrected after the Verdict:* false for a struct nothing
   compiled names, whose tests Zig does not run (Verdict plant A). Such a test no longer counts, and a reached file
   holding one fails.
5. **What fails.**
   - A file holding a test that no step reaches. The message names the file and its first test's line, and says
     where to name it. When a root reaches the file only through a module, the message says so.
   - A module root that leaves out a layer file or a test of its folder, as a `pub const` or in its test-build
     `comptime` block. `OUTSIDE_MODULE` lists the two files that are roots of their own: `core/fastmem.zig` and
     `interfaces/main.zig`.

Three probes, each with its own cache, settled the semantics before the rule was written
(`S6-T15-scratch.noindex/semantics/`, `zig test`):
- an import never referenced: its failing test did not run;
- an import reached through a function a test calls: its failing test ran;
- a failing test inside a nested `struct` that a test names: it ran.
