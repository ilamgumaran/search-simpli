### Deviations and decisions (each amended in `docs/folder-knowledge-implementation.md` in this commit, marked **S3-T4**)

1. **`ss_status` counts over the default scope**, not the whole index
   (finding a; §7, §9). It takes no options, so its scope is the one
   `ss_query` has without options; on an index without labels it is
   byte-for-byte 1.x plus the new tail.
2. **The §8 envelope made exact** (§8): `request` echo with defaults
   (`roots: null` when absent), `scope.roots` = the roots the request could
   see, `labels_applied` always true (saying whether labels hid something
   would reveal hidden files), `warnings` (so far `end_line_clamped`).
   `index_status` and `evidence` keep their v1 shapes (no envelope).
3. **`find`'s `path_prefix` is root-relative** (§8), like `list_files`' and
   like the `path` a hit reports; identical to before with only the legacy
   root.
4. **`list_files`**: `mtime_ms` is null (a generation does not record it;
   `INDEX-STATE.json` is the writer's and may describe a newer generation),
   `size` is the retained length or a pending file's announced size, a
   `total` field, page size 1–1,000 default 100, no FR-22 `kind` filter
   (§8 has none) (§8).
5. **RPC policy and codes** (§6, §7, §8, `docs/tool-protocol.md`): the raw
   service keeps a request's bounded `principal_labels` unless `--labels`
   is given; `-32005` capacity, `-32006` writer busy, `-32004` also for
   files; `apply_changes` is `-32601` without `--allow-write`; the server
   reopens after a write.
6. **`scope.termVisible` removed**, hook = `find.termInScope` (§7).
7. **A lost or damaged source section does not fail the open** (§4).
8. **Sparse line index without a format change** (§4; also noted in
   `docs/source-section-v1.md`).
9. **CLI extras**: `list-files` also takes `--page-size`/`--cursor`; `apply`
   prints a one-line summary (the report with `--json`); a request's own
   `expect_generation` that differs from `--expect-generation` is refused,
   not overridden (§6).
10. **`ss_evidence`** accepts at most 1,000 ids and names the code in its
    error (§8, §9).
11. **ABI test counting**: the six new checks are one per function, each
    asserting several outcomes (success plus every listed error path), so
    the count is 16 + 6 = 22 as ruled.
12. **Dart**: `roots({roots, principalLabels})`; the 2.0.0 `SnapshotStatus`
    and `EvidenceChunk` fields are nullable (null when parsing 1.x JSON);
    the package version stays 0.1.0 (the CHANGELOG is keyed by contract).
13. **`serve --http`'s response buffer grows** (it was a fixed 64 KiB; a
    `read_span` answer can hold 256 KiB).

### Findings (none blocks)
1. **The parity tests always state their parameters.** A surface that injects a different default goes unseen by them: plant C9 (Dart page size 21) passes every test; plant C3 (CLI) is caught only by `cli_test`. One parity request per method with no optional fields would close it.
2. **The Dart package version stays 0.1.0 across a breaking change** (an older library is refused). The CHANGELOG is keyed by contract; a version bump (0.2.0) at the consumer app's pin bump would make the break visible to the pub tooling.
3. **My per-surface p50s differ from the Report's by a microsecond or two either way** (core 4.4 against 3.1 µs, ABI 9.9 against 12–14 µs), under a higher load. Same shape: the ABI adds about 5 µs, RPC about 17 µs, the CLI about 20 ms of process start and open.
4. **The CLI/RPC surface tests skip in CI's Python job** (no Zig there), so parity is checked only where Zig is installed. The Linux native job runs Zig; adding `tests/test_folder_surfaces.py` there would keep the parity under CI.
