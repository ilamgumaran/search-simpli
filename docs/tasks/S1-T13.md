### Findings (none blocking)
1. **The old vacuous no-mask test is still there.** `a failed earlier candidate does not mask a later one` (test lines 151–160) is unchanged. Its opener succeeds on `/pkg/`, the first candidate (`attempts.length == 1`), so nothing earlier fails, and it still passes under P4. The new test does the job. The old one's name claims a property it does not test, and the Report says "added" without mentioning that it was kept. Rename it (e.g. "the package's copy is tried first and wins") or delete it.
2. **Two of the pin test's three paths do not pin `.app`.** `/Foo/Contents/MacOS/x` and `/Foo.app/Sub/Contents/MacOS/x` are false because `'Foo'` and `'Sub'` fail `length > 4`, not because of the `.app` check. Both still pass under P6, and only `/opt/App.app/Resources/Contents/MacOS/x` fails. The test catches P6, but it rests on one path. Folder names longer than four characters (e.g. `/Folder/Contents/MacOS/x`) would make all three count. S1-T12's suggested `/opt/x/…` would have passed P6 too.
3. **The package README's in-app item names only the "did not ship" error.** `docs/zig-engine-api.md` and the loader's doc comment now also give the "found but could not be opened" case, and the loader says that paragraph and the README "keep it in step". One clause in README item 3 would close it, and the same goes for `PROJECT-STATE.md`. Criterion 4 did not ask for it.
4. **An older README sentence is inexact (outside criterion 4).** Item 4 says the cwd and script candidates are tried "only if no `package_config.json` can be found (e.g. `pub get` was never run)". The code adds them whenever the package's own copy is missing or fails to open, even when package config was found (lines 166–176). Worth a line in the next docs pass.
