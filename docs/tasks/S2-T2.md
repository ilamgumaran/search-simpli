# S2-T2 · Linear-time dictionary build on the import path

**State:** built · **Series:** S2 (research doc, learning 2) · **Depends on:** S2-T1 · **Size:** S · **Builder:** Sonnet 5 · **Tester:** Opus

`postings.build` scans the growing term list for each token
(`zig/src/postings.zig:63`, `:148-153`) and re-scans each chunk for each token
(`:62`, `:96`). Measured: `searchd import-json` takes **12.19 s** for 1,000
documents and **108.25 s** for 10,000 on the M1; `searchd index` does the same
corpora in 0.12 s and 0.92 s (S1-T3's hash-map build, `lexical_build.zig:42-93`).

## Acceptance criteria
1. The `ascii-alnum-v1` import path builds its index through the hash-map
   path, keyed on the ASCII-lowercased token, with exactly the same df, tf,
   document lengths and case-insensitive matching as today.
2. **Bar (a):** `searchd import-json` of the 10k corpus: 108.25 s → **≤ 2 s**
   wall on the M1 (ReleaseSafe, `/usr/bin/time -l`, best of three).
3. **Bar (b):** query JSON **byte-identical** to the pre-change binary for the
   36 BM25-conformance queries, the ABI goldens, and 50 random queries over the
   1k corpus.
4. **Bar (c):** lexical section bytes may differ only in term order; anything
   else is a failure.
5. **Plant:** the timing test fails with the old build restored (best of
   five; assert growth order, not only an absolute).
6. All five suites green after the Report; libraries rebuilt last.
