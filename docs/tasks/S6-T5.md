## Rulings

1. **Inventory first, in the Report, before code.** Where `content` computes each warning and from what state; what `filename_response.zig` writes today under `both` and `filename` on every surface (CLI `query --json`, `evidence`, `search`, JSON-RPC, MCP, `ss_query`); which surfaces carry warnings at all today (S5-T3 recorded that JSON-RPC `search_knowledge` carries none); what `bothGroups` already holds.
2. **`both`.** The warnings are the ones the same query gives under `content`, with one difference that follows from the field: a word is **unmatched** only when neither a chunk in scope nor a visible file name holds it. Expansion and grouping are already shared under `both` (S5-T3, S5-T4), so `query_term_expanded` and `query_term_grouped` report exactly the expansions and members that were searched. Order, codes, message wording and member lists follow the existing warnings; no new code.
3. **`filename`.** The file-name channel is never expanded or grouped (S5-T3), so the only warning is `query_term_unmatched`, for a word no visible file name holds. State in the document that no `expanded` or `grouped` warning can appear under `filename` and why.
4. **The label wall holds.** A word held only by a hidden file or a hidden name gets the same warning, byte for byte, as a word held by nothing (the S2-T4 rule). A test compares hidden-versus-absent pairs under `both` and `filename` as S2-T4's did under `content`.
5. **Additive only.** `content` answers are byte-identical before and after on every surface (the captured-answers comparison, J2 gate clean without re-recording). Under `both` and `filename` the only change is the `warnings` array. No schema field is added; if you find the schema or header must change, stop at the Report.
