**Orchestrator:** Sol 6.1 · **Builder:** Luna (one workflow file) · **Tester:** Sol 6. The owner's model allocation is used in this environment; the Claude models named in the local process are unavailable. Delivery is a reviewable branch/PR, without merging. Use the existing cloud checkout.

## Problem and scope

The existing GitHub job sets `SEARCH_SIMPLI_NO_ZIG=1` intentionally. Python reference checks run, but native engine, C ABI and real CLI process regressions can escape CI. Add a separate Linux native job. Preserve the existing dependency-free job, test assertions, source, contracts and shipped libraries.

## Acceptance criteria

1. On pull requests and main pushes, the additional job installs exactly Zig 0.16.0 for Linux x86_64 from the official HTTPS archive, verifies SHA-256 **before extraction**, and checks the executable version. The published archive checksum is `70e49664a74374b48b51e6f3fdfbf437f6395d42509050588bd49abe52ba3d00`. Use temporary runner storage, bounded job duration and read-only repository permissions. Never bypass TLS/checksum checks.
2. The job runs the existing `zig build test -j2 --summary all` and `zig build test-abi -j2 --summary all` in `zig/`, then the existing `python3 -m unittest discover -s tests -v` from the repository root with `SEARCH_SIMPLI_LIBRARY_PATH`, `SEARCH_SIMPLI_NO_ZIG` and `SEARCHD_BINARY` unset. The real CLI process tests build their own executable using this toolchain. Command failures fail the job; the existing Python-only job remains intact. Platform-specific ctypes/Dart/macOS/Android checks remain separate and are reported honestly.
3. Reproduce installation and native check commands locally, record actual counts/exits/skips, and verify the workflow's embedded install shell rejects a deliberately incorrect checksum before extraction. Independent review checks the workflow structure and failure propagation. Run the requirements validator and documentation path/whitespace checks after filling the Report. GitHub-hosted execution remains unproven until its actual run completes.

## Rulings

This adds enforcement of existing behavior, without a new retrieval capability or contract. No capability approval is required. No wall-clock performance thresholds are added. Native source and library freshness stamp remain unchanged; rebuilding shipped platform libraries is unnecessary for a workflow-only change.
