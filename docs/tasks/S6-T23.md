# S6-T23: all the text (plan step H2)

**State:** filed by the orchestrator, 22 Nov 2026, from `main` at `2d060d2` · **Depends on:** [S6-T22](S6-T22.md) (the judged set this is measured on) · **Plan:** [objective plan](../plans/2026-11-16-objective-plan.md), [the priority of 22 Nov 2026](../plans/2026-11-16-objective-plan.md#the-priority-set-by-the-maintainer-on-22-nov-2026), step H2

## Why

"Take all the text in first." The engine reads 19 extensions. On the judged
set's folder 24 of 264 files are never read (logs, CSV and TSV tables, a shell
script, an XML file, four files with no extension), and none of the 23
questions whose answers sit only in such files is answered. The usage scenarios
of 22 Nov found the same from the outside
([scenarios](../testing/scenarios-engine-2026-11-22.md): I02, I10): `.markdown`
is not read although the engine's own documents name it. A file that is never
read cannot be found.

## What

### Part 1: a design note first (commit it, then stop and report)

`docs/decisions/0005-which-files-are-text.md`, from reading the code, with file
and line:

1. Where the 19 extensions are decided, every place that list is used (index,
   update, direct search, file-name channel, the importer, the bindings, the
   Python reference, documents), and what happens today to a file outside it
   (skipped silently, counted, reported?).
2. The proposed rule, to confirm or correct: **a file is read when its bytes
   are text**, decided by content, with the extension used only to skip known
   binary kinds cheaply and to label the kind. State the sniff exactly (how
   many bytes, valid UTF-8, the share of control bytes, a NUL byte, a byte
   order mark, UTF-16), its cost per file, and what it does with: an empty
   file, a very large file, a text file with one bad byte, a binary file with
   a text header (PDF, an image with metadata), minified one-line files,
   lock files and generated data of many megabytes, dot-files, files with no
   extension.
3. Limits a person would expect: a size above which a text file is skipped or
   read in part (say which, and how it is reported); kinds that are text but
   rarely wanted (say whether any are excluded by default and how a caller
   includes them).
4. What the caller is told: a count of files skipped and why, by kind, without
   paths in the default output; where it appears on each interface; whether
   that is a contract change (a new field) and its version step.
5. Tables and structured text (CSV, TSV, JSON, YAML, XML, logs): what reading
   them as plain lines gives on the judged set's `table` and `where-is-it`
   questions, measured with a prototype, and what it does not give (leave the
   rest to later steps; no table parsing here).
6. What changes for an existing index: are more files indexed at the next
   update without a rebuild; the identity that tells an old index from a new
   one (the readable-set rule as index data, like the chunker identity); what
   an app that pins the engine must do.
7. The effect on the judged set, measured with the prototype: every total and
   kind before and after, tightness included, and any question that gets
   worse. The scorer's "readable now" list is fixed by S6-T22 and is not
   changed here.
8. Index size and time on the 10k corpora and on the judged folder, before and
   after, and which timing rule applies to the change.

If the note finds a contract change is needed, name it and stop; the
orchestrator reads the note before the build.

## Notes for the builder

Never `caffeinate`, never `git stash` in any form, no `sleep` loops or polling,
scratch in a `.noindex` folder beside the worktrees, no recursive `rm` on a
variable path, never `--help` on an unread script, "shown by test X" or "argued"
beside each claim. A prototype for the measurements lives in scratch or under
`scripts/prototypes/`, never in `zig/src/` in Part 1.
