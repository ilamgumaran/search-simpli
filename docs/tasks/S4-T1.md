## Rulings
1. **A lazy open.** `ss_open` validates the manifest and the segment headers and loads only what `index_status` needs; the source section and the per-root statistics, path, sparse-line and position tables load at first use (the source at the first `read_span`, `outline` or `list_files` that needs it; the statistics at the first scored query), once per handle under the engine's existing threading rules (a second caller during the load waits for the first, never loads twice). The validation that `ss_open` did for those sections moves to the lazy load; a corrupt section then fails that first operation with the same error code the open gave before, and `index_status` reports `source: unverified` until the source has loaded (manifest-format-v2 §meta gains nothing; the status schema gains the one field, contracts 2.1.0). Measured in the Report (ReleaseSmall, p50 of 30, the 10k index): `ss_open` before (re-measure the 102 ms) and after (target ≤ 50 ms); the first `read_span` and the first scored query after a cold open before and after; open + first query must not exceed the before figure by more than 10 % (the cost moves, it must not grow).
2. **One changed file under 200 ms in ReleaseSmall.** Measure both candidates on a prototype before choosing, in the Report: (a) a cheaper integrity checksum for sections (CRC32C or xxh3 in place of SHA-256 for the per-section check; SHA-256 stays as the per-file content id and in `INDEX-STATE`); (b) delta sections (a generation appends a delta section for the changed records and compacts when the deltas pass a stated share of the base). Ship the smaller change that meets the bound; if (a) alone meets it, ship (a) and file (b) as a row with the measured numbers. NFR-12's bound in `docs/requirements/cap-19-folder-knowledge.md` tightens to ReleaseSmall with the new measured number.
