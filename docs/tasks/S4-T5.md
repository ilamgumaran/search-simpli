## Rulings
1. **The tools table.** The `search_knowledge` row says the request takes `search_field` (`content`, the default; `filename`; `both`), that `filename` and `both` need `retrieval_mode: lexical`, and that a result carries `matched_in` (`["content"]`, `["filename"]` or both), `basename` and `match_sections`; a `both` query keeps one result per file. Exact field names as `contracts/tools/search_knowledge*.json` state them (read them; quote nothing that is not there).
2. **The loop, step 2 ("Pick the finder").** One new bullet: a question that names a file, or asks "what is the file called … about", or where the word is likelier in a name than in the text: `search_knowledge` with `search_field: filename` (or `both` when the text may hold it too) and `retrieval_mode: lexical`. A result whose `matched_in` is `["filename"]` alone names a file and holds none of its text: it is navigation, not evidence; read the file (`outline`, then `read_span`) before quoting anything from it, and cite the file without lines when only the name matched. An index without the channel answers from the text (the host says so in a warning); do not retry with `filename` there.
3. **"When nothing comes back".** One sentence: before answering that a file does not exist, try the name itself with `search_field: filename` (prefixes and single words of the name), because `find` and the text search do not see file names.
4. **Tests.** `tests/test_example_loop.py` (the stub model follows `SKILL.md` against a real `searchd serve`) stays green and gains one case: a question naming a file in `fixtures/family-folder` by a word that appears only in its name, answered through `search_knowledge` with `search_field: filename` over an index built with the channel on (`searchd index --filename-index` or the equivalent flag the CLI has: read `cli.zig`; if the CLI has no such flag, build the index through the Python bridge's apply path and say so), then `outline`/`read_span`, with the citation of the file and no invented lines. The MCP/surface tests, the judgment pack (0 skipped) and `python3 -m unittest discover -s tests` all green; `scripts/check_no_home_paths.py` clean; `zig build test` not needed (no Zig change: say so).
