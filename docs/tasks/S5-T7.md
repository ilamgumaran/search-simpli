## Source

`core.search` narrows N, the average length and every document frequency to the path prefix before `_bm25_scores`. The engine keeps those statistics over the roots and labels the caller may see and narrows only which chunks may be returned. Ranks agree on today's prefixed tests; the scores do not. The reference is what the engine is judged against, so it must state the engine's rule. **The engine is right and does not change**: no file under `zig/` changes except a `*_test.zig`, so no native rebuild, no contracts change, no app pin.

## Rulings

1. **The fix is in the Python reference's `content` body scoring only.** The statistics come from the authorized set (roots and labels); the prefix filters candidates. Grouped terms (fuzzy-v1, fold-groups-v2) take their document frequency and the average length from the same authorized set. A hidden label's chunks enter neither the statistics nor the candidates.
2. **`filename` and `both` do not change.** The engine's `filename_field.scoreQuery` and the reference's `_search_filename_fields` use their own prefix-scoped statistics on purpose. Their fixtures stay as guards; any moved value there is a defect of this task.
3. **Conformance fixtures.** Plain and grouped `content` cases with files inside the prefix, outside it but visible, and under a hidden label. Raw lexical scores and final ranks are compared between `searchd` (`ReleaseSmall`) and the reference with the tolerance the existing conformance tests use (named in the Report, not chosen anew).
4. **The plants** (review Exit): the prefix filter removed fails a test; a hidden file included in the statistics fails a test; the old narrowing put back fails the new score comparison.
5. **Nothing judged moves.** J2 uses no prefix: every baseline cell on both surfaces is reproduced unchanged and the gate passes with the allow-list untouched. If any cell moves, the builder stops and reports it.
6. **Also in scope, if it is the same change:** the review's R04 notes that `FolderIndex.search` keeps an older ranking. It is **not** fixed here; the builder says in the Report whether R03's change touches it.
7. **Documents.** The 03-next row closed, `PROJECT-STATE.md`, `EXPERIMENTS.md`, the review's R03 marked as landed with the commit, and one sentence in `docs/evaluation.md` or the scoring document that states the rule for both surfaces.
