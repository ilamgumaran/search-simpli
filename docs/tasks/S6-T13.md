## Rulings

1. **The scan.** A test: an index directory whose `MANIFEST` names a documents or lexical file that is missing. Say what `lifecycle.scan` returns today. If it reports the current generation's remaining files as orphans (as read from the code), that contradicts the document's rule "return the error rather than guess": fix `scan` to return an error for a `MANIFEST` whose named file is missing, keep "no `MANIFEST`" as it is, and show no caller outside tests changes behaviour (list the callers). If the reading was wrong, the test pins today's behaviour and the 03-next row is corrected.
2. **The MANIFEST read.** A test that reproduces, deterministically (a test seam or an injected step between the `stat` and the read, not a timing race), an open that sizes its buffer from one `stat` of `MANIFEST` and reads after a publish replaced it with a larger one. Say what the open returns today. If it can return a decode error or, worse, succeed on a truncated manifest, fix the read so the open sees one whole `MANIFEST` (read by handle from one open, or re-check the size and retry a bounded number of times) and returns either a whole old or a whole new generation; the error for a `MANIFEST` that is really damaged does not change. If the reading was wrong, the test pins today's behaviour.

### The tests (`zig/src/manifest_read_test.zig`)

The file is reached from `lazy_open_test.zig` (`test { _ = @import(...); }`), so `root.zig`, which S6-T9 also
changes and which is in the natives' source digest, is untouched; `*_test.zig` files are outside the digest.

1. **`S6-T13: scan returns FileNotFound when MANIFEST names a missing documents or lexical file; no MANIFEST stays
   no error`.** Generations 1 and 2 published (`lifecycle.publishSerialized`); for each of `documents-2.hybseg` and
   `lexical-2.hyblex`: the whole directory scans as generation 2 current, generation 1 superseded; with the file
   removed `scan` must return `FileNotFound`; with `MANIFEST` then removed too it must return no current generation
   and three orphans.
2. **`S6-T13: an open whose MANIFEST is replaced between its stat and its read returns one whole generation`.** The
   seam is in the test only: the open is given a `std.Io` whose vtable is the testing `Io`'s with `fileStat`
   replaced by one that calls the real `fileStat` and then, once, runs a publish of generation 2 through the real
   `Io` (`StatSeam`). The test checks that the step ran exactly once, after a `stat` that returned the old
   `MANIFEST`'s length (so it was the `stat` of `MANIFEST`), and that generation 2 was published whole (a plain open
   afterwards reads it). The two generations are one-document v1 generations whose manifests differ in length only
   through the embedding model id, so the new `MANIFEST`'s length is set to the byte: the stat's length −1, +0, +1
   and +2048 (the bound and one either side, ruling 4). Each of `open`, `openScoped` and `openSource` must return
   generation 1 whole or generation 2 whole (number and text of one generation; for `openSource`, the manifest's
   model id of one generation); an error fails. Which one was read is printed.
3. **`S6-T13: a folder index whose MANIFEST grows across the publish opens whole between stat and read`.** A real
   folder index at generation 9 (`indexer.indexFolder`), and as the step an `--update` publish of three more files
   (`indexFolderIncremental`, generation 10; every section name gains a digit: `MANIFEST` 576 → 580 B), then
   `openScoped` through the seam: generation 9 with one document or generation 10 with four.
4. **`S6-T13: a damaged MANIFEST is refused with the same error as before, by every open`.** `MANIFEST` cut by one
   byte, with one byte extra, with its last byte flipped: `Truncated`, `TrailingData`, `ChecksumMismatch` from
   `open`, `openScoped` and `openSource`; the same on `main`'s code (above).

### The fixes (`14c438a`)

- **`lifecycle.scan`** reads `MANIFEST` itself and maps only that read's `FileNotFound` to "no current
  generation"; then the same decode, reads and `manifest.validateSnapshot` as `publication.loadCurrent`, each error
  returned. A missing documents or lexical file is `FileNotFound` from `scan` (no new error name). `publication.zig`
  is unchanged. **Callers of `scan`:** no `searchd` command, `ss_*` function, binding or Python code. In Zig:
  `root.zig` line 89 `_ = lifecycle.scan;` (a reference in its `comptime` block, not a call); `lifecycle.zig`'s
  three scanner tests; `incremental_indexing_test.zig` ("crash mid-publication…" two calls, "keep_generations=2
  leaves exactly two generations…" one, "lost MANIFEST with only generation 2 on disk…" two; it removes `MANIFEST`
  and generation 1's sections, but scans only after the recovery publish wrote a new `MANIFEST`); the new test. All pass. So no caller outside
  tests changes behaviour.
- **The open.** `snapshot_open.readManifest` opens `MANIFEST` once, `stat`s that handle, allocates that size and
  reads through the same handle (`file.reader(io, &.{})` and `readSliceShort`, what `std.Io.Dir.readFile` does,
  but on this handle), keeping the whole buffer for the free. `loadEngine` (so `open`, `openScoped`,
  `openScopedWith`: `ss_open`, `serve` and `mcp` (`rpc.zig`), the CLI's `query`, `evidence`, scoped commands) and
  `openSource` (called by tests only) use it. The allocation is the same size as before; one `open` and one
  `close` fewer per open. A publish renames a new file over `MANIFEST`, so the open handle keeps the old file and
  the read is whole; the old generation's sections are then read by name as before (if a prune removed them, the
  existing `FileNotFound` and retry apply, unchanged). There is no retry count and no size comparison in the fix,
  so ruling 4's numeric bound is the new `MANIFEST`'s length against the stat's, tested at −1, 0, +1.
  `openDetached` and `openScopedDetached` read no file and are unchanged.
- **Not changed, same pattern (read from the code, not tested):** `apply.readWhole` and
  `generation_alloc.currentGeneration` also size a buffer from one `stat` and read `MANIFEST` by name. In
  `apply.applyParsed` both run after it took `WRITER.LOCK` (`apply.zig` lines 764 to 779), so a cooperating writer
  cannot publish in between. **But `generation_alloc.nextFreeGeneration` (which calls `currentGeneration`) also runs
  before the lease** in a full rebuild: `ss_index_folder` without `update` (`abi.zig` line 832) and `searchd index`
  without `--update` or `--generation` (`cli.zig` line 845). There a second writer's publish between the `stat` and
  the read would make this writer fail with `Truncated` where it would otherwise go on to `WriterBusy` or publish.
  It is a writer racing a writer, not an open, so outside ruling 2; I did not change or test it. For the
  orchestrator. `find_bench.zig` (a benchmark) and `nfr13_arena_test.zig` (a test that replays the
  open's allocations) keep their own copies.
- No contract, C header, format or answer changes: an open that no publish crosses reads the same bytes; the
  damaged-`MANIFEST` errors are the same (test 4).

**Across real processes** (supplementary; a race, so not a test; [`xproc.txt`](../evidence/s6-t13/xproc.txt),
`scripts/prototypes/s6t13/xproc.py`): a writer process renames a 576 B and a 580 B `MANIFEST` (generations 9 and 10
