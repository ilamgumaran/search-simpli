# S3-T1 · Manifest v2, the Markdown chunker, retained source bytes

**State:** proposed (waits for CAP-19 approval, step 6b) · **Date:** 2026-10-31 · **Depends on:** verified S3-T7 (the frozen fixture) · **Size:** M

**Owner:** the Xcode Mac orchestrator (`vizhi-family-helper-pro`) · **Orchestrator:** Claude Fable 5.1 · **Builder:** Claude Opus 5.5 (local) · **Verifier:** Claude Opus 5.5 (local, a different agent)

**Why.** CAP-19 FR-18 and FR-22 (`docs/requirements/cap-19-folder-knowledge.md`), review findings 2 and 7 (`docs/reviews/2026-10-31-folder-knowledge-review.md`): Markdown is chunked by line windows with no headings or section path, the chunker's identity is not in the manifest (CFT-09), and chunks are stripped and LF-joined so byte-exact reads are impossible. Formats: `docs/folder-knowledge-implementation.md` §1, §2, §4.

## Rulings
1. **Manifest v2 (`HYBMAN02`)** as §1: flags `has_source`/`has_positions`, the source filename string, the `meta` JSON with `chunkers[]` (id and parameters) and `roots[]` (this task writes one root `r-legacy` for `index_folder`; S3-T3 fills roots). A v1 manifest still opens; `zig/src/manifest.zig` round-trips both; corruption of the new fields is detected by the existing checksum.
2. **`md-section-v1`** (`zig/src/chunker_md.zig`, new): front matter = a `---` line at line 1 up to the next `---` line within the first 100 lines, parsed as `key: value` string pairs (anything else: the block is kept as metadata text, the file still chunks); ATX headings `#`…`######` (a space after the hashes required) and Setext (`===`/`---` under a non-empty line, outside fences) open sections; a fenced block (``` or ~~~) is never split by a heading inside it; a chunk never crosses a heading; within a section `line-window-v1` applies with the same parameters; a fenced block longer than `max_chars` falls back to line windows inside the fence. Each chunk records `section_path` (heading texts from H1 down to the section's heading, trimmed), `heading_line`, `chunker_index`. Selected by extension `.md`/`.markdown` (case-insensitive); everything else keeps `line-window-v1`, whose golden output (`fixtures/chunk-golden.json`) is byte-for-byte unchanged. The Python reference (`src/search_platform/core.py`) gains the same chunker; a golden fixture `fixtures/chunk-golden-md.json` pins both implementations.
3. **Document records v4** as §2 (chunker index, section depth, heading line, source doc index, section path); readers decode v1–v3 with empty defaults; the chunk id formula is unchanged.
4. **Source section v1 (`HYBSRC01`)** as §4: original bytes, per-file line map over the original line terminators, sha256, bound by the manifest; written when the root's `retain_source` is true (the default for `index_folder` in this task: true, measured cost reported). `read_span` in the core (`zig/src/source.zig`) returns byte-exact lines with context, bounded (400 lines, 256 KiB); without a source section it answers `CAPACITY` `"re-index required: source absent"`. Front matter is returned as part of the bytes.
5. **`outline` in the core**: headings with level, text, line and end line; front matter range and parsed fields; the file's line count and chunker.
6. **Tests.** Zig: manifest v1/v2 round trip and corruption; `md-section-v1` golden (ATX, Setext, nested depth 3, fences, front matter, CRLF, no final newline, BOM, Tamil, an empty file); records v4 round trip and v3 compatibility; source section round trip, line maps for CRLF/CR/LF, `read_span` byte exactness on every fixture file (sha256 of the returned text equals the judgment), the caps. Python: the chunker golden and `outline`. The fixture is `fixtures/family-folder/` (S3-T7). `zig build test`, `zig build test-abi`, `python3 -m unittest discover -s tests`, `dart test` all green; `scripts/check_requirements.py` green.
7. **Measured in the Report:** the retained-source bytes and the document section size for the fixture and for the 10k benchmark corpus (before/after, §13 profile), chunk counts per chunker, `read_span` latency p50.
8. **Diff scope.** `zig/src/manifest.zig`, `chunker_md.zig` (new), `chunker.zig` (dispatch only), `segment.zig` (v4), `source.zig` (new), `indexer.zig` (writing the source section), the Python chunker and reference, fixtures, `docs/manifest-format-v2.md` (new), `docs/segment-format-v4.md` (new), `docs/source-section-v1.md` (new), `docs/folder-knowledge-implementation.md` (amend if the build changes a detail, say so), `PROJECT-STATE.md`. No ABI change yet (S3-T4), no positions (S3-T2), no roots beyond `r-legacy` (S3-T3).
