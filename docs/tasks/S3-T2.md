**Why.** CAP-19 FR-17 and FR-25, NFR-10 and NFR-11; review finding 7 (ordinals plus offsets, conjunctive words, final-token prefix, highlighting). ## Rulings
1. **`HYBLEX02`** as §3: a sorted term dictionary, section 4 positions (token ordinals, delta LEB128 per posting), section 5 offsets (per document, per token start and length in codepoints into the chunk's normalized text), header fields and checksum as specified; `HYBLEX01` still opens with `has_positions` false. The writer sorts terms; the reader keeps v1's zero-copy term slices.
2. **Query modes in the core** (`zig/src/find.zig`, new): `words` = every analyzed query term present in the chunk, BM25 order; `phrase` = the analyzed query tokens adjacent in order by ordinal within one chunk, BM25 order, repeated tokens handled; `prefix` = only the last token may end in `*`, expanded over the sorted dictionary within the visible vocabulary, ≤ 1,000 terms else `CAPACITY`; a quoted query forces `phrase`; `search_knowledge` is unchanged (disjunctive BM25). Overlapping chunks matching the same phrase occurrence (same file, overlapping line ranges, same original-text offset) are deduplicated to the earlier chunk.
3. **Hits** carry `match_offsets` (codepoint ranges into `content`) and a `snippet` (≤ 240 codepoints around the best-scoring window of matches, cut at token boundaries, with `snippet_offsets`), plus `exact_match` (`true`/`false` for phrase, `null` otherwise), `empty`, `coverage {files, sections}`, `truncated`, `pending_files` (S3-T3 fills `pending_files`; this task writes 0), and paging by a generation-bound cursor (`"<generation>:<offset>"`; a foreign cursor is `INVALID_ARGUMENT` `"stale cursor"`). Ordering: score desc, then root_id, path, start_line (INV-08).
4. **Tests.** Zig: v2 round trip and corruption; golden BM25 scores unchanged against `fixtures/bm25-golden.json`; phrase hits on the fixture judgments complete across all pages (precision and recall 1.00 after deduplication), including repeated tokens, punctuation inside phrases, Unicode (Tamil), an empty query (`INVALID_ARGUMENT`), the expansion cap, a phrase that spans a chunk boundary (documented as chunk-local: the judgment lists it as a known miss and the test asserts the miss); prefix recall 1.00; words recall@5 ≥ 0.9; offsets map onto the matched tokens exactly; deterministic order for equal scores; cursor staleness. Python reference implements the same modes for the judgment pack.
5. **Measured in the Report (§13 profile):** `words`, `phrase` and `prefix` p50/p95 at 10k chunks (NFR-10: phrase p50 ≤ 5 ms, words p50 ≤ 1 ms); `HYBLEX02` size versus `HYBLEX01` on the same corpus (NFR-11: ≤ 2.5×); index time and peak RSS before/after. A miss of a target is reported, not hidden, and the rollback (offsets recomputed at highlight time, or positions only) is named with its own numbers.
6. **Diff scope.** `zig/src/lexical_segment.zig` (v2), `postings.zig`, `scoring.zig` (visible-scope statistics hook for S3-T3), `find.zig` (new), `query.zig`, the Python reference (`src/search_platform/`), `docs/lexical-segment-format-v2.md` (new), `docs/scale-benchmark.md`, `PROJECT-STATE.md`, `docs/folder-knowledge-implementation.md` if amended. No ABI/RPC change (S3-T4).

   `HYBLEX02` and writes v2 exactly when the index carries positions: 80-byte

   bytes 0–71 and the payload), sections 1–3 as v1, section 4 ordinals
   (delta LEB128 per posting), section 5 offsets (per document a `u32` token
   count, then per token the start as a delta from the previous token's start
   and the length, in codepoints of the chunk's stored text). The writer
   (`lexical_build.buildPositional`) sorts the dictionary by bytes; the
   reader keeps v1's zero-copy term slices (tested), checks the dictionary is
   strictly sorted (so no hash set), the term ranges contiguous, and every
   rule of sections 4/5 (ordinals strictly increasing and below the document
   length, token count = document length, lengths ≥ 1, no leftover byte)

   manifest's `has_positions` is set exactly when the section is v2 (a

   `--update` write v2; `--update` carries unchanged chunks' exact tokens and

### Deviations from the implementation document (amended in this commit)

- §3: section 5's start delta is from the previous token's start; offsets
  are into the stored chunk text through the NFC map; v2 requires a strictly
  sorted dictionary and contiguous term ranges, validated at open;
  `has_positions` ⇔ `HYBLEX02` and a v1 manifest cannot bind v2, so
  `import-json` stays `HYBLEX01`; on `HYBLEX01` only `phrase` is refused;
  `--update` carries positions; the measured sizes.
- §7: `find`'s scope is the existing `path_prefix`/labels filter until S3-T3;
  BM25 goes through `scoring.CorpusStatistics`.
- §8: hits carry `snippet_start` (CAP-19 FR-17 asks for the snippet's start
  offset) and the snippet is a plain substring (no `…`; the example's snippet
  would read without them); the snippet window rule; phrase occurrences are
  non-overlapping; the deduplication rule made exact and applied to all
  modes; `files` over all pages in ranked order, `coverage` over the page;
  `truncated`/`pending_files` stay `false`/`0` until S3-T3; the refusals and
  their messages.
- §13: the profile as recorded; NFR-10's 10k chunks measured at 19,959.
