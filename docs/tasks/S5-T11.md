## Source

`searchd apply` on a directory with no index creates one with the file-name channel off, and takes no option to turn it on. `searchd index --filename-index` and the C ABI's open options can. So `scripts/j2_run.py` first indexes an empty folder (leaving an empty root `r-legacy`) and then applies its real roots. This task gives `apply` the option, for a fresh index only.

## Rulings

1. **Inventory and specification first, in the Report, before code.** How a fresh index gets its capabilities today on each path (CLI `index`, CLI `apply`, the C ABI, the Dart binding, the MCP and serve surfaces); where the capability is stored; what `apply` does today when the directory is empty, missing, or holds a manifest. Then the specification below restated against what the code really does, with any difference named as a deviation for a ruling **before** it is built around.
2. **The option.** `searchd apply <dir> --changes <file> --filename-index`. No new request field in the changes file and no contract schema change unless the inventory shows the option cannot be a CLI flag alone; if it cannot, stop at the Report.
   - **Fresh directory (no manifest), option given:** one operation publishes exactly the requested roots at the first generation with the file-name channel on. No placeholder root is created. `filename`, `content` and `both` answer at once.
   - **Fresh directory, option omitted:** today's behaviour, byte for byte.
   - **Existing index that already has the channel, option given:** accepted; the apply proceeds as without the option (a repeat of the same command is safe).
   - **Existing index without the channel, option given:** refused with a usage-class error that names the reason; nothing is written, the generation does not move, and the index answers as before. This task adds no migration.
   - The option does not appear on any other subcommand's parser and `index --filename-index` is unchanged.
3. **The capability process.** The additive CLI option goes through the requirements register as the repo's process requires (`scripts/check_requirements` passes; the requirement names its validation). It adds no wire field. If the process requires a named maintainer's approval for this class of change, say so in the Report and build no further than the specification; do not mark any capability Validated.
4. **Tests** (process tests against the built `searchd`, plus Zig unit tests where the seam allows): the four cases of ruling 2; empty roots; labels (a hidden label's file is neither searched nor named in the fresh index); repeat apply; the option given twice; a crash between writing and publishing (the existing recovery test method, applied to the fresh one-step path: after recovery the directory is either no index or the complete first generation, never an index without the channel).
5. **Equivalence.** The index made in one step answers every J2 query identically to the index made the two-step way, on `content`, `filename` and `both`, apart from the absent `r-legacy` root in `index_status`. `scripts/j2_run.py` moves to the one-step setup and its root check no longer allows `r-legacy`. **Every J2 cell on `searchd` is unchanged and the gate is clean without re-recording the baseline;** if a cell moves, stop and report.
6. **Plants**, each in its own scratch copy with its own Zig cache: the option parsed but not threaded to initialization (the fresh-index tests must fail); the refusal removed (the existing-index-without-channel test must fail).
7. **Natives.** `zig/src/cli.zig` is under the digest's inputs. If any digest-covered file changes, the natives are rebuilt with the documented toolchain and stamped, `check_native.sh` and the freshness test pass, and the Report gives sizes and whether each library's bytes changed. Contracts and the Dart version move only if ruling 2's stop condition was lifted by a ruling. Say plainly whether the app needs a pin for this task (expected: not for behaviour; the next pin carries the new digest).
8. **Suites and CI.** Zig Debug and ReleaseSmall, C ABI, Python with and without Zig, Dart; the home-path check; the branch's CI run green on the final commit, native J2 included.
