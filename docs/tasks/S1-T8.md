It replaces S1-T7's choice of 1 for bad byte counts; nothing in either repository depends on that yet.

## Acceptance criteria
1. **One path for argument errors.** Every *usage* error is reported the same way: unknown command, unknown flag for any subcommand, a flag with no value, a missing positional argument, an invalid value for any numeric or enumerated option (`--analyzer`, the `benchmark` mode). Each prints exactly **one** line to stderr naming what was wrong, prints nothing on stdout and no error trace in Debug or ReleaseSafe, and exits **2** (owner's ruling above; this includes S1-T7's byte-count path, which moves from 1 to 2). Deciding what is an error, and its line, lives in `zig/src/cli.zig` as a function that returns the message and the status. `main.zig` only prints it and exits. Zig test for each row of the before-state table that is an error, plus every subcommand's unknown-flag and missing-value cases. Plant: against `origin/main`'s `cli.zig`/`main.zig`. Out of scope: errors from doing the work (a snapshot that cannot be opened, an unreadable folder); say in the Report what those print today, without changing them. **Source scan** (ROLES: "a fix in one place is a search in all"): a Python test reads `zig/src/main.zig` and fails if an argument-parsing path bypasses criterion 1's function, e.g. any `orelse return error.Missing…`, `return error.InvalidArgument`, or `std.debug.print("unknown …` left there. Show it failing on `origin/main`'s `main.zig`.
2. **Numbers are digits only.** Every numeric option uses one parser: `--max-file-bytes`, `--max-total-bytes`, `--max-chars`, `--overlap-lines`, `--generation`, `--top-k`, and the `benchmark` positionals. It accepts `[0-9]+` within the type's range, and options that are positive today still reject `0`. `+5`, `-0`, `1_000`, ` 5`, `0x10`, the empty string and an out-of-range value are each rejected by criterion 1's path. The line quotes the value so an empty one is visible (`''`). A value too long for the message buffer still yields one line that names the option and marks the value as truncated. Zig tests; plant: the old `parseByteCount`/`parseUsize` accept `+5` and `1_000`.
3. **Help and bare invocation.** `searchd --help` and `searchd -h` print usage to **stdout** and exit 0. A bare `searchd` prints usage to **stderr** and exits 2. An unknown command is criterion 1's single line, pointing at `searchd --help`. The usage text states the exit statuses: 0 success, 1 the work failed, 2 usage error. Work failures keep exit 1 and their current text; a Zig or process test pins one of them at 1, so the two statuses cannot drift together.
4. **The freshness test's mutation.** `tests/test_native_freshness.py`'s `test_changing_contracts_version_changes_the_digest` appends a byte to the version file's current content instead of writing `9.9.9\n`, so it cannot pass by coincidence (S1-T7 finding 4).
5. **Libraries and stamp.** `tool/build_native.sh` is run **last**, after every Zig edit, with `SS_ANDROID_NDK` set to NDK 28.2.13676358; it re-stamps `native/SOURCE-SHA256`. Say whether the `.dylib` and `.so` changed byte for byte (expected: unchanged, since `src/abi.zig`'s import closure holds neither `cli.zig` nor `main.zig`; the stamp changes because the digest covers every `zig/src/*.zig`).
6. All five suites green after the Report, run with `SEARCH_SIMPLI_LIBRARY_PATH` unset; tails pasted with home paths redacted. No ABI, header, `CONTRACTS_VERSION` or Dart API change.
