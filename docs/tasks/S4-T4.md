# S4-T4 · One changed file with filename sections: the duplicated recovery state and the filename writer path

**State:** ready · **Date:** 2026-11-05 · **Depends on:** S4-T3 (merged at `596032c`; the consumer app pins it) · **Size:** M

**Owner:** the Xcode Mac orchestrator · **Orchestrator:** Claude Fable 5.1 · **Builder:** Claude Opus 5.5 (local) · **Verifier:** Claude Opus 5.5 (local, a different agent)

**Why.** The "Ready to build now" row *One changed file with filename sections: headroom and the duplicated state* in `docs/journey/03-next.md`. After S4-T2 one changed file in the 10k index costs p50 147.5 ms with the filename channel off and 172.5 ms with it on at low load, 181–185 ms (worst 189.8) at load 5–7, against NFR-12's 200 ms; f45c06d was 140.9 ms. Two known causes, neither profiled further (S4-T2 Report R7, Verdict note 1):

1. **The recovery state is written twice per generation.** `apply.zig` encodes the version 2 state JSON once for the bound section `state-N.hybstate` (`HYBSTA01`, 2,522,562 B at 10k) and once more for `INDEX-STATE.json` (the same bytes, a second atomic write and sync), 5 MB of state per generation for one changed line. The next writer parses the 2.5 MB JSON (`parseCommitted`, typed, `ignore_unknown_fields = false`) at every call. The open never reads either, and that must stay so.
2. **The filename writer path is a full rebuild plus a full validation.** `filename_field.build` re-tokenizes every basename and `filename_field.validate` decodes the two sections just written and re-tokenizes every name again (S4-T2 R4 moved that check from every reader's open to the writer). That is the +24 ms between off and on.

The consumer app's next task (its M16-T20) turns the filename channel on for every phone folder, so the "on" number is the one a phone will pay at every edit. The headroom today is 10–28 ms at load. This task makes it decidable and wider.

## Rulings

1. **Profile first, in the Report, before any change.** On S4-T1's 10k timing corpus (`scripts/gen_timing_corpus.py <dir> 10000`, `corpus_matches_recorded: true`), `ReleaseSmall`, filename off and on, one changed file (`group-00/doc-00000.md` + one line, fresh copy of the index per run, as `scripts/s4t2_budgets.py --mode apply` does): a stage table in milliseconds, five runs each, p50 and worst, for at least: open the previous generation (sections and the bound state read), `parseCommitted` of the previous state, `loadPrevious`, the documents/lexical/source build and encode, `filename_field.build`, `filename_field.validate`, `incremental_state.encode` + `state_section.encode`, the publish (every section write and sync, the manifest), `incremental_state.save`. Use a temporary instrumented build (a `std.time.Timer` per stage printed to stderr behind a build option or an environment variable that is off by default), or extend the driver; the instrumentation may stay only if it is off by default and costs nothing when off. The table decides how far rulings 2–4 go; a stage under 1 ms is not worth a change and the Report says so.

2. **`INDEX-STATE.json` becomes a pointer when the generation binds its state.** After a publication that wrote `state-N.hybstate`, `apply.zig` writes `INDEX-STATE.json` as version 3: `{"state_version":3,"generation":N,"analyzer_id":"…","state_file":"state-N.hybstate"}` and nothing else (no file table). `incremental_state.load` resolves a version 3 file by reading the named section from the same directory and checking it as the writer does (`manifest.validateState` against the current `MANIFEST`: size, header, checksum, generation and analyzer); when the `MANIFEST` is missing or does not bind that section, `load` returns `null` (as a missing state does today), never a partial state. Every reader keeps its behaviour: `generation_alloc.nextFreeGeneration` (the generation number is in the pointer), the folder indexer's `--update` (`indexer.zig`, which still writes and reads a full version 2 file and binds no section: a directory updated by the indexer after `apply` goes back to version 2, and the next `apply` reads it through the existing fallback), the `missing_manifest` detection in `apply.zig` (the file still exists), the lifecycle scanner (same name, never counted), `tests/test_cli_process.py` (the indexer's file stays version 2). Version 1 and 2 files still load. The format doc (`docs/folder-knowledge-implementation.md` §5, `docs/manifest-format-v2.md` v2.2 state section, `docs/publication-recovery.md`) says what the pointer is and when each form is written. A Zig test deletes the pointer and updates (the bound section carries the state), another corrupts the pointer (any byte) and updates (the bound section wins: the pointer is never trusted over the section), a third points it at a section the manifest does not bind (`load` returns `null`, the writer falls back to the reconstruction, the update still succeeds).

3. **The bound state shrinks, by measurement.** Say in the Report where the 2,522,562 B go at 10k (keys and punctuation, the hex hash, repeated `root_id`/`chunker`, `null`/empty fields), then choose one of:
   - **(a) compact version 2 JSON inside `HYBSTA01`**: omit `moved_from` when `null`, `required_labels` when empty, `sha256` when `null`; the typed parser gives those fields their defaults. Allowed only if the 0.3.0 library at `596032c` still **updates** a directory this tree wrote (prove it with that library through `ss_apply_changes` in the driver: the update succeeds and the next generation's state names every file); otherwise (a) is refused and (b) is the choice.
   - **(b) a binary state section `HYBSTA02`**: a string table for `root_id`, `chunker` and labels; the hash as 32 raw bytes; little-endian fixed-width integers; the XXH3-64 checksum and length in the header exactly as `HYBSTA01` carries them so `manifest.validateState` is unchanged; a format doc `docs/state-section-format-v2.md` with the byte layout. The writer reads `HYBSTA01` and `HYBSTA02`; it writes `HYBSTA02`. The 0.3.0 library then refuses to *update* such a directory with `InvalidStateSection` (`SS_ERR_CORRUPT_SNAPSHOT`) while it still opens and queries it; the CHANGELOG and the consumer row state that as the rollback rule (the rule since S4-T2 is already "keep the previous directory"). Round-trip, truncation, checksum-flip and stray-magic tests in Zig; a flipped byte in the section still refuses with the stated codes (S4-T2 R3's plant, repeated).
   Gate for either: the state bytes per generation at 10k at most half of today's (≤ 1,261,281 B), and `parseCommitted` of the 10k state at least as fast as today (stated in the ruling 1 table, before and after).

4. **The filename writer path, by the profile.** If `filename_field.validate` is ≥ 3 ms at 10k: make the writer's check cheap without weakening it — verify the decoded sections against the structures `buildDecoded` just produced (same tokens, same postings) instead of re-tokenizing from the catalog text, or verify by a structural pass (term order, posting ranges, anchors) plus a sampled re-tokenization whose sample the Report states, and keep the full re-tokenization under the Zig tests. If `filename_field.build` is ≥ 5 ms: state in the Report which part (tokenizing, sorting, encoding) and take the one cheap win if there is one; a redesign (an incremental filename build) is a NEXT row, not this task. Either way the filename sections' bytes and the query results are unchanged: the driver shows byte-identical `filenames-N.hybseg` and `filename-lexical-N.hyblex` for the same input before and after, and the filename gates of S4-T2 R7 (query p50, first-query load) hold.

5. **Budgets re-measured, before (`596032c`) and after.** Extend `scripts/s4t2_budgets.py` (or add `scripts/s4t4_budgets.py` reusing it) and run it with the `596032c` library and `searchd` as *before*, interleaved rounds, low load stated: `ss_open` p50 off and on, open + first filename query, one changed file off and on (five runs, p50 and worst), state bytes per generation, `MANIFEST` bytes and flags, and the 0.3.0 library's behaviour on a directory this tree wrote (ruling 3). **Gates:** one changed file at low load p50 **≤ 160 ms with the filename channel on** and **≤ 144 ms off**; `ss_open` within 0.3 ms of before, off and on (the open still touches no state); state bytes per generation ≤ half; the NFR-13 arena test (`zig/src/nfr13_arena_test.zig`) green with its numbers stated; the filename query gates of S4-T2 R7 held. If a gate is missed, the Report says by how much and which stage remains, and the task still merges if the number improved and nothing regressed; the orchestrator rules.

6. **Package, natives, docs.** No C ABI or contract change is expected (`contracts/` stays 2.2.0; say so, or say what changed). `bindings/dart/search_simpli` goes to **0.3.1** with a CHANGELOG entry (the pointer, the state section form, the rollback sentence, the numbers).
