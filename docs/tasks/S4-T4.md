# S4-T4 · One changed file with filename sections: the duplicated recovery state and the filename writer path

**State:** built · rulings on the Report written · awaiting verification · **Date:** 2026-11-05 · **Depends on:** S4-T3 (merged at `596032c`; the consumer app pins it) · **Size:** M

**Owner:** the Xcode Mac orchestrator · **Orchestrator:** Claude Fable 5.1 · **Builder:** Claude Opus 5.5 (local) · **Verifier:** Claude Opus 5.5 (local, a different agent)

**Why.** The "Ready to build now" row *One changed file with filename sections: headroom and the duplicated state* in `docs/journey/03-next.md`. After S4-T2 one changed file in the 10k index costs p50 147.5 ms with the filename channel off and 172.5 ms with it on at low load, 181–185 ms (worst 189.8) at load 5–7, against NFR-12's 200 ms; f45c06d was 140.9 ms. Two known causes, neither profiled further (S4-T2 Report R7, Verdict note 1):

1. **The recovery state is written twice per generation.** `apply.zig` encodes the version 2 state JSON once for the bound section `state-N.hybstate` (`HYBSTA01`, 2,522,562 B at 10k) and once more for `INDEX-STATE.json` (the same bytes, a second atomic write and sync), 5 MB of state per generation for one changed line. The next writer parses the 2.5 MB JSON (`parseCommitted`, typed, `ignore_unknown_fields = false`) at every call. The open never reads either, and that must stay so.
2. **The filename writer path is a full rebuild plus a full validation.** `filename_field.build` re-tokenizes every basename and `filename_field.validate` decodes the two sections just written and re-tokenizes every name again (S4-T2 R4 moved that check from every reader's open to the writer). That is the +24 ms between off and on.

The consumer app's next task (its M16-T20) turns the filename channel on for every phone folder, so the "on" number is the one a phone will pay at every edit. The headroom today is 10–28 ms at load. This task makes it decidable and wider.

2. **`INDEX-STATE.json` becomes a pointer when the generation binds its state.** After a publication that wrote `state-N.hybstate`, `apply.zig` writes `INDEX-STATE.json` as version 3: `{"state_version":3,"generation":N,"analyzer_id":"…","state_file":"state-N.hybstate"}` and nothing else (no file table). `incremental_state.load` resolves a version 3 file by reading the named section from the same directory and checking it as the writer does (`manifest.validateState` against the current `MANIFEST`: size, header, checksum, generation and analyzer); when the `MANIFEST` is missing or does not bind that section, `load` returns `null` (as a missing state does today), never a partial state. Every reader keeps its behaviour: `generation_alloc.nextFreeGeneration` (the generation number is in the pointer), the folder indexer's `--update` (`indexer.zig`, which still writes and reads a full version 2 file and binds no section: a directory updated by the indexer after `apply` goes back to version 2, and the next `apply` reads it through the existing fallback), the `missing_manifest` detection in `apply.zig` (the file still exists), the lifecycle scanner (same name, never counted), `tests/test_cli_process.py` (the indexer's file stays version 2). Version 1 and 2 files still load. The format doc (`docs/folder-knowledge-implementation.md` §5, `docs/manifest-format-v2.md` v2.2 state section, `docs/publication-recovery.md`) says what the pointer is and when each form is written. A Zig test deletes the pointer and updates (the bound section carries the state), another corrupts the pointer (any byte) and updates (the bound section wins: the pointer is never trusted over the section), a third points it at a section the manifest does not bind (`load` returns `null`, the writer falls back to the reconstruction, the update still succeeds).

### Ruling 2: `INDEX-STATE.json` as a version 3 pointer (`b4b1c5b`)

- `apply.zig` writes, after each publication, `{"state_version":3,"generation":N,
  "analyzer_id":"analyzer-v2","state_file":"state-N.hybstate"}` (94 B at 10k) with
  `incremental_state.savePointer`; nothing else.
- `incremental_state.load` resolves a version 3 file (`parsePointer`, exactly four
  fields) through `resolvePointer`: the current `MANIFEST` must bind that file for that
  generation and analyzer, else `null` (also without a `MANIFEST`, or when the section file
  is gone); the section must pass `manifest.validateState` and decode to the manifest's
  generation and analyzer, else `InvalidState`. Version 1 and 2 files load as before.
- `generation_alloc.highestGenerationOnDisk` calls `incremental_state.recordedGeneration`:
  the pointer's generation, or a version 1/2 file parsed as before. The writer's precedence
  in `apply.zig` is unchanged (bound section, then a matching state file, then the
  reconstruction); `missing_manifest` still checks that the file exists.
- Zig tests (`apply_test.zig`, "S4-T4 R2: …"): the pointer's exact bytes and a load through
  it; the pointer deleted, then an update (the bound section carries the hash and own label

### Ruling 3: the bound state shrinks (`ad3a9d7`)

**Where the 2,522,562 B go** (the `state-2.hybstate` the 596032c library wrote after one
changed file on the 10k corpus; its 2,522,530 B payload equals that `INDEX-STATE.json` byte
for byte; one root, 10,000 indexed files, every `mtime_ms` and `moved_from` null, every

| Part of the payload | Bytes | Share |
|---|---:|---:|
| keys, quotes, colons, commas | 1,120,000 | 44.4 % |
| `sha256`, 64 hex digits in quotes | 660,000 | 26.2 % |
| paths (in quotes) | 230,000 | 9.1 % |
| `chunker` repeated per file | 150,000 | 5.9 % |
| `root_id` repeated per file | 100,000 | 4.0 % |
| `null` and empty fields (`mtime_ms`, `moved_from`, `required_labels`) | 100,000 | 4.0 % |
| `status` | 90,000 | 3.6 % |
| numbers (`size`, `chunks`) | 42,333 | 1.7 % |
| entry punctuation, header, roots | 30,197 | 1.2 % |

compatibility proof was not needed and not run; (b) is the choice by the size gate, not by

### Deviations and notes

1. **Ruling 2's premise about the indexer does not hold.** The ruling says the folder
   indexer (`indexer.zig`, `searchd index --update`) "still writes and reads a full
   version 2 file and binds no section". Since S4-T2 the indexer builds an `apply_changes`
   batch and publishes through `apply.applyBatch` (`indexer.zig` line 196), so every
   generation it writes binds `state-N.hybstate` and, after this task, writes the version 3
   pointer, like `apply`. A directory updated by the indexer therefore does not go back to
   version 2. The indexer's own `incremental_state.load` calls resolve the pointer.
   `tests/test_cli_process.py` still passes unchanged: it rewrites the `generation` field
   of `INDEX-STATE.json` with `json.loads`/`json.dumps`, which works on the pointer, and
   `generation_alloc` reads that field (deviation 2).
2. **`generation_alloc.zig` changed** (outside ruling 8's list). Its
   `highestGenerationOnDisk` called `incremental_state.load`, which for a pointer must
   check the section against the `MANIFEST`; a pointer whose section the `MANIFEST` does not
   bind (the crash window, or the test above that rewrites the generation) would then lose
   its generation number, and the allocator must count it. It now calls
   `incremental_state.recordedGeneration`, which reads only the `generation` field of a
   version 3 file (a version 1 or 2 file is parsed as before). Side effect found by the
   profile: the old call parsed the whole 2.5 MB file on every write (8.5 ms at 10k);
   it is now 0.14 ms.
3. **A test assertion changed:** the S3-T3 crash test (`apply_test.zig`) now expects
   `load` to return `null` after the crash, and `recordedGeneration` to return 1 (ruling 2
   above).
4. **A test renamed:** in `lazy_open_test.zig`, the test that said writers run the full
   filename check now says who does (the tests and `import-json`); its body is unchanged.
5. **`import-json` keeps the full check:** `importer.zig` still calls
   `filename_field.validate` (it is outside ruling 8's list, and its sections are not
   built from a writer's document list). Only `apply.zig`'s writer uses `validateBuilt`.
6. **The libraries grew:** macOS dylib +17,328 B (808,408 → 825,736), Android `.so` +9,544 B
   (777,672 → 787,216); the iOS binary is 64 B smaller. The JSON reader and writer for the
   old state forms stay, for directories written by 0.2.x and 0.3.0.
7. **Instrumentation:** ruling 1's stage timers stay in `apply.zig`, off by default
   (`SEARCH_SIMPLI_APPLY_STAGES=1` turns them on; off, one `getenv` per call and no clock
   read). The finer split of `filename_field.build` and `validate` in ruling 1's table came
   from a temporary timer patch in `filename_field.zig`, measured once and reverted (never
   committed).
8. **Hash normalization in `HYBSTA02`:** a file's SHA-256 is stored as 32 raw bytes. A
