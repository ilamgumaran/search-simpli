# S6-T20: a full rebuild chooses its generation number under the writer lock

**State:** filed by the orchestrator, 21 Nov 2026, from `main` after the S6-T17 merge · **Depends on:** [S6-T17](S6-T17.md) (its Verdict showed the gap), [S6-T13](S6-T13.md), [S6-T16](S6-T16.md) (the public core API) · **Plan:** [objective plan](../plans/2026-11-16-objective-plan.md), section B follow-ups ("generation numbering in interfaces") and the lifecycle

## Why

[S6-T17](S6-T17.md)'s ruling 2 was "never a number already used". Its verifier
showed, on `main` and on the task's head alike, that two writers can still
republish a used number: a full rebuild chooses its number with
`generation_alloc.nextFreeGeneration` **before** it holds `WRITER.LOCK`
(`interfaces/abi.zig` and `interfaces/cli.zig` call it, then
`indexer.indexFolder` builds, then the publish takes the lock). A second writer
that publishes in between leaves the first with a number that is no longer
free. The verifier's probes saw `MANIFEST` go from 11 back to 10 with
`keep_generations = 1`, and `PathAlreadyExists` in other orders.

An update (`apply.zig`) does not have the gap: it takes the lease first and
reads, numbers, builds and publishes inside it.

The maintainer was asked on 21 Nov 2026 how to close the gap and chose:
**choose the number under the writer lock**, with a design note first. Refusing
a stale number at publish time was the alternative and was not chosen.

The same change answers a follow-up in [core-api](../core-api.md): the
interfaces should not be numbering generations at all.

## What

### Part 1: the design note (commit it first, before any code)

`docs/decisions/s6-t20-generation-under-lock.md` (or the name that folder's files use), short, from reading the code,
answering with file and line:

1. Every path that publishes a generation (full rebuild from the C API, from
   `searchd index`, the incremental path, `apply`, the importer, `init-demo`,
   any other), and for each: where the number is chosen, where the lease is
   taken, and whether the number can go stale in between.
2. The proposed shape. The orchestrator's reading, to confirm or correct: the
   full rebuild takes the lease before it chooses a number and holds it through
   the build and the publish, as `apply` does; the interfaces stop calling
   `nextFreeGeneration` and pass "no number" to the core.
3. What changes for a caller. In particular: a second writer that starts while
   a full rebuild is building now gets `WriterBusy` at once instead of building
   and then failing or overwriting. Say whether that is already a documented
   refusal on every interface (it should be: `WriterBusy` exists on all of
   them), and what the lifecycle document must now say.
4. A caller-supplied number (`searchd index --generation N`, and any other
   such input): what happens to it. It must be checked under the lease; say
   what the refusal is when the number is not free, using an error that
   already exists if one fits.
5. Readers: confirm that holding the lease for the length of a build blocks no
   reader (readers do not take `WRITER.LOCK`); show the code.
6. Anything this cannot close (for example a writer that does not honour the
   lock, or a file system without working locks), stated as a known limit.

If the note finds the proposed shape wrong or finds a contract change is
needed, **stop after the note** and report; do not build.

### Part 2: the change

1. The full rebuild chooses its number inside the lease it publishes under.
   One lease, taken once: no release and retake between choosing and
   publishing.
2. `interfaces/abi.zig` and `interfaces/cli.zig` no longer call
   `generation_alloc.nextFreeGeneration`. If nothing in `ops/` or
   `interfaces/` uses it afterwards, it leaves `core.api`, and
   `docs/core-api.md` is updated from the checker's output.
3. Tests, in `zig/src/core/` or `zig/src/tests/` as fits, using the seam
   S6-T17's tests use where it helps:
   - the verifier's two probes from S6-T17 as tests: with a second writer
     publishing while a full rebuild is between choosing and publishing, the
     second writer is refused with `WriterBusy`, no number is published twice,
     and `MANIFEST` never goes backwards;
   - a caller-supplied number that is not free is refused under the lease,
     and nothing on disk changes;
   - each test fails on `main` (show it: the test run against the code before
     the change, in the evidence) and passes on the head.
4. Documents: `docs/generation-lifecycle.md` (the two-writer section now says
   what is true; remove "known gap" wording only where the gap is closed),
   `PROJECT-STATE.md`, `docs/journey/03-next.md`, the Dart CHANGELOG and
   version if the libraries change (they will).

## Rulings

1. **No number is published twice, and `MANIFEST` never goes backwards,** for
   any interleaving of two writers that both honour `WRITER.LOCK`. This time
   the claim must be shown, not stated: the tests in What 3, and the Report
   says which interleavings are covered and which are argued from the code.
2. **No contract, header or format change.** No new error code, no new field.
   `WriterBusy` is already a documented refusal. If the design needs a new
   refusal, stop and report.
3. **Answers and the read path do not change.** Only writer code changes.
4. **Natives are rebuilt and restamped** (`tool/build_native.sh`,
   `SOURCE-SHA256` in the same commit as any change to its inputs), sizes in
   bytes against `main`'s. The timing rule of 2026-11-17
   (`docs/process/ROLES.md`) applies as written: say what it requires for a
   writer-only change, and do that.
5. **The same tests run,** plus the new ones: both S6-T15 guards pass, and the
   Report gives the count before and after.
6. **Stop before:** changing what `apply` does; changing the lock file or how
   it is taken; any change to pruning; anything in `contracts/` or
   `zig/include/`.
