**Ruling 2, the change** (`src/search_platform/folders.py`, `FolderIndex.search`). The helper builds its authorized
snapshot, `{"chunks": self.visible_chunks(roots, principal_labels), "roots": sorted(self._allowed(roots, labels))}`,
and calls `core.search(snapshot, query, top_k=k, candidate_k=k, retrieval_mode="lexical",
principal_labels=sorted(labels))`, with `fuzzy` and `fold` at their defaults (the engine's rule). The snapshot is the
statistics (roots and labels), so the title field, fuzzy-v1 and fold-groups-v2 run over exactly what the caller may
see, as in the engine. Its own BM25 and the `_bm25_scores` import are gone. Kept: `roots`, `principal_labels`,
`top_k`, `conjunctive`, the root and file metadata, and the result fields (`chunk_id`, `root_id`, `path`,
`start_line`, `end_line`, `section_path`, `score`, `content`); `score` is the chunk's `ranking.lexical.score` (BM25 plus
the title part it received), not `core.search`'s fused `score`. `conjunctive` ranks every visible chunk
(`k = len(chunks)`), keeps the chunks holding every query word as typed (the test it had, and `find`'s `words`), in
rank order, and cuts at `top_k`. No path-prefix parameter.

*The seam, for S5-T8:* **none in `core.py`.** The helper uses `core.search`'s existing signature and reads, from the
index dict it passes, only `index["chunks"]` (each chunk's `id`, `path`, `start_line`, `end_line`, `text`, `terms`,
`length`, `required_labels`, which `FolderIndex._chunk` already writes) and `index["roots"]` (a list of root ids, read
by `_title_root_ids`); from each hit it reads `chunk_id` and `ranking.lexical.score`. A `core.py` ranking rule that
S5-T8 adds reaches the helper with no edit here; a rule that needs a new index key, or a rename of
`ranking.lexical.score`, would need the snapshot or the read above to follow, and `tests/test_folder_ranking.py`
fails if the helper and `core.search` part.
