**What changes.** One key function **K** maps an analyzer-v2 token to its v3 term(s). It has four steps, in this order:
1. **F, fold.** NFKC and full case folding, applied to a fixpoint. A token that folding turns into more than one token is split again (`½` becomes `1`, `2`).
2. **A, Latin marks.** Combining marks after a Latin base letter are dropped, and an eight-letter table is applied.
3. **S, English plural.** ASCII `a–z` words of 3 to 49 letters, with a keep list.
4. **T, Tamil.** A bounded list of seven suffix rules, with a keep list.

K applies to every surface: body, title, file name, `find` and the query. It can be placed two ways:
- **Index side (`analyzer-v3`).** Rulings 7–9. The dictionary holds K's terms, and every index is rebuilt once.
- **Query side (`fold-groups-v1`).** Ruling 10. The v2 index is kept. Each query term is searched as every dictionary or visible-title term with the same K, and scored as one word through S5-T3's group machinery. No index is rebuilt.

2. **F, the fold (exact).**
   - **The input** is one analyzer-v2 token: the v2 split on NFC text, variation selectors dropped, letter/digit runs plus marks plus ZWJ/ZWNJ.
   - **The fold** is applied per code point from one generated table. For each code point *c*, the table holds `NFKC(casefold(NFKC(c)))` iterated to a fixpoint, with Python 3.9.6's `unicodedata`. The token is then normalised to NFC with the existing composition tables. This is Unicode's own construction of `toNFKC_Casefold` (map each code point of the NFD form, then NFC), except that **default-ignorable code points are not removed**: the v2 split already drops variation selectors and keeps ZWJ/ZWNJ inside tokens, and v3 keeps that.
   - **The re-split.** If the folded token holds a code point outside the v2 token classes (letter/digit/mark/ZWJ/ZWNJ), it is split again by the v2 rule. For example, `½` becomes `1⁄2`, then `1`, `2`.
   - **Positions.** Each piece takes its own token ordinal, in order. Every piece's source offsets are the whole original token's range.
   - **Pinned to Unicode 13.0.0**, the version of `zig/src/unicode_tables.zig`. A different Unicode version is a new analyzer id, not a table refresh.
   - **The table**, generated by extending `scripts/gen_unicode_tables.py` (counts, not sizes; ruling 13 profiles the size):
     - 6,158 code points change under the fold;
     - 3,852 of them are not already handled by today's NFC and simple fold;
     - those 3,852 hold 10,529 bytes of UTF-8 output; 1,303 code points map to more than one code point, and the longest maps to 18.
     - By block: mathematical alphanumerics 996, Arabic presentation forms 797, enclosed and squared forms 777, fullwidth 173, Hangul compatibility jamo 146, other 963.
     - A naive layout (4-byte key, 2-byte offset, 1-byte length, UTF-8 pool) is about **37.5 KB**.
   - **Measured on the traps:** `ｇｏｇｇｌｅｓ`→`goggles`, `ﬂute`→`flute`, `１２`→`12`, `straße`→`strasse`, `Ⅻ`→`xii`, `x²`→`x2`, `½`→`1`, `2`.

3. **A, Latin marks (exact).**
   - **The marks.** After F: NFD, then drop every code point U+0300–U+036F whose nearest preceding non-mark code point is `a`–`z` (after the table below). Marks after any other base are kept: Greek tonos stays, and Tamil vowel signs are not in U+0300–U+036F anyway. Vietnamese tone marks sit on Latin letters, so they are dropped (recorded). Then NFC.
   - **The table:** `ø`→`o`, `đ`→`d`, `ł`→`l`, `ħ`→`h`, `ŧ`→`t`, `ı`→`i`, `æ`→`ae`, `œ`→`oe`. These are lowercase only, since F has already folded case.
   - **An ASCII token is untouched.**
   - **Measured:** `résumé`→`resume`, `crêpe`→`crepe`, `øre`→`ore`, `łódź`→`lodz`, `æsop`→`aesop`, `frühling`→`fruhling`, `noël`→`noel`.
   - **Why it ships with no J2 gain.** It costs nothing measured: FST equals FAST on every J2 row, every negative and every pack. It reaches what fuzzy-v1 cannot:
     - words under 5 code points (`cafe`/`café`, `noel`/`noël`);
     - `find`, which fuzzy-v1 never touches.

     A later addition would cost a second rebuild. The accent-heldout slice (ruling 11) must show it: if FA does not beat F there, A is dropped before Phase 2.
   - **The trade, recorded:** `résumé` and `resume`, `naïve` and `naive`, `pâte` and `pate` become one word.

4. **S, English plural (exact).** It applies only to a token matching `[a-z]{3,49}` after F and A, and not in the keep list. The first rule that applies wins:
   1. ends in `ss`, `us` or `is`, or does not end in `s`: unchanged;
   2. ends in `ies`: length ≥ 5 → drop `ies`, add `y` (`ponies`→`pony`); else drop `s` (`ties`→`tie`);
   3. ends in `sses`, `xes`, `ches`, `shes` or `zzes`: drop `es` (`boxes`→`box`, `classes`→`class`, `lunches`→`lunch`);
   4. ends in `oes` and length ≥ 6: drop `es` (`potatoes`→`potato`; `shoes` and `toes` fall to rule 5);
   5. length ≥ 4: drop `s` (`tests`→`test`, `rides`→`ride`, `shoes`→`shoe`);
   6. otherwise unchanged.

   **The keep list** (exact): news, species, series, always, perhaps, christmas, lens, atlas, canvas, bias, alias, chaos, cosmos, pants, trousers, scissors, glasses, maths, physics, athletics, gymnastics, politics, measles, mumps, means, lots, thanks, towards, afterwards, upstairs, downstairs, indoors, outdoors, headquarters, whereas, yes, does, goes, was, has, his, its, this, thus, plus, bus, gas, us, is, as.

   **The known misses** (two forms that stay apart; no wrong merge): `buses`→`buse`, `caches`→`cach`, `headaches`→`headach`, `movies`→`movy`, `cookies`→`cooky`.

   **The known merge, recorded:** `leaves`→`leave` (the noun and the verb).

   **`-ing` and `-ed` are not in v3** (ruling 1; open question 2).

5. **T, Tamil (exact).** It applies only to a token whose code points are all in U+0B80–U+0BFF, and that is not in the keep list `நாங்கள், நீங்கள், உங்கள், எங்கள், தங்கள், அவர்கள், இவர்கள், மக்கள்`.

   The first rule whose suffix matches and whose condition holds wins, provided the result keeps **at least two Tamil letters** (U+0B85–U+0BB9):

   | Suffix | Replace with | Condition on the stem | Example |
   |---|---|---|---|
   | `ங்கள்` | `ம்` | none | `மரங்கள்`→`மரம்`, `பழங்கள்`→`பழம்`, `புத்தகங்கள்`→`புத்தகம்` |
   | `கள்` | (nothing) | none | `யானைகள்`→`யானை`, `பாடல்கள்`→`பாடல்` |
   | `த்தில்` | `ம்` | none | `மரத்தில்`→`மரம்`, `நூலகத்தில்`→`நூலகம்` |
   | `த்தின்` | `ம்` | none | `மரத்தின்`→`மரம்` |
   | `க்கு` | (nothing) | ends in a vowel sign (ா ி ீ ு ூ ெ ே ை ொ ோ ௌ) | `கடைக்கு`→`கடை`, `பள்ளிக்கு`→`பள்ளி`, `தேர்வுக்கு`→`தேர்வு` |
   | `யில்` | (nothing) | ends in ி, ீ or ை | `பள்ளியில்`→`பள்ளி` |
   | `யின்` | (nothing) | ends in ி, ீ or ை | `பாட்டியின்`→`பாட்டி` |

   - **Never stripped:** the accusative `ஐ` (J2 guards `g1` `காலை` and `g2` `நாளை`) and the nominal `-வு` (guard `g3` `தேர்வு`).
   - **Measured:** Tamil 0.231 → 1.000 in both variants and both placements. Guards `g1`–`g3` stay at rank 1, and the Tamil pack is identical.
   - **The known misses** (no wrong merge): `நாட்கள்`→`நாட்` (should be `நாள்`), `சொற்கள்`→`சொற்`, `கடலுக்கு`→`கடலு`, `வீட்டுக்கு`→`வீட்டு`.
   - **Written from J2's rows.** The suffix list was written from J2's own Tamil rows, so its J2 number is an upper estimate. The tamil-heldout slice (ruling 11) is the real test, and **T ships only if it passes there**.

7. **Index side: `analyzer-v3`, the manifest and compatibility.** This applies if the owner takes the rebuild.
   1. **The id.** `analyzer-v3` = analyzer-v2's split + K. `indexer.AnalyzerId` gains `.v3`; `label`/`parse` accept `analyzer-v3` and `v3`.
   2. **The flag.** Manifest flag bit 5, `analyzer_v3` (`0x0020`), is set on every generation whose `analyzer_id` is `analyzer-v3` and on no other. `known_flags` gains bit 5.
      - A reader before S5-T4 refuses a v3 generation with `UnsupportedFlags` before reading any section. This is the S4-T2 bit-3 precedent.
      - It is needed because today's `Engine.queryTraced`, `find.tokenizeQuery` and `filename_field.tokenize` fall through to the **ASCII** tokenizer for any id that is not `analyzer-v2`, and `Engine.open` does not check the id. Without the bit, an older library would open a v3 index and silently mis-analyse every query.
      - A manifest whose bit 5 disagrees with its `analyzer_id` is `InvalidManifest`.
   3. **Fail closed on an unknown id.** `Engine.open` / `snapshot_open` check `analyzer_id` against {`ascii-alnum-v1`, `analyzer-v2`, `analyzer-v3`}; any other id is `UnsupportedAnalyzer`. Every analyzer dispatch becomes an exhaustive `switch` on the enum, with no `else` that falls through to ASCII: the query path, `find` (`tokenizeQuery`, positioned tokens), `filename_field.tokenize`, `fuzzyApplies` and `bothGroups`.
   4. **Old snapshots.** A v3 library reads a v2 generation with v2 analysis, by its stored id, and its results are byte-identical to `main`'s. J2 run on a v2 index through the new library equals `e0d258b`'s baseline cells exactly. `compat_292cb568_test.zig` passes unchanged.
   5. **Updates.** `apply_changes` and `ss_index_folder --update` with **no** `analyzer` option keep the previous generation's analyzer, the way `filename_index` already does. Today the option defaults to `analyzer-v2`, which would refuse every update to a v3 index. An explicit, different analyzer without `reanalyze` is `AnalyzerMismatch`, as today; postings are never reused across analyzers.
   6. **Reanalyze (the rebuild).** `apply_changes` takes a new option `reanalyze: true` together with `analyzer: "v3"`.
      - Every retained file is re-chunked and re-analysed from the previous generation's **source section** (no file is read), any changes in the call are applied on top, and the result is published as a new generation by the ordinary full-build path.
      - If any document has no source bytes, it fails closed with `CAPACITY` "re-index required: source absent"; the caller then re-sends the files.
      - The previous generation stays on disk under `keep_generations`. A handle opened on it keeps answering from it, so **the app reads the old index while it rebuilds** and switches by reopening.
   7. **Import.** `contracts/snapshot-interchange.schema.json` accepts `analyzer-v3`. The importer and its Python twin validate it; any other id is still `UnsupportedAnalyzer`.
   8. **The default.** A fresh directory still defaults to `analyzer-v2` in this task (`searchd index`, `ss_index_folder`, `apply_changes`). v3 is opt-in by option, and the app opts in when the owner says so. The flip is a one-line later task (open question 4).
   9. **Rollback.** Once a phone's index is v3, no earlier library opens it. The app must never roll its pin back past this task, as with S4-T2's Dart 0.3.0. The CHANGELOG says so.
   10. **The contract.** Contracts 2.5.0 (additive: the interchange enum value and the `reanalyze` option), Dart 0.6.0 (the enum value, the option, the CHANGELOG, natives rebuilt on this Mac, `native/SOURCE-SHA256`). `ss_status` already reports `analyzer_id`, which is how the app sees that an index is stale.

10. **Query side: `fold-groups-v1`.** This applies if the owner declines the rebuild. The index stays analyzer-v2, with no format change and no phone rebuild. The rule is exactly the prototype's `install_groups`:
    - **The key map.** For a v2 snapshot, the key map is derived at the first query, like S5-T2's title table. It maps each dictionary term and each title term *d* with K(*d*) ≠ *d* to K(*d*). Only the terms whose key differs are kept: 7 of 34,058 at 10k, and 15–17 % on J2's three roots.
    - **The group.** For each distinct analysed query term *t*, the group is every in-scope dictionary term and visible-title term *d* with K(*d*) = K(*t*). *t* itself is in the group when it is present. Order: *t* first, then df descending, then bytes. All members have weight 1.0.
    - **The trigger.** A group is used when it is non-empty and not just {*t*}.
    - **The scoring** is S5-T3's: one word, max-df blend, best member per chunk, in the body part and the title part.
    - **fuzzy-v1 runs as today for every term without a group.**
    - **Privacy.** A member held only by a label-hidden chunk is neither used nor reported, as in fuzzy-v1.
    - **A key of more than one piece** (re-split) groups by the joined key.
    - **What stays untouched:** `find`, the `filename` channel, and every writer.
    - **The warning.** A `query_term_grouped` warning carries the members, in the pattern of `query_term_expanded`. Contracts 2.5.0.
    - **The `ß` row.** On a v2 index, the Python reference's body fold is made the engine's simple fold (the mirror follows the engine). Python's v2 accent cells then equal `searchd`'s (0.556 → 0.444 `content`), re-recorded with `--why`.
