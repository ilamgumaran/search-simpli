# S6-T18: the command line's one-shot query no longer derives the title field itself

**State:** filed by the orchestrator, 21 Nov 2026, from `main` at `12b839b` · **Depends on:** [S6-T16](S6-T16.md) (it listed this as a follow-up) · **Plan:** [objective plan](../plans/2026-11-16-objective-plan.md), section B (follow-ups to B3)

## Why

[core-api](../core-api.md), "Names that look like internals", lists
`title_field.derive`: `interfaces/cli.zig` (`runSearch`) builds a ranking input,
the title field, in an interface and hands it to the core's query. A new
interface that wants the same answers would have to know to do that. The core
already derives the field for a scoped open (`scope.zig`). The derivation
belongs behind a core call, and the name should leave `core.api`.

[S6-T17](S6-T17.md) is verified and awaits the maintainer; it touches other
files (`generation_alloc.zig`, its test). Keep clear of them; only the status
documents will overlap at merge.

## What

1. **A core call** for what `runSearch` does: a lexical one-shot query over an
   opened generation that derives the title field it ranks with. Its place and
   name are the builder's proposal, stated in the Report before the change is
   described (on the engine type, or a function beside the existing derive in
   the core). Doc comment: what it does, who owns the returned memory, errors.
2. **`cli.zig`** calls it and no longer imports `title_field` for `derive`.
3. **`core.api`** loses `title_field.derive`; the new call is published in its
   place with a doc comment. `title_field.policy_id` stays (two operations
   print it). `docs/core-api.md` is updated: the follow-up is struck from the
   list with the task's number, and the name counts are restated from the
   checker's output.
4. **The guard** (`scripts/check_layers.py`) and its tests follow the changed
   list; a planted `title_field.derive` in `interfaces/` fails it.

## Rulings

1. **Answers byte-identical.** `searchd query` and `searchd search` output is
   byte-identical to `main`'s for every query in the Python suite and the J2
   gate's queries (run the gate, or state why it could not be run). No
   contract, C header, format or error-name change.
2. **Same work, same allocator.** The new call allocates what `runSearch`
   allocates today, from the allocator it is given; it does not cache, and it
   does not derive when the caller already has a title field. Peak memory for
   `searchd query` on the 10k timing corpus is reported against `main`'s.
3. **Natives.** Rebuilt and restamped in the same commit as any change to the
   digest's inputs; sizes against `main`'s (macOS 1,006,456 B, Android
   966,800 B, iOS 971,424 B, `searchd` ReleaseSmall 1,151,208 B). If the three
   libraries are byte-identical, say so. `searchd` is expected to differ.
4. **Timing.** A query path's code moves in `searchd`, so timing by the rule of
   2026-11-17 (`docs/process/ROLES.md`) is owed for `searchd query` before a
   Verdict, on the corpora that rule names. If the libraries are byte-identical,
   no library timing is owed.
5. **Tests.** The same tests pass by name as on `main`; new tests for the core
   call live where the layer rules put them; both S6-T15 guards pass and the
   Report gives the new totals.
6. **Stop before:** any answer difference; a contract, header or format
   change; changing how a scoped open derives or holds its title field.
