# S6-T24: pattern search, `scan` (plan step H3)

**State:** filed by the orchestrator, 23 Nov 2026 · **Depends on:** [S6-T23](S6-T23.md) (the text rule; branch from `main` after it merges), [S6-T22](S6-T22.md) (the judged set) · **Plan:** [objective plan](../plans/2026-11-16-objective-plan.md) step H3; **specification:** [H3 in the implementation specification](../plans/2026-11-22-text-search-implementation-spec.md#h3-pattern-search-scan)

## Why

The maintainer's direction of 22 Nov 2026 makes simple token and pattern
matching ("like `sed`, `awk`") the base of text search. Today an exact string
cannot be searched: `142.50` becomes the tokens `142` and `50`, quotes are
ignored outside `find`, and there is no pattern code in `zig/src/`. On 23 Nov
the maintainer said to build this step, then pause.

## What

The specification's H3 section is the requirement: request and response fields,
order (path, then line), the pattern subset matched in linear time, the two
sources (an index's source section; a folder with nothing prepared), the code
table, the tests and acceptance. Read it whole. Where this file and the
specification differ, this file rules.

### Rulings (orchestrator, 23 Nov 2026; the specification's open questions, decided so the build can start, each reversible by the maintainer or a reviewer)

1. **H3-Q1:** the engine has its own small matcher in `core/` for the subset in
   the specification. No dependency. `literal` is the default mode.
2. **H3-Q2:** a separate operation `scan`; `find`'s contract does not change.
3. **H3-Q3:** `scan` is byte-honest: case options only, no mark or accent
   folding in this version. It must be usable as an oracle.
4. **H3-Q4:** the version step is whatever the repository's written rule gives
   for a new read-only operation that changes no existing response; the note
   quotes the rule with file and line and applies it. Capability document
   first (next free CAP number), status "Accepted under the maintainer's
   direction of 22 and 23 Nov 2026; recorded for his review".
5. **H3-Q5:** a default time budget of 2 s, a request field up to 30 s,
   `stopped: time` when exceeded; never a partial page presented as complete.
6. No postings-based prefilter in this task. The plain scan is measured first.
7. Every existing answer is unchanged: ranked search, `find`, evidence
   byte-identical on the three 10k corpora; the 181 judged questions and their
   digests untouched. The exact-string questions are a second, separately
   frozen set with its own digest file.
8. Extracting the read-and-caps logic from `apply.applyParsed` into one shared
   function is a refactor with no behaviour change, shown by the existing tests
   and the 10k byte-identity; it is its own commit.
9. All interfaces in this task: `searchd scan` (over an index and over a
   folder), `ss_scan`, the MCP and RPC tool `scan` (read-only), Dart `scan`,
   the Python reference. Schemas under `contracts/tools/`.
10. Natives rebuilt and restamped in the same commit as any digest-input
    change; sizes in bytes against `main`. Timing: prepare and push the orders
    with controls matched to the code delta; STOP before taking timing.

## Rulings after Part 1 (orchestrator, 23 Nov 2026)

ADR 0006 at `91b9764` is accepted and Part 2 goes ahead. Each ruling below is the orchestrator's decision,
reversible by the maintainer or a reviewer.

1. **Section 13, items 2–13: accepted as the note states them.**
   - There is no `cancelled`.
   - `truncated` keeps `find`'s meaning, and paging is `next_cursor` alone.
   - Order is `root_id` byte order.
   - Lines are numbered by `lineStarts`.
   - `smart` is decided by the fold table.
   - The grep agreement test records its exclusions.
   - Only the pure part of read-and-caps is shared.
2. **O-1:** `\w` and `\b` use the analyser's word code points, so `_` is not a word character. The user-facing
   document says so with one example, because it differs from grep.
3. **O-2:** `\d` is Unicode Nd.
4. **O-3:** contracts 2.10.0, Dart 0.12.0, CAP-25 first. CAP-25 and the Report state that no written rule fixes
   the size of the step, and that minor follows the practice since 2.0.0. This is a question for the maintainer,
   listed as such.
5. **O-4:** no. A folder cursor sees adds and removes only. The document says that an edit between pages can be
   missed.
6. **O-5:** the folder scan is on the command line and in the Python reference only. There is no `ss_scan_folder`
   in this task; it is recorded as a 03-next row.
7. **O-6:** `searchd scan <dir> "<pattern>"` runs over an index, and `searchd scan --folder <folder> "<pattern>"`
   over a folder.
8. **O-7:** a line that alone outlasts the budget is not skipped silently. The caller must never be able to loop
   forever on the same cursor: what is returned must be distinguishable from ordinary `stopped: "time"` progress.
   - Use an existing error or field if one fits.
   - If it needs a new error code, the Report says so as a contract addition under CAP-25.
   - Add a test for it.
9. **O-8:** `\t` is accepted; `\n` and `\xHH` stay refused.
10. **O-9:** cancel is a later capability, recorded as a 03-next row.
