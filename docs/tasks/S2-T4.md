# S2-T4 · Warnings, opt-in profile, and the effective request in the query report

**State:** ready (start after S2-T3 merges; same files) · **Series:** S2 (research doc, learnings 6 and 13) · **Depends on:** S2-T3 · **Size:** S · **Builder:** Sonnet 5 · **Tester:** Opus

`ss_query` cannot say why a list is empty or poor: a query word that matches
nothing is dropped silently (`zig/src/lexical_build.zig:139`), a query that is
only punctuation, a `candidate_k` that cut ranks, a vector ignored in lexical
mode (`zig/src/abi.zig:287-293`). The app wants to tell a child "I couldn't
find *dinosaurus*"; a tester wants per-phase timings without a profiler.

## Acceptance criteria
1. The report gains `warnings`: an array of `{code, message, term?}` with
   codes `query_term_unmatched`, `query_empty_after_analysis`,
   `vector_ignored`, `candidate_depth_cut`; and, when `"profile": true` is in
   `options_json`, `profile{tokenize_us, score_us, rank_us, serialize_us,
   matched_chunks}`; and `request{analyzer_id, retrieval_mode, top_k,
   candidate_k, path_prefix}` echoing what was actually used. All additive
   JSON: `contracts/search-tool.schema.json` and `CONTRACTS_VERSION` minor
   bump; Dart types mirrored; header documented.
2. **Bar (a):** with `warnings`, `profile` and `request` stripped, the output
   is byte-identical to the previous library on every golden.
3. **Bar (b):** every query word that matches no chunk appears in `warnings`
   (checked over the 200 random queries of S2-T3 plus 50 with planted unknown
   words).
4. **Bar (c):** with profile off, p50 changes by ≤ 2 %; with it on, by ≤ 10 %
   (same harness as S2-T3).
5. **Plants:** each code has a test that fails when its emission is removed.
6. All five suites green after the Report; libraries rebuilt last.
