### Deviations

1. **PR #21's six later commits merged as well** (`83452bc`, before R1): the author's own
   merge of f45c06d and five follow-ups (contracts 2.2.0, the section slab, a typed state
   parse, the filename-enabled NFR-13 variant, `filename_bench.zig`). The Notes ask for it;
   the rulings then build on them. The PR head is still `84bce47`.
2. **R3: flag bit 4 (16)**, one of the two forms R3 offers, not a field inside the flag-8
   extension: the state must be bound on directories without filename sections, where no
   flag-8 extension exists. Consequence: R2's "0.2.1 refuses on flag 8" becomes "0.2.1
   refuses **every** generation a v2.2 folder writer publishes", and the review's section 4
   item 3 (0.2.1 reads filename-off generations) no longer holds. The CHANGELOG, the format
   doc and the consumer row state the rollback rule: keep the previous directory. (A
   binding hidden inside `meta` would have kept 0.2.1 reading, at the price of the very
   meta binding R3 removes; not chosen.) The `HYBSTA01` section duplicates the JSON
   `INDEX-STATE.json` holds (2,522,562 B per generation at 10k on disk).
3. **R4: the filename bytes are reserved at open, not read.** The open allocates the
   size of both sections and of their decoded tables (`filename_field.loadReservation`)
   inside its one section slab (the PR's source-section reservation pattern) and
   opens both files (so a handle keeps its generation's bytes after pruning); the first
   filename query reads into that reservation and decodes from a fixed buffer over it,
   falling back to the handle's arena. So "`ss_open` reads neither section" holds, but the
   open's peak includes the reservation (same 10k corpus: open 50.1 MB with filename
   sections against 45.2 MB without). Reserving keeps the first filename query from
   growing the handle's arena by another geometric step. The one-shot `snapshot_open.open` (CLI single queries) stays eager.
4. **R5:** besides the ruled changes, the body term hash map was removed
   (`postings.lookupExact` over the sorted terms; filename terms through a sorted
   `term_order`). The anchor-walk cursor that took the first filename query after a cold
   open from 5.9–6.2 ms to 4.8 ms landed in the R7 commit, after R7's first measurement.
5. **R6 changes one PR #21 semantic:** a full rebuild (`searchd index` without `--update`,
   `ss_index_folder` over an existing directory) without the setting now keeps the
   directory's channel; PR #21 refused it with `FilenameMigrationRequiresNewDirectory`.
   An explicit different value is still refused (`FilenameSettingMismatch` on update,
   `FilenameMigrationRequiresNewDirectory` on rebuild).
6. **R7's driver** is Python with ctypes (`scripts/s4t2_budgets.py`), one child process
   per library, not a C harness; it measures the same calls (`ss_open`/`ss_close`,
   `ss_query`, `ss_apply_changes`) with `time.perf_counter_ns`.
7. **The R0 merge commit and the R3 commit are not green on their own** (276/277 and
   289/290, both the NFR-13 cap); every commit from R4 on is.
8. **CI cross-check (R8) not done here.** `native-package.yml` runs on `pull_request` only;
   this task pushes the branch and opens no PR, so comparing CI's macOS and Android bytes
   with the table above is left to the PR / verifier. Its iOS binary is not adopted
   regardless.
9. Commit author: the repository's configured git identity, as in earlier tasks; each
   commit carries one `Co-Authored-By: Claude Opus 5.5` line.

  null keeps the directory's setting); `SnapshotInterchangeV2`. A filename query on a
  directory without the channel and a setting that contradicts the directory's
  (`FilenameIndexUnavailable`, `FilenameSettingMismatch`) surface as
  `SearchSimpliException`.
- **Filename search needs a fresh directory.** Pass `filenameIndex: true` to the first
  `applyChanges` (or `indexFolder`) on a new, empty directory, feed every file's bytes,
  then switch to it. An existing index cannot be converted in place.
- **Rollback:** a library older than 0.3.0 refuses every directory 0.3.0 has written or
  updated, with or without filename search; keep the previous directory to roll back to.
  An index written by 0.2.1 opens under 0.3.0 at the same cost (7.34–7.36 ms on the 10k
  index) and its first update rewrites it as v2.2.
