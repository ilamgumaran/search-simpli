# S4-T2 · Integrate PR #21 (the filename channel, bound recovery, scoped writers) onto main after S4-T1

**State:** open · **Depends on:** S4-T1 (merged at f45c06d) · **Size:** L · **Builder:** Opus 5.5 · **Verifier:** Opus 5.5

**Source:** PR #21 (`improve/recovery-and-filename`, head 54f667d, 11 commits from e9d97b0) by another agent, reviewed 1 Nov 2026 in `docs/tasks/REVIEW-PR21.md`. The design fits S3 and the branch is green on its own base, but it was built before S4-T1 and, merged as it stands, it undoes S4-T1's measured gains: the recovery state copied into the manifest's meta makes a 10k MANIFEST 2.5 MB (main: 533 B), the open 32–34 ms (main: 1.6 ms on that harness) and one changed file 131 ms (main: 63 ms), and the NFR-13 10k test fails under the 64 MiB cap; the filename sections are rebuilt at every open; the filename query is quadratic (276 ms at 10k); `openConfined` refuses a root declared through a symlinked prefix; both sides call their contracts 2.1.0. This task merges the PR's work, keeping the author's commits, and fixes those as part of the integration.

- **R3. Recovery state out of the meta.**

  - Keep the PR's recovery tests and point them at the section. Add a corruption test (a flipped byte refuses the write with a stated code; the reader still opens).
  - Gate: the MANIFEST of a 10k index stays under 1 KiB without filename (main: 533–540 B).
- **R4. Filename sections load lazily and are checked cheaply.**

  - `index_status` reports the policy id from the manifest alone.
  - Extend `lazy_open_test.zig`: filename sections not read at open; a damaged catalog fails the first filename query with a stated code while content queries keep working; the concurrent first-use test covers the filename load.

  - No decode per query.
  - Keep the exact semantics. The six frozen cases, the Python↔native parity and the hidden-parity tests must pass unchanged.
