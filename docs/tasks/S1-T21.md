Zig 0.16.0 is at `~/development/zig/zig-0.16.0-macos-aarch64/zig` (on PATH after `source ~/development/env.sh`). Full Xcode 27.0 is on this Mac: `xcrun --sdk iphoneos --show-sdk-path` gives the iOS SDK that an `aarch64-ios` build needs for its libc and frameworks.
- `bindings/dart/search_simpli/tool/build_native.sh` copies the macOS dylib and the Android `.so` into `native/<platform>/` and writes `native/SOURCE-SHA256`; the Dart loader (`lib/src/library_loader.dart`) opens by platform and throws `UnsupportedError('search_simpli: no prebuilt libsearch_simpli for platform …')` elsewhere. On iOS a dynamic library must live in a `.framework` bundle inside the app to be signed and loaded; Flutter's documented form for FFI is `DynamicLibrary.open('name.framework/name')`.
- The app's whisper library already ships this way (`vizhi_whisper.framework`, app task M8-T3): `Info.plist` with `CFBundleIdentifier`, `CFBundleExecutable`, `MinimumOSVersion` 17.0; install name `@rpath/<name>.framework/<name>`.

The Dart suite runs on the Mac with the macOS library as today (the iOS library cannot be loaded on the Mac; say so).
4. **The example app and docs**: `bindings/dart/search_simpli/README.md` and ADR 0002 gain the iOS sentence (how the app embeds the framework is the app's task M8-T5; here only what ships and how it is opened). `docs/tasks/STATUS.md` row; `CHANGELOG` if the package has one.

### Ruling 1 · `aarch64-ios` in `zig build lib`
- `zig/build.zig`: `abi_targets` gains `.{ .cpu_arch = .aarch64, .os_tag = .ios, .os_version_min = 17.0 }` with `needs_apple_sdk = true`. `appleIosLibcFile` runs `xcrun --sdk iphoneos --show-sdk-path` (via `b.runAllowFail`) and writes a Zig libc paths file (`include_dir` and `sys_include_dir` = `<sdk>/usr/include`, `crt_dir` = `<sdk>/usr/lib`), handed to `library.setLibCFile`, the same mechanism the Android target uses with the NDK. The format is the one `zig libc` prints for a paths file (`zig libc` on this Mac printed `include_dir=` and the commented key list). No `--sysroot` is used: `b.sysroot` is builder-global and would also redirect the macOS and Android compiles. Zig's Mach-O linker reads `<sdk>/usr/lib/libSystem.tbd` as a text stub through `crt_dir`; the link succeeded, so no further wiring (no framework paths, no `-isysroot`) was needed. Justification is empirical: the build below, `vtool` reporting platform IOS, and `ss_*` exports. I found no Zig doc line that states this; the doc source for the paths-file keys is the `zig libc` output and `std.Build.Step.Compile.setLibCFile`. For the dynamic library only, `library.install_name = "@rpath/search_simpli.framework/search_simpli"` (see ruling 2 for why it is set at link time).
- Skip: with `PATH` holding only the Zig directory (no `xcrun`) the build printed `zig build lib: the iOS SDK was not found (needs macOS with Xcode and `xcrun --sdk iphoneos`); skipping the aarch64-ios libraries.` and installed the other three targets (`aarch64-linux-android aarch64-macos x86_64-linux`).
- Output (`zig build lib -Doptimize=ReleaseSmall --summary all`): `lib success`; `compile lib search_simpli ReleaseSmall aarch64-ios.17.0 success` for static (2s) and dynamic (3s); the other six compiles also succeed. `zig-out/lib/aarch64-ios/`: `libsearch_simpli.a` 555664 bytes, `libsearch_simpli.dylib` 415833 bytes.
- `vtool -show-build` on the dylib: `platform IOS`, `minos 17.0`, `sdk 27.0`; `lipo -info`: `arm64`.
