# S1-T21 · The search core for the iPhone: an `aarch64-ios` build in `zig build lib`, shipped as `search_simpli.framework`, opened by the Dart loader on iOS

**Why.** Simpli Helper runs on the family iPhone since 18 Oct 2026 (app task M8-T1), with `HostPlatform.ios.hasSearchCore` false and the Library saying "Search is not ready on this phone yet." because `search_simpli/native/` ships only `macos-arm64` and `android-arm64` (ADR 0002 named iOS "when the app needs it"). The app needs it now (app task M8-T5 bundles what this task ships).

## Facts (18 Oct)
- `zig/build.zig`'s `abi_targets` lists `aarch64-macos`, `aarch64-linux-android` (needs `SS_ANDROID_NDK` for libc) and `x86_64-linux`; `addAbiLibraries` builds static and dynamic per target with `link_libc = true`. Zig 0.16.0 is at `~/development/zig/zig-0.16.0-macos-aarch64/zig` (on PATH after `source ~/development/env.sh`). Full Xcode 27.0 is on this Mac: `xcrun --sdk iphoneos --show-sdk-path` gives the iOS SDK that an `aarch64-ios` build needs for its libc and frameworks.
- `bindings/dart/search_simpli/tool/build_native.sh` copies the macOS dylib and the Android `.so` into `native/<platform>/` and writes `native/SOURCE-SHA256`; the Dart loader (`lib/src/library_loader.dart`) opens by platform and throws `UnsupportedError('search_simpli: no prebuilt libsearch_simpli for platform …')` elsewhere. On iOS a dynamic library must live in a `.framework` bundle inside the app to be signed and loaded; Flutter's documented form for FFI is `DynamicLibrary.open('name.framework/name')`.
- The app's whisper library already ships this way (`vizhi_whisper.framework`, app task M8-T3): `Info.plist` with `CFBundleIdentifier`, `CFBundleExecutable`, `MinimumOSVersion` 17.0; install name `@rpath/<name>.framework/<name>`.

## Rulings
1. **`aarch64-ios` in `abi_targets`**: `.{ .cpu_arch = .aarch64, .os_tag = .ios }` with a `needs_apple_sdk` flag; when the host has `xcrun` and the iOS SDK, the build passes the SDK as the sysroot (and whatever libc wiring Zig 0.16 needs for `aarch64-ios`; say exactly what, with the Zig doc or source line) and builds static and dynamic into `zig-out/lib/aarch64-ios/`; when the SDK is absent, it skips with one warning line, as the Android target does without the NDK. `zig build lib` on this Mac builds all four; `zig build test` and the Zig conformance suite are unchanged (totals pasted: Python, Zig, ABI, Dart as the baseline rows in STATUS).
2. **`search_simpli.framework`**: `tool/build_native.sh` wraps the iOS dylib as `native/ios-arm64/search_simpli.framework/` (`search_simpli` binary with install name `@rpath/search_simpli.framework/search_simpli`, `Info.plist` with `CFBundleIdentifier` `family.vizhi.searchsimpli`, `CFBundleExecutable` `search_simpli`, `CFBundleName`, `CFBundlePackageType` `FMWK`, `MinimumOSVersion` `17.0`, `CFBundleSupportedPlatforms` `iPhoneOS`), arm64 only, minimum iOS 17.0 (`vtool -show` or `otool -l` pasted); unsigned (the app signs it when it embeds it). `native/SOURCE-SHA256` covers the sources as before; the framework is committed like the dylib and the `.so` are (size in the Report). A `tool/check_native.sh` (or the existing check) verifies the three shipped binaries' architectures and the framework's `Info.plist` keys.
3. **The Dart loader on iOS**: `openSearchSimpliLibraryWith` gains `isIOS` and, on iOS, returns `opener('search_simpli.framework/search_simpli')` (the `SEARCH_SIMPLI_LIBRARY_PATH` override still first); the "no prebuilt" message lists iOS among the built platforms; Dart tests for the iOS branch (the path handed to the fake opener; the override winning; the message). The Dart suite runs on the Mac with the macOS library as today (the iOS library cannot be loaded on the Mac; say so).
4. **The example app and docs**: `bindings/dart/search_simpli/README.md` and ADR 0002 gain the iOS sentence (how the app embeds the framework is the app's task M8-T5; here only what ships and how it is opened). `docs/tasks/STATUS.md` row; `CHANGELOG` if the package has one.
5. **CI**: the GitHub workflow builds the iOS library only on a macOS runner with Xcode, else the skip line shows; nothing else changes. No author rewrite; one `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>` per commit; never a `Claude-Session:` line.
