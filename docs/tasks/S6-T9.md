1. **Format document first, then the build, in one phase.** Write the format documents by the repository's convention (a new state-section version, a new catalog version, the manifest version and flag bit or bits) so a reader can implement a decoder from them alone: the layout byte for byte, how a state record names its source-table entry, how a stem and a chunk id are derived from an anchor, every validity rule with its own error, and a worked example. **Stop and report before building only if** the contracts or the C header would have to change, the measured saving on a re-encoded 10k timing corpus is under half of S6-T3's figure for either part, or the design cannot be implemented as written; otherwise go on. If one part meets the bar and the other does not, build the one that does and report the other.
2. **One format version, the previous readers kept.** The new library opens an index written by `main` at `fa56ee9` and by each earlier format step (before S6-T8, before S6-T7, before S6-T4) and answers identically; it writes the new format at the first publish, one whole generation, byte-identical to a fresh index. An older library refuses the new index with a clear error through the CLI and the C ABI and leaves the files byte-identical. This is the fourth one-way step: the migration note goes in the Dart CHANGELOG and the 03-next pin row, beside the other three.
3. **Same answers.** Every surface (CLI, JSON-RPC, MCP, `ss_query`, `find`, `read_span`, `outline`, `list_files`, `searchd search`, and search under `search_field` `filename` and `both`) byte-identical to `main` on J2, the fixtures, the family fixture and the three 10k corpora, fresh and on an old-format index updated once. Change detection in particular: after the migration, an unchanged folder plans zero work, and a changed, added, removed and renamed file is each planned exactly as `main` plans it.
4. **Expectations, stated here before measuring.** Size: each part within 5 % of S6-T3's figure on the 10k timing corpus. Open time and memory after open: not above `main`. Query, `find` and file-name search: not slower than `main` on any cell by the rule of 2026-11-17 in [ROLES](../process/ROLES.md). Planning an update (the path that reads state), one-file update and first publish from the old format: not slower than `main` by more than 2 %. A missed expectation is reported as missed and is the maintainer's to accept; it is not tuned away and not reworded. Removing work the new code does not need is engineering, not tuning, and is recorded as made after measurement.
5. **Timing** by the rule of 2026-11-17: five gated runs by the verifier (the builder takes two for information), Latin-square orders written before the first run, controls `main2` and `main` plus never-run code, including controls with never-run code placed beside the new code (S6-T8 showed placement alone moves cells by tens of microseconds); the control set is fixed and committed before the first run.
