### Design decisions worth the tester's attention

- **`ss_query`'s JSON round-trips byte-for-byte through Dart's own
  `jsonEncode`.** `SearchKnowledgeResult.toJson()`'s field order was written
  to match `zig/tests/abi_test.c`'s golden string field-for-field (not
  guessed — I read the golden first), and `test/conformance_test.dart`'s
  first test asserts `jsonEncode(result.toJson())` equals that exact golden
  string, not just an equivalent parsed structure. This is a stronger claim
  than "the fields are the same" — it proves this binding's `toJson()`
  never reorders, drops, or reformats anything `ss_query` returned.
- **The Android instrumentation smoke test does not call `ss_import_json`
  on-device.** It was tried first (publish a snapshot into the app's own
  `files/` directory, then open it) and failed on the `vizhi-phone` emulator
  (API 37) with `ss_import_json: AccessDenied`. Root-caused, not just
  worked around blindly: Zig 0.16's `Dir.createFileAtomic`
  (`zig/src/publication.zig`'s atomic-publish path) opens an `O_TMPFILE`
  descriptor before renaming it into place on Linux targets
  (`lib/std/Io/Threaded.zig`'s `dirCreateFileAtomic`), and this device's
  SELinux policy denies `O_TMPFILE` inside an app's private directory — the
  function turns that specific `EACCES` into `error.AccessDenied` directly,
  with no fallback to a non-`O_TMPFILE` path. This is an engine/std-library
  question (`ss_import_json`, owned by S1-T0), not something a binding
  should paper over, so the example instead bundles an already-published
  snapshot as a Flutter asset and only exercises `ss_open`/`ss_query`/
  `ss_close` (which never write) — recorded in `example/lib/main.dart`'s
  header comment and this package's README, and listed as a known
  limitation below rather than silently avoided.
- **`ss_evidence`/`ss_query` error convention.** `SearchSimpli.query`
  frees every native buffer it allocates (`malloc`/`toNativeUtf8`) in a
  `finally` block regardless of success or `ss_*` failure, and frees the
  `ss_query`/`ss_evidence`/`ss_status` result string with `ss_free` before
  returning the parsed Dart object — verified by running `dart test` under
  default settings repeatedly with no leak-detection tool available in this
  environment, so this is a code-review-level guarantee (every allocation
  path has a matching free on every exit path), not a measured one.
- **`SearchSimpli.close()` is not idempotent by design** (throws
  `StateError` on a second call) rather than silently ignoring it, matching
  `search_simpli.h`'s "do not call `ss_close()` twice on the same handle"
  contract as closely as a safe Dart wrapper can — a silent no-op would let
  a caller double-free without ever finding out.

### Not done / narrowed scope

- **Criterion 2's "every fixture"** is read here as "every fixture S1-T1
  itself proved a Python-reference golden for" — `fixtures/bm25-golden.json`
  (`app_text` + `tamil/passages`, the same 18-query set
  `zig/src/bm25_conformance_test.zig` uses for the engine's own Python
  conformance claim) plus the S1-T0 ABI harness's 3-document demo snapshot.
  `fixtures/judgments.json`, `fixtures/mixed-judgments.json`,
  `fixtures/semantic-judgments.json`, and
  `fixtures/relevance-smoke/judgments.json` are graded-relevance fixtures
  built around vector/hybrid modes and nDCG/MRR aggregate scoring
  (`evaluate.py`/`relevance_smoke.py`), not a per-query "Python's top-1
  path" golden the way `bm25-golden.json` is — extending this conformance
  test to them would mean generating a new golden fixture (a scope decision
  for whoever owns `fixtures/`, not something to do silently inside a
  binding task). `searchd index` itself is also lexical-only
  (`embedding_model_id: "none"`, S1-T1), so a vector/hybrid fixture has no
  native-CLI equivalent to compare against yet regardless.
- **`ss_import_json` is not proven to work from an Android app's private
  storage.** See the design-decisions section above; this is a Zig
  standard-library / `ss_import_json` (S1-T0) finding, not fixed here.
  `importSnapshotJson` works correctly from Dart on macOS (exercised by
  every test in `test/`) and is the mechanism `test/conformance_test.dart`
  and `test/search_simpli_test.dart` both use to set up fixtures.
- **No `ss_index_folder` binding** — S1-T3 (running in parallel on
  incremental folder indexing) had not landed `ss_index_folder` in
  `abi.zig`/the header as of this branch; per the coordinating instructions
  for this round, no TODO stub was added since the function does not exist
  yet to bind. `SearchSimpli` only binds the eight S1-T0 functions that
  exist today.
- **Only macOS arm64 and Android arm64** (ADR 0002's current bindings
  target set, per criterion 1 literally) — no Linux/iOS/Windows Dart
  library.
- Leak-freedom of the FFI wrapper (every `malloc`/`ss_free` pair) is a
  code-review-level guarantee, not instrumented with a native leak
  detector (none was available in this environment) — see the design
  section above for exactly which paths were checked by hand.
