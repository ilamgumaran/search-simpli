# S2-T12 · Never publish an empty generation by accident; expose pruning and recovery in Dart

**State:** verified · **Series:** S2 (found by the S2-T5 verifier, findings A and B) · **Depends on:** S2-T5 · **Size:** S · **Builder:** Sonnet 5 · **Tester:** Opus

Two leftovers from S2-T5.

**A.** With `MANIFEST` missing but `INDEX-STATE.json` present, `searchd index
--update` and `ss_index_folder` in update mode treat the directory as new,
trust the state file's "every file unchanged", and publish an **empty**
generation with exit 0; every later update stays empty until a file changes,
and with `keep_generations` the same run prunes the older complete
generations. S2-T5's own publish order cannot produce that state
(`INDEX-STATE.json` is written only after the second directory sync), so it
takes an outside deletion of `MANIFEST` or a filesystem that ignores
directory sync; but the outcome is silent data loss of the index, which is the
one thing a phone's publisher must never do.

**B.** The Dart wrapper has no `keepGenerations` on `IndexFolderOptions` and
does not expose `recovered`, `pruned_files` or `prune_failures`, so the app
cannot ask `ss_index_folder` to prune through the package, nor see that a
recovery happened. (`ss_import_json` already takes `keep_generations` in the
payload, and `SnapshotInterchangeV1.keepGenerations` exists.)

## Acceptance criteria
1. When there is no previous engine to load (no `MANIFEST`, or `MANIFEST`
   unreadable in a way S2-T5 did not already cover), the update path **does
   not load `INDEX-STATE.json`**: it re-indexes every file and publishes a full
   generation, reporting `"recovered": "missing_manifest"` (additive; the
   value set is documented next to `"missing_section"`). An update can publish
   zero documents only when the folder holds zero indexable files, and then
   the report says so explicitly (`"documents": 0` with no `recovered`).
2. **Bar (a):** the S2-T5 verifier's case (vii) — `MANIFEST` deleted, sections
   and `INDEX-STATE.json` present — now publishes the full corpus
   (`documents` equals the corpus count), and a following update is ordinary.
   Repeat with `keep_generations: 1`: the older complete generations are
   pruned only after the full generation is visible.
3. Dart: `IndexFolderOptions.keepGenerations` (≥ 1, `ArgumentError` on 0),
   passed through `ss_index_folder`'s options; the index report type exposes
   `recovered` (nullable enum with an `unknown` fallback carrying the raw
   string), `prunedFiles` and `pruneFailures` (null when the option was not
   set). Round-trip tests from captured reports, including one with and one
   without each field.
4. **Plant:** with the state-file load restored for the no-manifest case, the
   test from criterion 2 fails (`expected N, found 0`); with the Dart
   pass-through removed, the Dart test fails.
5. `docs/incremental-indexing.md` and `docs/publication-recovery.md` list both
   `recovered` values and say what each costs.
6. All five suites green after the Report; libraries rebuilt last.

### Non-blocking findings
1. **Generation numbers can go backwards after a lost `MANIFEST`** (older than this branch; `origin/main` does the same). The setup: generations 1–2, then `--keep-generations 1` leaves only `documents/lexical-2`, then `rm MANIFEST`. The next publish (full or update) is **generation 1**: `nextFreeGeneration` takes the lowest free number, not one above the leftovers. The generation-2 files then count as orphans "at or past current" and survive pruning until the counter passes them. With keep 1, the run after that is gen 3 and removes them. An app that reopens only when `generation` increases would miss the recovered snapshot. Suggestion for the orchestrator: when `MANIFEST` is missing, start numbering above the highest section file present.
2. **Dart native leak on the `ArgumentError` path.** `SearchSimpli.indexFolder` allocates `dirPtr`/`folderPtr` with `toNativeUtf8()` before `options.toJson()` runs, and outside the `try`/`finally`. An invalid `keepGenerations` therefore leaks two small native strings per call. It also opens the `DynamicLibrary` first, a `dlopen`, not an `ss_*` call. One-line fix: compute `jsonEncode(options.toJson())` before the first allocation.
3. **`no_previous` is redundant with `recovered`**, as explained under Plants. It is harmless; keep it or fold it.
4. Out of scope and unchanged, as listed: S2-T5 finding C (open vs scan on trailing bytes; a flipped `MANIFEST` byte is `TrailingData`/`Truncated` depending on position) and the `"keep_generations":"2"` coercion.
5. No real power cut was performed. The trace is a DYLD interposer on `linkat`/`renameat`/`unlinkat`; directory syncs were not traced here (S2-T5 covered them).
