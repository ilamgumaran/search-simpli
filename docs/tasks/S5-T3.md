**What changes.** The change is at query time only.
- **The trigger.** A query term triggers when it matches no chunk in scope (the exact predicate behind today's `query_term_unmatched`), no visible file's title field holds it, it is all Latin script, and it is at least 5 code points long.
- **The expansion.** A triggering term is expanded to at most 3 terms within an optimal-string-alignment distance of 1, or 2 for terms of 6 or more code points. Each expansion keeps the first code point. The candidates come from the body dictionary and the title term table.
- **The scoring.** The expansions score as one word. They share one document frequency, the largest of theirs. Each chunk takes the best member's part, weighted 1.0 at distance 1 and 0.5 at distance 2.
- **Surfaces.** This applies to the body part and the title part, so `content` and `both` both gain. `filename` and `find` are unchanged.
- **Formats.** There is no format change, no writer change and no phone rebuild.

## Rulings

1. **The design, and what it is not.**
   - **Chosen.** Expansion at df 0 only, at query time, scoring as one word (rulings 2–3).
   - **What it is not:**
     - not a "did you mean" rewrite;
     - not a change to the analyzer, the dictionary or any format;
     - not fuzzy `find`, and not fuzzy matching on the `filename` channel.
   - **Rejected, with the numbers that rejected them** (J2 misspelling `content` success@1/MRR@10 unless stated; the gate is against the S5-T2 baseline):
     - **A weight below 1 at distance 1.** 0.8 gives 0.438/0.546, and mixed MRR 0.808 instead of 0.833. 0.5 gives 0.375/0.509; 0.3 gives 0.250/0.449. With the blended df, a weight of 1.0 already scores an expansion exactly as the real word would score. A lower weight only loses rows (`m05` sits on a knife edge and is lost at 0.9).
     - **Damping by `1 − d/len`.** 0.438/0.545: it loses `m05`.
     - **No distance 2.** 0.438/0.562: it loses `m01` (`dinosoar`).
     - **Expansion at low but non-zero df (df ≤ 1).** **The gate fails.** Control `c22` (`tomato seedlings potted`) loses rank 1 (`potted`→`pottery`; MRR 1.000 → 0.978). Without the typed word kept in its own group, Tamil also falls from 0.231 to 0.000.
     - **No title guard.** **The gate fails.** `th08` (`health`, a word only a folder name holds) is expanded away from itself, falls out of the top 10, and title-heldout drops from 1.000 to 0.875.
     - **Any first letter.** Misspelling is the same (0.500/0.590), but morphology `content` drops from 0.308 to 0.231 and the expansions are noisier. On a corpus where a first-letter range is small, it also multiplies the scan.
     - **Each expansion's own df, summed** (Luxir-like): the same J2 numbers. It breaks the principle that a rare spelling never outranks the common word. At distance 1 from 3 code points it lifted one accent row (`cafe`→`café`) only by also scoring `cage` and `cake` at their rarer dfs. Rejected on that principle.
     - **Summing the members within a chunk** instead of taking the best: the same J2 numbers, but mixed MRR is 0.808 instead of 0.833 (`combine-exact-and-meaning` is not lifted). One word should count once.
     - **The prefix/edit hybrid** (a completion of ≥ 4 code points counts as distance 1): misspelling 0.438/0.545, morphology 0.308/0.429, **Tamil 0.231 → 0.385** (measured at weight 0.8). This is a stemming effect, and it belongs with the analyzer-v3 folding/stemming task (open question 7).
     - **Distance 1 from 3 code points** instead of 5: the same misspelling numbers, but morphology MRR is 0.417 instead of 0.429, and mixed MRR is 0.825 with `avoid-full-corpus-scan` 2→3 (`file`→`files`). It also makes wrong short expansions: `cafe`→cage/cake, `skip`→slip/skin, `pony`→pond, `them`→the/they/then, `why`→who, `once`→one. It would also scan for `how`, `does` and `work` in the S4 timing query `how does the hybrid retrieval work for a search`, which all have df 0 in the 10k corpus.
     - **N.** 1, 3, 10 and 50 give identical J2 numbers. N = 3 bounds the work and the report.
     - **Tamil and other scripts.** Expanding them gives the same J2 numbers, but every Tamil expansion has a wrong meaning (`கடைக்கு`→கடலுக்கு, `பழங்கள்`→பாடங்கள், `பாடல்`→பால்). Tamil is left out explicitly (ruling 2). Rows `t01`–`t13` are not touched.
     - **Expansions feeding `find`.** Rejected (see "What no expansion fixes", `m06`). A suggestion is a separate, later task (open question 4).

2. **The rule, exactly (`fuzzy-v1`).** It applies to the lexical channel under `content` and `both`, in lexical and hybrid retrieval.

   **Terms.** A query's terms are its analysed terms, as today:
   - under `content`, the body analyzer's terms;
   - for the title part, `title-field-v1`'s terms.

   Each distinct term is considered once.

   **The trigger.** A term *t* triggers when all four of these hold:
   1. *t* matches no chunk in scope. This is the exact predicate that makes today's `query_term_unmatched`, including a term present only outside the scope (`query_report_test.zig`, "also covers a term present only outside the searched scope").
   2. No **visible** file's title field holds *t*: the title guard. A term held only by a hidden file's title does not guard.
   3. Every code point of *t* is a digit 0–9 or a Latin letter in one of these ranges:
      - U+0061–U+007A;
      - U+00DF–U+00FF except U+00F7;
      - U+0100–U+024F;
      - U+1E00–U+1EFF.

      The Python mirror uses this table, not `unicodedata` names. The prototype used names, and the two agree on every J2 term.
   4. *t* has at least **5** code points.

   Check them cheapest first: length, then script, then the title-guard lookup. A term that fails any check costs nothing more.

   **The bound.** The maximum distance *k* is 1 for 5 code points and 2 for 6 or more. Distance is **optimal string alignment** (adjacent transposition = 1, no substring edited twice), counted on the code points of the analysed (NFC, folded) terms, never on bytes.

   **The candidates.** A candidate is a term *c* that meets all of these:
   - *c* is a body-dictionary term with in-scope df ≥ 1, or a term of a visible file's title field;
   - *c* has the same first code point as *t*;
   - |len(*c*) − len(*t*)| ≤ *k*;
   - 1 ≤ OSA(*t*, *c*) ≤ *k*.

   **The order and the cut.** Candidates are ordered by (distance ascending, key df descending, UTF-8 bytes ascending). The key df is the in-scope body df, or 1 for a title-only term. The first **N = 3** are kept.
   - The in-scope df is used everywhere, never the whole-index df. Hidden chunks must not change which word a principal is shown.
   - No candidate means no expansion, and the query behaves as today.

   **The group.** The group of *t* is its kept candidates, each with a weight *w*: **1.0** at distance 1, **0.5** at distance 2. The typed term itself is not a member: its df is 0.

   **Body scoring.**
   - The group's document frequency is one blended value: df_g = the **largest** in-scope body df among the members. A title-only member contributes 0, and if every member is title-only, the group has no body part.
   - In each chunk, the group contributes max over the members it holds of *w* · BM25(tf, df_g, chunk length, average length). N and the average length are those of the scope, as today.
   - Every non-triggering term scores exactly as today.

   **Title scoring** (`title-field-v1`).
   - The same group is used, with the title field's df: df_g = the largest title df among the members.
   - Per file, it contributes max over held members of *w* · BM25_title.
   - Coverage counts the query term as covered when the file's field holds any member. The denominator stays the query's distinct terms.

   **Reuse.** One scan per triggering term per query. `both` reuses the same groups for its body scoring and its title part.

   **The warnings.** See ruling 5. The typed term still gets its `query_term_unmatched` warning, unchanged, and then one `query_term_expanded` warning. `check_unmatched_warnings.py` stays green.

3. **Where it lives (Zig).**
   - **`zig/src/fuzzy.zig` (new).**
     - The Latin check.
     - The bounded OSA on code points: banded |i − j| ≤ *k*, with an early exit when a row's minimum exceeds *k*.
     - The candidate scan over one sorted term table. `postings.Index.terms` is sorted bytewise (HYBLEX02), and UTF-8 byte order is code-point order, so the terms sharing *t*'s first code point form one contiguous range, found with `lowerBound` on the first code point's bytes and on the next code point's bytes. The title field's term table is scanned the same way.
     - The ordering, the cut and the group.
   - **`engine.queryTraced`.**
     - After `resolveTokensTraced`, only for the terms it reports unmatched, run the trigger checks and the scans, then hand the groups to the scorer and to `title_field.scoreQuery`.
     - A query with no group takes **today's code path unchanged**: one branch, before any allocation.
   - **The scorer.**
     - The members' document frequencies go through `SparseScorer.document_frequencies` (df_g for each member).
     - The per-chunk "best member" needs a group-aware accumulation. The builder chooses its shape: a member-to-group map with a per-chunk max, or a small wrapper scorer. The profile (ruling 9) reports its cost.
   - **`filename_field.scoreQuery`** (the `both` path's body scoring) takes the same groups.
   - **Nothing is retained** between queries. The scan reads the dictionary in place.

4. **The Python reference's mirror** (`src/search_platform/core.py`).
   - `search()` computes the groups once per query from the visible chunks, with the same trigger, candidates, order and cut. It passes them to `_bm25_scores` and `_title_scores` (internal signatures) and to `_search_filename_fields`' body scoring.
   - With no group, both functions run today's arithmetic unchanged, bit for bit. The prototype's `fuzzy_expand.py` shows that this holds when the groups are summed in sorted term order.
   - `FolderIndex.search` is not mirrored, as at S5-T2 (its deviation 6).
   - **The known surface difference.** The reference's body `tokenize` uses full case folding, while the engine and `_filename_tokenize` use the simple fold. A term with `ß` can therefore trigger on one surface and not the other (J2 `a09`). The golden avoids such terms and names this (open question 6).

   - **Privacy.** An expansion is always an in-scope term, by ruling 2. A unit test plants a term held only by a hidden chunk and asserts that it is neither used nor reported.

#### 6. What was built

- **`zig/src/fuzzy.zig`** (new):
  - the trigger: 5 or more code points, every code point a Latin letter or a digit, no chunk in scope holds the term (roots, labels, the path prefix), and no visible title holds it (roots and labels, no prefix);
  - OSA, banded and clamped at `k + 1`, behind a letter-count lower bound;
  - the scan reads the dictionary range that starts with the typed word's first code point (a binary search on a sorted dictionary, otherwise a filtered linear walk);
  - a body candidate must be held by a chunk under the prefix. Its key df is the visible scope's df (roots and labels, never the prefix: ruling 8). A title-only candidate has key df 1;
  - the order is (distance, key df descending, bytes), and 3 are kept;

  - `SparseScorer` gives the group one df (the maximum over its body members);
