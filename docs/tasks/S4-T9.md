# S4-T9 · The open holds only what it reads: no reservation for unread sections, no arena slack on the slab

**State:** ready (starts from `main` after the S4-T8 merge) · **Date:** 2026-11-05 · **Depends on:** S4-T8 (the scale tests and the by-table attribution) · **Size:** M

**Owner:** the Xcode Mac orchestrator · **Orchestrator:** Claude Fable 5.1 · **Builder:** Claude Opus 5.5 (local) · **Verifier:** Claude Opus 5.5 (local, a different agent)

**Why.** S4-T8 measured NFR-13 (the 64 MiB caller-owned workspace, CAP-19) past 10k files, filename channel on, peak live bytes: the open 50,128,018 B at 10k, 74,149,978 at 15k, 98,275,150 at 20k (linear within 0.43 %, 4,814,713 B per 1,000 files); `find` would reach the cap at about 11,985 files, `list_files` at 12,064, the open itself at 13,527. Its attribution found that almost all of the open's peak is **one arena block for the section slab**: `snapshot_open.loadEngine` allocates, in one piece, the documents and lexical sections it reads **plus the source section's bytes and the filename channel's reservation, which it does not read** (PR #21's slab, S3-T4's deferred source, S4-T2 R4's reservation: all placed there so that a first `read_span` or filename query would not grow the handle's arena by another geometric step), and `std.heap.ArenaAllocator` sizes that block at about 1.5 times the request, so the decoded tables that follow add 0 held bytes and the slab's size alone drives the peak. At 20k the lexical section is 24,054,450 B (24.5 % of the peak); the corpus's text, reserved for the source section, is about 14.4 MB; the arena's slack is about a third of the whole.

This task changes what the open holds, not what it reads from disk or how the index is laid out: the format, the contracts, the analyzer, every result are unchanged.

## Rulings
1. **The open allocates exactly what it reads, once, outside the arena's growth.** `loadEngine` asks the handle's parent allocator (the one the arena was built over: `std.heap.c_allocator` in `abi.zig`; the test's `Capped` in `nfr13_arena_test.zig`; whatever `rpc.Generation` and `searchd` pass) for **one exact block** holding the manifest bytes, the documents section, the lexical section and the decoded tables the open builds from them (`hybrid.Document` × `document_count`, the vectors, `postings.TermEntry` × `term_count`, `postings.Posting` × `posting_count`, the `u32` lengths), sized from the manifest's counts, and frees it when the handle closes (`ss_close`, `Generation.deinit`, the scoped open's `deinit`). Nothing of the open goes through the arena's geometric growth any more; the arena stays for per-call scratch. State in the Report how the block is owned (a field on the opened engine or the handle) and that a failed allocation still fails the open cleanly (`CAPACITY`, as today).
2. **Unread sections are not reserved.** The source section's buffer is allocated at its first use (`scope.zig`'s `openSource` path already allocates when `source_buffer` is null: that branch becomes the only one) and the filename channel's catalog and lexical sections and their decoded tables at the first filename query (`scope.zig` line ~538's `FixedBufferAllocator` over the reservation becomes an exact allocation from the parent allocator), each as **one exact block from the parent allocator**, owned like ruling 1's and freed at close, so the reason the reservations existed (no geometric step on first use) still holds without paying for them at open. `filename_field.loadReservation` is removed or kept only as the size the first filename query allocates (say which). `index_status` still reports the filename policy without reading the sections (S4-T2).
3. **The bar.** `nfr13_arena_test.zig`: the existing 10k tests keep their names and assert the 64 MiB cap as today, and their printed peaks must fall (the Report shows before and after per operation at 10k, from this branch's runs, next to S4-T8's); the two scale tests from S4-T8 keep their 256 MiB measurement cap and their printed peaks, and **the 15k test gains the assertion that every operation's peak is under 64 MiB** (the open, `find`, `search_knowledge`, `list_files`, a filename query, a `both` query). ### Per ruling

1. **One exact block for what the open reads** (`edafe3d`). `snapshot_open.loadEngine`
   reads the manifest once into a buffer of its own (its counts size the block), then asks
   `Allocators.blocks` (the handle's parent allocator) for one block laid out by
   `snapshot_open.OpenBlock.of` from the manifest's counts: `hybrid.Document` ×
   `document_count`, `postings.TermEntry` × `term_count`, the `f32` vectors,
   `postings.Posting` × `posting_count`, the `u32` lengths (each at its own alignment;
   the block is aligned to the strictest, `engine.open_block_alignment` = 8), then the
   manifest's copy and the documents and lexical sections as read. The manifest is decoded
   again from the copy, and the first buffer is freed before the open returns (it is live
   beside the block for one copy: 696 B at 10k). **Ownership:** a field on the opened
   engine, `Engine.open_block: ?[]align(8) u8`; the allocator it came from is
   `scope.Loads.blocks`. `snapshot_open.close(engine, folder)` closes the files
   (`Folder.close`), frees the first-use blocks (`Folder.releaseBlocks`) and then the open's
   block; `ss_close` (through `abi.closeWith`), `rpc.Generation.close` (so `searchd serve`
   and `searchd mcp`, and the served reload, which opens the next generation before it
   closes the old one) and the NFR-13 `measure` call it before their arena goes. The
   `Generation`'s blocks come from its `gpa`, not its heap arena, so they survive the
   reload exactly as long as the generation does. **A failed allocation** fails the open as
   before: `error.OutOfMemory` from the same call, the block freed by `errdefer` in
   `loadEngine` and `openScopedWith`; `ss_open` returns `NULL` with `ss_open: OutOfMemory`,
   which is what it said before (the open has no `CAPACITY` code today; a lazy load's
   failure still answers `SS_ERR_OUT_OF_MEMORY`). The test "the cap bites (a 256 KiB cap
   refuses the same open)" still passes. Callers: `openScopedWith(.{ .blocks, .arena })` is
   new; `openScoped(allocator)` and the eager `open(allocator)` pass one allocator for both
   (`Allocators.one`), so the one-shot CLI commands, the benches and the tests that hand an
   arena keep everything in it, discarded wholesale (deviation 2).
2. **Unread sections are not reserved** (`b5f4dab`). The block holds no source or filename
   reservation. `scope.Loads.readSource` allocates the source section's bytes as one exact
   block from `Loads.blocks` (the only branch now; `Engine.source_buffer` and
