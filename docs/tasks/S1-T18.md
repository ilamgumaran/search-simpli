# S1-T18 · `NoFreeGeneration` names its cause; the Dart allocator hook leaves the public API

**State:** built (2026-10-10) · **Series:** S1 · **Depends on:** S2-T14 · **Size:** XS · **Builder:** Sonnet 5.5 · **Tester:** Opus 5.5

**From the S2-T14 Verdict, findings 2 and 3.** Since S2-T14 a stray section file or an `INDEX-STATE.json` naming a huge generation (anything at `u64` max) stops every self-numbered publish into that directory with `error.NoFreeGeneration`, even next to a valid `MANIFEST`, and the error does not say which file caused it; `main` before S2-T14 published normally there (it ignored the stray). The rule stands (numbers never go backwards); the message must name the cause so a person can delete the right file. Separately, S2-T14 added `Allocator allocator = malloc` to the public `indexFolder` signature of the Dart package as a test hook; a package-private seam is the right shape.

## Rulings
- The numbering rule of S2-T14 is unchanged. The CLI and the ABI error for `NoFreeGeneration` name the offending path (file name only, no directory) and the generation read from it, on one line.
- The Dart package's public `indexFolder` signature returns to its pre-S2-T14 shape; the counting-allocator test reaches the seam through a package-private constructor or `@visibleForTesting` member, not a public parameter. The leak test stays and keeps asserting 0 allocations on the `ArgumentError` path.

Through `ss_index_folder` the ABI error text (or `ss_last_error`, whichever the ABI exposes) carries the same name. A Zig test and a Python process test pin the message.
2. The Dart public signature restored; the leak test green through the private seam; `dart analyze` clean; the package README's `indexFolder` line matches the signature again. **Plant:** the reorder reverted → the leak test fails `Expected: <0> Actual: <2>`.
