# S6-T14: the source files move into `core/`, `ops/` and `interfaces/` (plan step B2)

**State:** filed by the orchestrator, 20 Nov 2026, from `main` at `548dac1` · **Depends on:** [S6-T1](S6-T1.md) (the layer map and its checker), [S6-T9](S6-T9.md) (the last format step, merged, so no open branch touches these files) · **Plan:** [objective plan](../plans/2026-11-16-objective-plan.md), section B, step 2

## Why

The layers exist today only as a table in `scripts/check_layers.py` and
`docs/layers.md`: all the Zig files sit side by side in `zig/src/`. A
contributor cannot see from the tree what is core and what is an interface, and
the build does not stop an interface reaching into core internals except through
the checker. Step B2 makes the tree and the build say what the checker says.

## What

A mechanical move with no behaviour change.

1. Every file the checker assigns to a layer moves, with `git mv`, to
   `zig/src/core/`, `zig/src/ops/` or `zig/src/interfaces/`, as
   `scripts/check_layers.py` assigns it today. No file changes layer.
2. `zig/build.zig` builds the core as its own module; operations and interfaces
   reach it as a module, not by a relative path into `core/`. If Zig 0.16's
   module rules make a part of this impossible without changing code beyond
   import lines, stop and report the smallest alternative.
3. `scripts/check_layers.py` and `docs/layers.md` describe the new tree, and the
   checker fails when a file sits in a folder other than its layer's.

## Rulings

1. **Only import lines and build wiring change in source.** No function body,
   no public name, no error, no string. A diff of each moved file against its
   old content shows `@import` lines only. Anything more is listed in the Report
   with its reason, or the task stops.
2. **Tests, benchmarks and tools.** A test file that imports files of one layer
   only moves into that layer's folder beside its subject. A test that crosses
   layers, and every benchmark and tool, goes where the builder proposes
   (`zig/src/tests/`, `zig/src/tools/` or similar), stated in the Report with the
   rule used. Every test that runs today runs after: the totals per step equal
   `main`'s (Build Summary and the engine step), and a deliberately broken
   assertion in one test per folder fails the build.
3. **Same bytes out.** Indexes written by the head are byte-identical to
   `main`'s on the three 10k corpora, the fixtures and J2; every answer surface
   (CLI, JSON-RPC, MCP, C ABI) is byte-identical on J2; the C header and the
   exported symbols are unchanged; contracts unchanged.
4. **Natives.** Rebuilt and restamped in the same commit as the move, because
   the digest covers the paths. Sizes are reported against `main`. A size change
   is expected to be zero or a few bytes; more than 1 % on any native stops the
   task.
5. **Speed.** The expectation, stated before measuring: query, find and open
   time **pass the timing rule of 2026-11-17** (`docs/process/ROLES.md`) against
   `main` on the three 10k corpora. The literal difference is reported beside
   it for the maintainer.
6. **Documents.** Every living document that names a path under `zig/src/` is
   corrected (README, CONTRIBUTING, `docs/layers.md`, format and lifecycle
   documents, the skill, CI workflows, scripts). Past task files, evidence and
   the journey's history are left as written. Dart package version: bumped only
   if the natives' bytes change (then 0.9.5, with a CHANGELOG entry that says
   no behaviour changed).
7. **Stop before:** a contract, C header, format or answer change; a change to
   any function body; a layer change for any file; a failing byte comparison.

root directory and lets a file belong to one module only, so this is the one form the module rules allow.
`fastmem.zig` stays the separate object it was (not in `core.zig`); `main.zig` is in no module root (an executable's
root).

**Forced by Zig, build wiring only: the test step is split.** A Zig test build collects the tests of its root
module's files only, never an imported module's (measured in a scratch experiment before the move). With one test
root, as on `main`, the core's and operations' tests would silently stop running. So `zig build test` has one run
step per folder (`core`, `operations`, `interfaces`, `tests`) beside the unchanged `fastmem` step, and each module
root names its folder's files in `comptime { if (@import("builtin").is_test) { _ = name; ... } }`: compiled in a test
build only, and no test of its own (an unnamed `test {}` block would add one to the totals). The four steps add up
to `main`'s one engine step exactly (ruling 2).

### The checker

`scripts/check_layers.py` keys every file by its path under `zig/src/` (`core/engine.zig`, …) and adds
`MODULE_ROOTS` and the folders. It fails on any of these:

- a file directly in `zig/src/` or in an unknown folder;
- an assigned file outside its layer's folder, with the place FILES gives it named;
- a file in `tests/` that is not a test, benchmark or tool;
- a `.zig` path import that leaves the importing file's folder (another layer is reached through its module);
- a module imported from a folder below it (`core` by operations, interfaces and tests; `operations` by interfaces
  and tests; `interfaces` by tests only), with a test or benchmark in a layer's folder held to that layer;
- `@import("core").name` naming no `pub const` of the root;
- a layer file importing a test through a module;
- a module root imported by path;
- a test or benchmark in `tests/` that reaches one layer only (it belongs beside its subject).
