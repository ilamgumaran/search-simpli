# S2-T1 · `ss_import_json` accepts the Unicode analyzer

**State:** ready · **Series:** S2, the Luxir learnings (`docs/research/2026-10-luxir-learnings.md`, learning 1) · **Depends on:** S1-T8 · **Size:** M · **Builder:** Opus · **Tester:** Opus (a different instance)

The family app publishes its library through `ss_import_json`, whose contract
pins `ascii-alnum-v1` (`zig/src/importer.zig:13`, `:51`;
`contracts/snapshot-interchange.schema.json:10`). Measured: the Tamil fixture
published that way has **0 terms** and scores success@1 **0.00**; `café` is
indexed as `caf`. `analyzer-v2` (S1-T1, Tamil 10/10) never reaches the app.
This is a correctness gap in the shipped product, not an optimisation.

## Acceptance criteria
1. `ss_import_json` (and `searchd import-json`) accept `"analyzer_id":
   "analyzer-v2"` and tokenize the documents with `analyzer_v2`, building and
   recording the index exactly as `indexer.indexFolder` does for that analyzer
   (`zig/src/indexer.zig:267-298`). `ascii-alnum-v1` stays accepted and
   unchanged. Any other value is still rejected with the existing error.
2. The schema's `analyzer_id` becomes an `enum` of the two values;
   `contracts/CONTRACTS_VERSION` goes 1.0.0 → **1.1.0** (additive); the C
   header's doc comment and `docs/` name the second value; the Dart
   `SnapshotInterchangeV1` type gains the field with both values, and the Dart
   `contracts_version` test and `ss_version()` agree on 1.1.0.
3. **Bar (a):** the Tamil fixture published through `import-json` with
   `analyzer-v2` scores success@1 **1.00** (it is 0.00 today; paste both runs).
4. **Bar (b):** for every judged fixture under `fixtures/` and the chunk and
   BM25 goldens, the full ranked list (path, lines, score to 1e-6) through
   `import-json` + `analyzer-v2` is **identical** to `searchd index` with
   `analyzer-v2` on the same chunks.
5. **Bar (c):** `ascii-alnum-v1` imports are **byte-identical** to today's on
   the existing goldens; `zig build test-abi` 12/12 unchanged; the Python
   export path (`export_zig.py`) still validates against the schema.
6. **Plants:** the Tamil test fails on `origin/main`'s importer; the schema
   test fails with `const` restored; the Dart version test fails with 1.0.0.
7. All five suites green after the Report, run with `SEARCH_SIMPLI_LIBRARY_PATH`
   unset; `tool/build_native.sh` run last so the libraries and
   `native/SOURCE-SHA256` match the source (the digest covers
   `contracts/CONTRACTS_VERSION`).

### Things a tester should know

- **analyzer-v2 still splits Tamil at vowel signs and virama** (documented
  in `analyzer_v2.zig`), so a one-word Tamil query matches many passages
  through shared fragments. `யானை` returns 9 of 10 passages, with the right
  one first. Rank 1 is right on all 10 judged queries, but the tail is
  noisy. This is the same on both doors and is not changed here. Research
  learning 5 covers it.
- `zig build test` prints a `failed command: …` line on stderr even when it
  reports N/N passed. This happens because tests write to stderr through
  `std.debug.print`. It is not a failure.

### What the app must change (for the app's orchestrator)

1. Send `"analyzer_id": "analyzer-v2"` in the interchange JSON it passes to
   `ss_import_json`.
   - Today the app's `SnapshotInterchangeV1`
     (`packages/vizhi_core/lib/src/search/contracts/snapshot_interchange.dart`)
