## Problem

S1-T18 names the first file carrying the highest generation. Its advice, “delete or rename that file to publish here,” is insufficient when multiple traces carry `u64` max. A user can follow the advice and still be blocked by another trace. Complete the diagnostics while preserving the generation-allocation and publication rules.

## Acceptance criteria

1. At an exhausted highest generation, the single-line `NoFreeGeneration` diagnostic lists **every** matching trace among `MANIFEST`, `INDEX-STATE.json`, canonical `documents-N.hybseg`, and canonical `lexical-N.hyblex`, exactly once in that fixed order. Include the numeric generation and file names only. Lower-generation traces, malformed aliases, directories and caller paths are excluded. A single trace remains named; no stale files carry across calls or threads. An overflow after a taken candidate accounts for both taken section files.
2. The CLI and `ss_index_folder`/`ss_last_error` expose the complete list through their existing error channel and buffers, with CLI exit 1 and empty stdout. Give reliable, non-destructive guidance: a fresh output directory is usable; resolving the listed traces needs inspection. Remove the single-file deletion/rename promise. The failed call must leave every original snapshot file byte-identical. No automatic deletion, generation-rule change, contract bump, or query-output change. Update `docs/generation-lifecycle.md` to the actual behavior.
3. Independent regression checks cover the single-file case, all four max traces, tied subsets, lower/noncanonical exclusions, repeated-call reset and thread isolation. Exercise a real CLI and C ABI caller; verify a fresh output directory succeeds and the old snapshot is unchanged after the error. Restore the parent diagnostic in an isolated scratch copy with fresh Zig caches: the new checks must fail on that parent. Do not weaken existing assertions.
4. Rebuild packaged libraries last with pinned Zig 0.16.0 and verified NDK r28c, record sizes/hashes/stamp, and retain contract 1.2.0. Run the original Zig engine, C ABI, Python and Dart checks plus relevant regression checks and the relevance smoke. Report exact executed/passed/failed/skipped/unrun outcomes. Run requirements, path and documentation checks after writing the Report. Verify actual GitHub CI on the published branch.

## Rulings

- This is a repair to existing diagnostics and guidance, without a new retrieval capability or contract; no capability approval is needed.
- `lifecycle.sectionGeneration` already excludes leading-zero and malformed names. Preserve that definition.
- Use bounded, thread-local metadata for the four canonical trace kinds; avoid a second filesystem scan, extra allocation or query-path changes. Keep list order independent of directory iteration order.
- Runtime source ownership is `zig/src/generation_alloc.zig`; CLI/ABI already share its formatter. Extend existing tests at those boundaries rather than adding a competing error channel. Root reviews the implementation before final verification.
- PR #8 remains unchanged and unmerged. The new branch includes its verified Linux fix so native validation can run here.
