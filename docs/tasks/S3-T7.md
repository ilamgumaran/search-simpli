**Deviations from the task and section 12.**
1. The runner lives at the repository root (`relevance_smoke.py`; CI and `tests/test_relevance_smoke.py` use that path), so `scripts/relevance_smoke.py` is a 15-line wrapper that forwards to it. The diff scope names `scripts/relevance_smoke.py`; the real code change is in the root file.
2. The known miss is a one-word-per-line chant straddling a window edge, not a phrase across a heading: a heading's own words sit between the two halves in the token stream, so such a phrase does not exist for any engine. The window-edge case is the real chunk-local loss (the 3-line overlap saves phrases up to four lines long; five lines escape it). It lives in a `.txt` file so it is chunked by `line-window-v1` under any S3 chunker.
3. `read_span` and phrase/prefix/outline cases are all skipped by the runner for now (the task allowed this); `read_span` was not faked against the generator's own computation.
4. Added files beyond the diff scope list: `generate.py`, `content.py`, `README.md` inside `fixtures/family-folder/`. Lifecycle scenarios 11-13 carry step lists (apply_changes reports, find results) with files created by the step itself; they are not run until S3-T3/T4.
5. Spans for `read_span` avoid line 1 of the BOM file because a BOM is not part of a line; the convention is written in the README and judgments. Scenario 1 (words) expects lines holding both words on one line.
