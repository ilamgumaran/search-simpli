### The failure: Ruling 2, the `read_span` sha256 convention
The five `read_span` sha256 values hash lines `start_line..end_line` **without the last line's line terminator** (`generate.py` `Corpus.span_sha`; README and `judgments.json` `conventions.read_span` say so). Hashed from the original bytes with the line terminators included, as the orchestrator's check asks (inclusive 1-based ranges, BOM stripped), four of the five do not match:

| id | Range | Frozen value (terminator excluded) | Terminator included |
| --- | --- | --- | --- |
| s1 `school/science-notes.md` | 40-60 | 574 B `6892686a…` | 575 B `7813c9fac9e2ca4e513c8f122bc0d7798767595b84537914b169bb6867ead5c4` |
| s2 `home/crlf-shopping.md` | 3-8 | 63 B `56a41ea5…` | 65 B `290fd8e9a18f38f5abe08e022543951f51c576c3dc5b87199303745ed639cd8d` |
| s3 `home/bom-checklist.md` | 3-6 | 28 B `63fcd8d5…` | 29 B `2f7f13fd0ab5dcbf46b025e9193f051117521428142cac14eecee5508ba73afd` |
| s4 `home/no-final-newline.txt` | 3-4 | 39 B `70209e0b…` | 39 B, the same (no terminator) |
| s5 `laptop/big-log.txt` | 9000-9010 | 818 B `b835e5f8…` | 819 B `af31d1c35b14a2bd06da273348f7401a8459f66c81514ffb78cb7d091ff3801f` |

Why this blocks a frozen oracle rather than being a convention to note: FR-22 asks for exact lines "byte-exact with retained original source text, including line endings"; §4's line map stores each line start "then the end offset", so the natural slice of lines `a..b` ends at the start of line `b+1`, terminator included; and CAP-19's blocking review case lists "missing final newline" among the exact-span cases, which only means something if a span normally ends with its terminator (under the frozen convention s4 hashes the same whether or not the file ends in `\n`). S3-T1 would build `read_span` to the requirement and fail this pack, or build to the pack against the requirement. The Report does not list the convention among its deviations (deviation 5 covers the BOM only), so it never reached a ruling. Not a change a verifier may make: it changes `generate.py`, `judgments.json` and the test.

**Round 2 needs:** `span_sha` slices to the end of `end_line` including its `\n`/`\r\n` (unchanged when the file ends without one); the `conventions.read_span` and README sentence say so; `test_sha256_matches_files` computes the same; regenerate. Expected values are the right-hand column above. Everything else below was verified and need not change; a round-2 verifier re-runs the generator diff, the sha check and the suites.
