## Source

Measured on `main` at `efbdd0e`: the index of the 10,000-file timing corpus is 32,281,645 B for 7,269,199 B of text, 4.44 times the corpus; the text is held twice (`documents` 9.27 MB, `source` 8.28 MB) and the lexical section is 12.49 MB. The objective asks for an index that is efficient in disk use as well as in reads and writes. This task finds out where the bytes go on realistic text and what each remedy would save and cost. **It changes no format and no engine source.**

## Rulings

1. **Corpora**, all generated from invented text by scripts you commit (the corpora themselves are not committed): (a) the timing corpus at 1,000 and 10,000 files; (b) ordinary English prose with a natural (Zipf-like) word distribution, a few thousand distinct words, markdown notes of mixed length, 1,000 and 10,000 files; (c) Tamil prose by the existing `scripts/gen_tamil_timing_corpus.py`; (d) the repository's own fixtures. State each corpus's bytes, files, chunks, distinct terms and postings.
2. **The byte budget.** For each corpus, with and without the file-name channel: bytes per section file, and inside each section the bytes per part (for `lexical`: dictionary, postings, positions, tables; for `documents`: chunk text, ids, citations, labels, vectors if any; for `source`: text, line maps; `state`; the file-name pair), read from the format documents and confirmed by a measuring tool (a script over the files, or a `_bench`-style Zig program outside the digest). The parts of each file must sum to its size.
3. **Duplication.** How many bytes of text are stored more than once (chunk text against source text, chunk overlap, state against documents), measured, not estimated.
4. **Candidates**, each with measured or prototype-measured savings on corpora (a)–(c) and a stated cost; a prototype may be a script that re-encodes the existing section bytes, it need not be an engine change:
   - chunk records refer to spans of the source section instead of carrying text;
   - the source section stored once but block-compressed (say which codec is available without a dependency, and what a small in-tree codec would cost in binary size);
   - tighter position and posting coding; positions optional per index, with what `find` phrases and the title field lose without them;
   - the state section: what in it repeats what other sections hold;
   - generations retained on disk: what `keep_generations` does to total directory size during normal updates, and what the app's setting is by default in the binding;
   - anything else the budget shows.
   For each: bytes saved per corpus; which readers must change; expected effect on open time, warm query, `read_span`, `find` and one-file update (reasoned from the code, with a measurement where a prototype allows); whether old indexes stay readable; the size cost to the libraries.
5. **Recommendation.** An ordered list of format changes for D2, a target ratio per corpus with the evidence for it, and what must be decided by a ruling before D2 is filed. Written as `docs/index-size.md`, with the raw tables under `docs/evidence/s6-t3/`.
6. **No change under `zig/src/` apart from a new `*_bench.zig` if you need one** (benchmarks are outside the digest; confirm the digest is unchanged at the end). No contract, binding or format-document change.
7. **Suites and CI.** Python with and without Zig; the home-path check; CI green on the final commit.
8. **Documents.** `docs/index-size.md`; `PROJECT-STATE.md`; a 03-next row per recommended change. **Do not edit `README.md`, `CONTRIBUTING.md` or `docs/layers.md`** (S6-T1 owns them). `IMPROVEMENT-BOARD.md` is not edited.

**What was added.**

- `scripts/index_size_budget.py`:

  - `duplication` locates every chunk's text in its file's bytes through the line map;
  - `candidates` re-encodes the existing section bytes for each remedy; both text-once prototypes are decoded back
    and compared byte for byte, and every rebuilt file is checked against its SHA-256;

- `scripts/prototypes/s6t3/`: Zig probes for deflate, an in-tree LZ4-style codec and C2b posting decode, with
