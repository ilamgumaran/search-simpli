# S6-T21: a caller's own generation number at or below the current one is refused

**State:** filed by the orchestrator, 21 Nov 2026, from `main` after the S6-T20 merge · **Depends on:** [S6-T20](S6-T20.md) (its Verdict's finding 2 and item (a)), [S6-T17](S6-T17.md) · **Plan:** [objective plan](../plans/2026-11-16-objective-plan.md), section B follow-ups and the lifecycle

## Why

After [S6-T20](S6-T20.md) a writer that numbers itself can no longer publish a
number twice or move `MANIFEST` back. A writer that **brings** its number still
can. S6-T20's verifier showed, with real processes, on `main` before and after:

- `searchd index --generation 5` (or an import numbered 5) over generation 9
  publishes 5 and moves `MANIFEST` from 9 to 5;
- `import-json` numbered current + 1, stopped before its lock while two
  rebuilds with `keep_generations = 1` run, publishes 10 again and moves
  `MANIFEST` from 11 to 10.

A number whose section files exist is already refused (`PathAlreadyExists`).
The maintainer decided on 21 Nov 2026: **refuse a caller's number at or below
the current generation, as a documented new refusal**, in its own task.

## What

### Part 1: the design note (commit it first, before any code)

`docs/decisions/0004-callers-generation-number.md`, short, from reading the
code, with file and line:

1. Every input through which a caller supplies a generation number (the CLI's
   `--generation`, `import-json`, `ss_import_json`, the Dart binding, the
   Python reference, `init-demo`, any other), and where each number is used.
2. Where the check goes. The orchestrator's reading, to confirm or correct:
   under the writer lease, immediately before the publish, compare with the
   current `MANIFEST` generation read inside the lease (and with the highest
   generation on disk, if a lost `MANIFEST` makes the two differ: say which
   rule is right and why).
3. The refusal: which error. Use one that exists on every interface if it
   fits honestly; otherwise name the new one and list every file a new error
   touches (`contracts/`, `zig/include/`, the Dart and Python mappings, the
   error documents). Say what the caller sees on the CLI, the C API and Dart.
4. Who is affected: every test, script, fixture, example or document in this
   repository that passes a number at or below the current one today (search
   for them; `init-demo` and the Python reference included), and what each
   must become.
5. The version consequence: contracts and Dart version steps under the
   repository's versioning rule, and whether the app (which pins this
   engine) passes a number anywhere (read the app's use of the binding from
   the Dart package's public API only; do not open the app repository).

**Stop after the note and report.** The orchestrator reads it before the
build, because a new error is a contract change.

### Part 2: the change (only after the orchestrator says go)

1. The check, under the lease, for every path in note item 1.
2. Tests: the verifier's two cases above as tests (each fails on `main`,
   shown in evidence, and passes on the head); a number above the current one
   that is free still publishes; nothing on disk changes when the refusal
   fires.
3. Documents: `docs/generation-lifecycle.md` (the "can go backwards" sentences
   become what is now true), the error documents, `PROJECT-STATE.md`,
   `docs/journey/03-next.md`, the Dart CHANGELOG and version.

## Rulings

1. **For writers that honour `WRITER.LOCK`, `MANIFEST` never goes backwards
   and no number is published twice, whoever chose the number.** Shown by
   tests; the Report says which interleavings are tested and which argued.
2. **The refusal is documented on every interface** it can reach, in the same
   commit as the code.
3. **Answers and the read path do not change.**
4. **Natives are rebuilt and restamped** in the same commit as any change to
   `SOURCE-SHA256`'s inputs, sizes in bytes against `main`'s. Say what the
   timing rule of 2026-11-17 requires for a writer-only change and do that;
   tell the orchestrator before taking timing (the machine is not kept awake).
5. **The same tests run,** plus the new ones; both S6-T15 guards pass; counts
   before and after.
6. **Stop before:** changing the lock or how it is taken; pruning; what a
   self-numbering writer does; any format change.

## Notes for the builder
