## Rulings
1. **Roots** as §1 `meta.roots` and §5: `root_id`, `label`, `kind`, `required_labels`, `retain_source`, `origin`; root-qualified paths `root_id/relative`; a root added, re-indexed or removed (`remove_root`) without touching another root's chunks; v1 state loads as `r-legacy`.
2. **`apply_changes`** in the core (`zig/src/apply.zig`, new) exactly as §6: ops `add | change | remove | move | pending | remove_root`; exactly one of strict `content_base64` (valid UTF-8 after an optional BOM, ≤ `max_file_bytes`) or `file` (absolute, under a declared `local` root, no symlinks, allowed only when opened with file reads enabled); sha256 computed by the engine and verified when supplied; batch caps (10,000 changes, `max_total_bytes` decoded); `expect_generation` checked before any work; per-path ordering with `conflicts` reported; rename detection by hash with deterministic pairing and `ambiguous_moves`; `pending` replaces a file's chunks with none and lists it by name; the report fields of §6. One writer (`WRITER.LOCK`); publication through the existing atomic path with the manifest binding documents, lexical and source sections; `INDEX-STATE.json` v2 written after the manifest. `index_folder` is rewritten as a walk that builds a change batch (one `local` root, `file` changes) so one path writes generations; its report keeps every existing field.
3. **Visible-scope statistics** as §7: scope = roots named ∩ labels (root labels add to document labels), applied before candidate generation in every operation; BM25 document count, average length and document frequency over the visible scope (per-root precomputed; per distinct label set within a root, ≤ 64 sets, else exact counting at query time); prefix expansion over visible terms only (hook for S3-T2's dictionary); `index_status`, `list_sources`, `list_files` count visible files only.
4. **Tests.** Zig: two roots indexed and queried together and apart; `remove_root` leaves no term, count or state; two label domains inside one root: the hidden domain's documents, terms (a term that occurs only in hidden documents does not expand and does not change idf), counts and `index_status` are indistinguishable from absent, asserted on every operation's payload; forged `principal_labels` in a host-fed request are rejected (the scope comes from the trusted caller side); `apply_changes`: add/change/remove/move/pending/remove_root each one call; content hash mismatch rejected; `file` outside the root, a symlink, a `..` path, a NUL in a path each rejected with nothing published; a batch over the caps rejected whole; a stale `expect_generation` rejected with the current generation named; duplicate and conflicting changes in one batch (`conflicts`); two removed files with equal hashes and one added (`ambiguous_moves`, deterministic pairing); `pending` over an indexed file removes its chunks; crash recovery: a simulated failure between the manifest publish and the state write leaves a readable generation and the next call reports `unchanged` correctly (`docs/publication-recovery.md`). Python reference: the same semantics for the judgment pack.
5. **Measured in the Report (§13 profile):** full index of the 10k corpus through `apply_changes` (NFR-12: ≤ 3 s, ≤ 300 MB peak); one changed file in a 10k index (≤ 200 ms); hidden-versus-absent query timing for the same query over the fixture, 200 samples, p50/p95 of both, disclosed (not promised equal).
6. **Diff scope.** `zig/src/indexer.zig`, `incremental_state.zig` (v2), `apply.zig` (new), `manifest.zig` (roots in meta), `authorization`-related filtering in `query.zig`/`service.zig`, `scoring.zig` (statistics source), the Python reference, `docs/incremental-indexing.md` (v2 state and `apply_changes`), `docs/authorization.md` (visible-scope statistics; the timing disclosure), `PROJECT-STATE.md`, `docs/folder-knowledge-implementation.md` if amended. No ABI/RPC change (S3-T4).
