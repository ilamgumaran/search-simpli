## Source

After step 1 the 10k timing index is 3.41 times its corpus. The text of every file is stored twice: in the chunk records (`documents-N.hybseg`) and in the source section (`source-N.hybsrc`). [`docs/index-size.md`](../index-size.md) § A′ and its rulings 1 and 5 settle the design: the chunk text stays where queries read it; the source section keeps only the bytes no chunk holds, and `read_span`/`outline` rebuild a file from its chunks and gaps and check its SHA-256; records are coded compactly (ids as raw bytes, varint fields), and each path is stored once, in the source section's file table, other sections referring to a file by its ordinal. Measured by the S6-T3 prototype on the 10k corpora: source −7,159,445 B and record coding −1,217,773 B (timing); −17,018,295 B and −1,365,133 B (prose).

#### 1. The format, in ten lines

1. **Documents section.** `HYBSEG01` record **v5**, with a 56-byte header (counts, file count, file-table bytes,
   records bytes, decoded path bytes, XXH3-64 required) and two areas.
2. **File table.** One entry per file (with a chunk or retained bytes), in strictly increasing path order. The path
   is front-coded (shared ≤ 255, lexical v3's order rule), followed by `(chunk_count << 1) | retained`. Each path is
   stored once here.
3. **Records.** One per chunk in file order. A flags varint, then the id as 10 raw bytes (or inline when not
   20-hex), then varints: text length, start, span, chunker, depth, heading back, section path length. Then optional
   labels and vector, the text, and the section path. Path and `source_doc_index` come from the table.
4. **Source section.** `HYBSRC02` v2 has no paths. Record *r* belongs to the table's *r*-th retained file. Each
   record holds the SHA-256, flags (BOM, kept whole), the u64-varint length, the line count, and, unless kept
   whole, the chunk count plus one recipe varint per chunk.
5. **Recipe.** An even value is a gap of v/2 residual bytes followed by the whole chunk. An odd value is an overlap
   of k = (v+1)/2 with bytes already emitted, so only `chunk[k..]` is emitted, or nothing when the chunk is contained.
   The file's residual tail comes last.
6. **Areas.** The line maps are v1's, byte for byte. The residual area holds each file's gaps and tail, or all its
   bytes when kept whole, in record order and gap-free. Every offset is derived by walking.
7. **Kept whole.** A file is kept whole when it has no chunk, or when some chunk is not an exact span. Every
   multi-line chunk of a CR LF, CR or other non-LF file is such a chunk, because the chunkers join lines with `\n`.
8. **Validation.** The order is header, then checksum, then bounds before allocation, then the walk. Each area has
   its own "no byte left over" rule (table, records, source records, maps). The residual runs must sum exactly. The
   retained count must equal the source file count. A file with zero chunks must be retained or kept whole.
9. **Reads.** The SHA-256 of a rebuilt file is checked at every `read_span` and `outline`, and a mismatch returns
   today's `re-index required: source section unavailable (SourceFileSha256Mismatch)`. The line map is checked
   against the rebuilt bytes at the first read per handle.
10. **Manifest v2.4.** Flag bit 6 `text_once` (`0x40`) is set exactly when the generation uses v5 and v2. An old
    library refuses it with `UnsupportedFlags` before reading any section. A new library still reads v1–v4 and
    `HYBSRC01`.

#### 4. Old library with a new index, new library with an old one

- **Expected:** not slower, likely faster by the write volume.

#### 7. Open questions for the ruling (each with my recommendation)

1. **Where the file table lives.** Ruling 5 puts it in the source section; this document puts it in the documents
   section. With ruling 5:
   - generations whose roots are all `local` (not retained by default) would need a source section anyway, and
     `has_source` would change meaning;
   - the open would have to read and check the source section, which is lazy today;
   - a damaged source would fail every query instead of only `read_span`/`outline`.

   The bytes are equal: the table moves, and 16 header bytes move with it. **Recommend: the documents section.**
2. **Ordinals in the state section, the catalog and the meta lists: now or in D2 step 4?** § 2 has the design. Each is
   a format change of its own (the catalog becomes derivable, the state gains an ordinal field). Each adds
   compatibility work to this step. **Recommend: step 4.**

   In this step the one cross-section reference is the source's binding by order. The "ordinal off by one" plant
   (ruling 6) can target it: move the retained bit from one file to its neighbour. The count still agrees, and the
   SHA-256 or the chunk count catches it.
3. **CR LF and other non-LF files are kept whole.** That is 8 files in the six corpora. A CR LF corpus (written on
   Windows) would keep its text twice, as today. **Recommend: accept now.** If a measured corpus needs it later, a
   per-file "lines joined by CR LF" flag can follow.
4. **A file's length is a u64 varint.** Every other varint is u32. A gap or overlap of 2 GiB or more makes the file
   kept whole. **Recommend: as written** (no byte cost; v1 allowed u64 lengths).
5. **Overlong varints are accepted.** This matches `postings.readVarint` and lexical v3. **Recommend: accept**, with
   no writer emitting one.
6. **The chunk count in each source record** costs 1 byte per file (10,000 B on 10k) and duplicates the table's. It
   gives a structural refusal before the SHA-256 when the binding is off. **Recommend: keep.**
7. **Section identity.** The documents section keeps magic `HYBSEG01` as version 5 (`segment.inspect` already
   dispatches versions 1–4). The source gets a new magic `HYBSRC02`, as `HYBLEX03` and `HYBSTA02` did.
   **Recommend: as written.**
8. **The document's name.** `docs/source-and-documents-format-v1.md` covers both sections, because they are now one
   format bound together. **Recommend:** keep it, and in Phase 2 add a pointer from `segment-format-v4.md` and
   `source-section-v1.md`.
9. **A record v5 cannot code** (empty path, line 0: `import-json`'s uncited form). The folder writer never makes
   one. **Recommend:** the publish fails before writing if it ever does, with no fallback to v4.
10. **The residual area is streamed** like v1's text, not resident. It is small in these corpora, but a corpus with
    many kept-whole files would make it large. **Recommend: streamed.**

#### 8. Not verified, and limits

- **No engine code exists yet.** Every timing is in memory: no file I/O, the open's read and the streamed checksum
  excluded on both sides. The I/O effects in § 5 are byte counts, not times.
- **One-file update and first publish** are estimates.
- **The prototype writes each section's checksum as zero.** Python has no XXH3, so its decoder skips that one check.
  The probe computes XXH3 over the bytes for the timing only.
- **The old-library refusal was run through the CLI only.** The C ABI and Dart were not run; they share
  `manifest.decodeV2` (from the code).
- **Some breaks never appeared.** No VT, FF, FS, GS, RS, NEL, LS or PS line break occurs in the six corpora. The
  kept-whole rule for them comes from the chunkers' code (`"\n".join(lines).strip()`), not from a measured file.
- **The self-test ran on J2 and family.** Its byte-level patches assume one-byte fields there. On fixtures one patch
  overflowed a byte, and prose has no zero-chunk file. Neither is a decoder failure.
- **Not exercised:** files over 4 GiB, and paths sharing more than 255 bytes.
- **The ruling-5 placement was not encoded separately.** Its bytes are derived (the same table, ±16 header bytes).
