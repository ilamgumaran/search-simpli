## Source

After step 1 the 10k timing index is 3.41 times its corpus. The text of every file is stored twice: in the chunk records (`documents-N.hybseg`) and in the source section (`source-N.hybsrc`). [`docs/index-size.md`](../index-size.md) § A′ and its rulings 1 and 5 settle the design: the chunk text stays where queries read it; the source section keeps only the bytes no chunk holds, and `read_span`/`outline` rebuild a file from its chunks and gaps and check its SHA-256; records are coded compactly (ids as raw bytes, varint fields), and each path is stored once, in the source section's file table, other sections referring to a file by its ordinal. Measured by the S6-T3 prototype on the 10k corpora: source −7,159,445 B and record coding −1,217,773 B (timing); −17,018,295 B and −1,365,133 B (prose).

## Rulings

1. **Phase 1: the format document and a prototype, no engine code.** `docs/source-and-documents-format-vN.md` (name it by the repository's convention), written so a reader can implement a decoder from it alone: both sections' new layouts byte for byte, the manifest version and flag, every validity rule a reader enforces (bounds, ordering, "no byte left over", ordinals in range, the SHA-256 check and when it runs), how a file is rebuilt from chunks and gaps including overlapping chunks, chunks that are not exact spans of the file (kept whole, per § A′), empty files, files with no chunk, and CR LF or missing final newline. A prototype in `scripts/prototypes/s6t7/` that re-encodes the six corpora S6-T4 used and reports bytes per section, rebuilds every file and compares it with the original, and estimates open time and memory. Report: the inventory of every reader and writer of the two sections (with which sections refer to a path today and how each would refer to an ordinal); the numbers against S6-T3's; the list of what an old reader does with the new index and a new reader with the old; open questions. **Stop for rulings.**
2. **One format version, with the previous reader kept.** The new library opens an index written by `main` at `a534678` and answers identically; it writes the new format at the first publish (as step 1 did, in one generation, the old generation left whole until the manifest is replaced). An older library refuses the new index with a clear error and does not crash or modify it. The migration note goes in the Dart CHANGELOG and the 03-next pin row. Contracts and the C header do not change; if you find they must, stop at the Phase 1 Report.
3. **Same answers.** Every surface (CLI, JSON-RPC, MCP, `ss_query`, `find`, `read_span`, `outline`, `list_files`, `search`) is byte-identical to `main` on J2, the fixtures, the family fixture and the three 10k corpora, on a fresh index and on an old-format index updated once. `read_span` over every file, whole and in ranges that cross chunk boundaries and gaps, returns the file's exact bytes.
4. **Bars (Phase 2).** Size: the source and documents sections within 3 % of the Phase 1 prototype's figures on each corpus; the index-size table re-measured. Open time and memory after open: not above `main`. One-file update and first publish from the old format: reported, with the Phase 1 Report stating the expected change before measuring. `read_span` and `outline` now rebuild: measure them on small, median and largest files of each corpus against `main`, state the expected cost before measuring; they are changed paths. Query and `find` timing by the rule of 2026-11-17 in [ROLES](../process/ROLES.md), five gated runs by the verifier (the builder takes two for information), controls sized to this task's compiled-code delta.
5. **Damage and crash.** Every validity rule in the format document has a test that violates it with the checksum recomputed, including each "last element" boundary and a leftover byte after each section's last element (S6-T4's two missed plants were of this kind). A rebuilt file whose SHA-256 does not match is refused with a clear error, never returned. A publish killed at any point leaves a whole old or whole new generation.
6. **Plants**, each in its own scratch copy and Zig cache, at least: a gap written one byte short; the SHA-256 check skipped; an overlapping chunk's overlap emitted twice on rebuild; a path ordinal off by one in another section; the old-format reader removed; a leftover byte accepted after the last gap.
7. **Natives, suites, CI, documents** as S6-T4: rebuild and stamp the three libraries, sizes and digest in the Report; Zig Debug and ReleaseSmall, C ABI, Python with and without Zig, Dart, J2 gate; layers, requirements and home-path checks; CI green on the final commit. Documents: the format document, `docs/index-size.md` (step 2's status and the measured table), README measured lines, `PROJECT-STATE.md`, 03-next (D2-2 done; the pin row carries both one-way notes), Dart CHANGELOG and patch version. `IMPROVEMENT-BOARD.md` is not edited.
8. **Layers.** The rebuild logic is core; no interface file learns the format. `scripts/check_layers.py` stays clean with no new allowed import.
