# S6-T17: a full rebuild does not fail when another writer publishes while it reads `MANIFEST`

**State:** filed by the orchestrator, 20 Nov 2026, from `main` at `4c84ee8` · **Depends on:** [S6-T13](S6-T13.md) (its fix for an open; this is the follow-up it left open) · **Plan:** [objective plan](../plans/2026-11-16-objective-plan.md), section G (correctness follow-ups)

## Why

[S6-T13](S6-T13.md) made an open read `MANIFEST` through one handle, so a
publish between the `stat` and the read cannot make the open fail. Its Report
and Verdict (finding 3) list the same pattern left in the writer: a full
rebuild (`ss_index_folder` without `update`; `searchd index` without `--update`
or `--generation`) calls `generation_alloc.nextFreeGeneration` **before** it
takes `WRITER.LOCK`. That reads `MANIFEST` in `generation_alloc.currentGeneration`
by one `stat` and then a read by name. If a second writer publishes in between,
this writer can fail with `Truncated` where it should go on to publish or to
`WriterBusy`. `incremental_state.readStateFile` runs in the same place; its
caller turns every error into `null`, so a race there can lose the
`INDEX-STATE.json` trace of the highest generation for that one call.

This was read from the code, not reproduced.

## What

1. **Reproduce first.** A test that fails on `main`: a `MANIFEST` replaced (by
   rename, as a publish does) with a longer and with a shorter one between the
   `stat` and the read in `currentGeneration`. Use the way S6-T13's tests did it
   (read its task file and tests first; reuse its seam if one fits). If it cannot
   be reproduced, stop and report: the task is then a document correction only.
2. **Fix `currentGeneration`** so the size and the bytes come from the same
   open file, as S6-T13 did for the open. Reuse the core's existing helper if
   one fits; do not add a second copy of the pattern.
3. **`readStateFile` before the lease.** Reproduce or rule out the lost trace
   (replace `INDEX-STATE.json` between its `stat` and read, and see whether
   `nextFreeGeneration` returns a number at or below one already used). Fix it
   the same way if it is real. State which it was.
4. **Report what remains**: after the fix, every `stat`-then-read-by-name site
   left in `zig/src` outside tests and benchmarks, each with why it is safe
   (under the lock, or the user's own file) or filed as a follow-up.

## Rulings

1. **Answers and formats unchanged.** No contract, C header, format or error
   name changes. The generation number a full rebuild chooses is the same as
   `main`'s in every case without a race.
2. **A race ends in one of two ways:** the writer goes on with a number above
   every generation on disk, or it returns `WriterBusy`. Never `Truncated`, and
   never a number already used.
3. **Natives.** Function bodies change, so the natives are rebuilt and
   restamped in the same commit, with sizes reported against `main`'s (macOS
   1,006,456 B, Android 966,800 B, iOS 971,424 B, `searchd` ReleaseSmall
   1,151,208 B). The changed code is on the writer's path only; say whether any
   open, search or find path's code changed. If none did, timing by the rule of
   2026-11-17 is not owed; if one did, it is, before a Verdict.
4. **`core.api`.** No new name in `core.api`; both guards of S6-T15 and the
   S6-T16 rule pass.
5. **Stop before:** changing when the lock is taken (moving `nextFreeGeneration`
   under the lease is a design change; describe it as an option if the fix above
   is not enough, do not make it); a contract, header, format or answer change.
