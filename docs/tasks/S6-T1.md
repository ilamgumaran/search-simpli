- **Reading.** Each file is read whole as Zig tokens: comments (`//`, `///`, `//!`), string and character literals, `@"…"` identifiers and `\\` multiline string lines are tokens of their own, so their text is never code. An `@import` is the builtin token followed by `(`, one string-literal token, an optional `,` and `)`, with any whitespace and newlines between; the line reported is the one where `@import` starts. The string's escapes are decoded (`\xNN`, `\u{…}`, `\n`, …): Zig 0.16.0 compiles `@import("other\x2ezig")` and `@import("other\u{2e}zig")` (scratch probe, `All 1 tests passed`). Any other operand is reported, not skipped: in the same probe Zig refuses `@import("oth" ++ "er.zig")`, `@import(p)` with `const p = "other.zig"`, and a `\\` multiline string, each with `error: @import operand must be a string literal`.
- **Resolving.** A `.zig` target is resolved against the importing file's real directory (`Path.resolve`) and taken relative to `zig/src/`. A target outside `zig/src/` fails ("which is outside zig/src/"), a target naming no file fails ("resolves to … : no such file"), an imported file that is not assigned fails at the import as well as at the file. Dot folders under `zig/src/` are no longer skipped.
