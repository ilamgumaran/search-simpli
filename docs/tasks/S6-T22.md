# S6-T22: a judged set for "the right file and the right passage" (plan step H1)

**State:** filed by the orchestrator, 22 Nov 2026, from `main` at `863869c` · **Plan:** [objective plan](../plans/2026-11-16-objective-plan.md), [the priority of 22 Nov 2026](../plans/2026-11-16-objective-plan.md#the-priority-set-by-the-maintainer-on-22-nov-2026), step H1

## Why

The maintainer's priority is text search done very well: find the files relevant
to a question and answer from the relevant parts. The existing judged sets score
ranking. None says whether the passage that answers a question came back. Steps
H2 to H6 need a number that moves when they help and when they hurt.

## What

1. **A corpus, generated, invented.** A script under `scripts/` writes a folder
   of plain-text files shaped like what a household and a small project keep:
   notes, lists, recipes, schedules, logs, tables as CSV and TSV, JSON and YAML
   data, markup, a little source code, plain files with no extension, long
   files and one-line files, two scripts at least (Latin and Tamil), near
   duplicates, and files whose name says more than their text. Deterministic
   from a seed; a few hundred files; invented names and facts only.
2. **Questions with judgments.** At least 120, in a contract-shaped JSON file,
   each with: the question as a person would type it; the query words a caller
   would send (when they differ); the files that must be found; the line ranges
   that hold the answer; and a kind. Kinds, each with at least eight questions:
   a word the file holds; a different form of the word; a misspelt word; an
   exact phrase; a number, date or code; a question whose answer spans two
   passages of one file; one that needs two files; a question about the file's
   name, not its text; "which files are about X"; "what is in this file";
   a question with no answer in the folder (the right result is nothing).
3. **A scorer.** A script that runs `searchd` (direct search and an index, both)
   over the corpus and reports, in total and per kind: was a required file in
   the top 1, 3 and 10; was a required line range inside a returned passage
   (top 1, 3, 10); for no-answer questions, how often something was returned
   anyway; and the size in bytes of the evidence handed over. Output is a JSON
   file and a Markdown table. Deterministic.
4. **The baseline.** Run it on `main`'s engine and commit the result under
   `docs/evidence/s6-t22/`. Write `docs/text-search-score.md`: what the set is,
   how to run it, the baseline table, and, kind by kind, what the engine cannot
   do today (stated from the numbers, no proposals beyond naming the plan step
   that addresses each).

## Rulings

1. **No engine change.** Nothing under `zig/src/`, `contracts/`, `zig/include/`
   or the bindings changes. Scripts, data, tests of the scripts, documents.
2. **The judgments are checked, not asserted.** A test verifies every judged
   line range exists in the generated corpus and holds the answer's key words.
   The Report says how the judgments were made and what share was read by eye.
3. **Honest kinds.** Questions the engine cannot answer today stay in the set
   and score zero; none is dropped or reworded to pass.
4. **Invented content only**, no home paths, deterministic output.
5. **The Python suite and the guards pass;** counts before and after.

### How the judgments were made, and what share was read by eye (ruling 2)

- I wrote every question and every planted file by hand, the answer line into the file first and the question
  after it; the filler (journal, shopping lists, meeting notes, logs, recipes, inventory rows) is drawn from fixed
  sentence pools I wrote, and holds no answer.
- Line numbers are computed, never typed: a range is an anchor text on exactly one line (or a line number for a
  file's head), and the generator refuses an anchor on zero or several lines.
- Checked by tests, not asserted: `test_every_range_exists_and_holds_its_keys` reads all 167 ranges back from a
  freshly generated folder with its own line splitter and finds every key word in each;
  `test_absent_words_are_absent` checks the `absent_from_corpus` words (misspelt and no-answer questions) and
  `absent_from_files` words (word-form and filename questions) as analyzer tokens;
  `test_file_is_what_the_questions_script_writes` keeps the committed file equal to the script's output. Planted
  faults make each fail ([`plants.txt`](../evidence/s6-t22/plants.txt)). The check found one wrong judgment of
  mine: none-08 named "panel" as absent, and a journal line says "the fence panel rattled"; the check now names
  "solar" only.
- **Read by eye: all of it.** I printed every question with the text of every resolved range (129 questions, all
  ranges) and read each once, before the baseline; and I read the engine's top results for every question that
  missed, came below rank 1 or answered a no-answer question (46 with `both`, 35 with
  `content`) against its judgment. None of the misses is a judgment error by that
  reading; each is stated in the document.
