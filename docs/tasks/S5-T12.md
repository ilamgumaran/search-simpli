## Source

`Engine.bothGroups` builds a visible-collection view before it knows whether any query word needs one. The queue records a warm `both` query with no triggering word (`bazecha`, 10k timing corpus) at about 0.053–0.059 → 0.085–0.090 ms, and a grouped frequent word (`system`) missing its `both` increment bound (+0.065 ms against +0.03). Both are earlier whole-query measurements. The eager view is seen in the source; that it causes the cost is a hypothesis until measured.

## Rulings

1. **Phase 1: measure before any change, and stop.** On current `main`'s engine, with the existing methodology (the 10k timing corpus, `ReleaseSmall`, interleaved rounds under the load gate, raw measurements kept under `docs/evidence/s5-t12/`): `bazecha`, `system`, `hashing` and a two-word question in both word orders, each under `content` and `both`, plus a build with the eager view skipped when no word triggers (a prototype, not shipped code) to attribute the cost. Report what reproduces. **If the `bazecha` overhead no longer reproduces, say so and build nothing for it.** The Phase 1 Report ends with a recommendation and the builder stops for a ruling.
2. **Phase 2, only what Phase 1 supports, one change at a time.** (a) The visible collection built lazily and at most once per query when grouping needs it, with a membership-only check first if that can establish no view is needed. (b) Separately, and only if Phase 1 shows it matters: `filename_field.zig`'s touched-chunk scoring for frequent groups. Each change is measured alone; the two are not mixed into one number.
3. **Nothing observable moves.** Groups, warnings, scores, ties and visibility are identical: every golden byte-identical, every J2 cell on both surfaces unchanged with the gate clean and no baseline re-record, the find and filename equivalence check of S5-T8 (same requests, 0 differ), and a hidden label's file neither searched nor named. No policy id, contract, Dart version or format changes.
4. **The acceptance rule.** The named overhead improves beyond the measured noise (a second build of the before sources gives the noise band), under the same methodology, with the before and after figures and their ranges stated. No query in the measured set gets slower beyond noise. The bounds of S5-T8's Phase 1 ruling 5 still hold. A change that does not meet this is not shipped, and its measurement is kept as a rejected attempt.
5. **Regression test.** A growth-ratio test in the style the repo already uses (ratio of `both` to `content` work, or of counted operations), not a wall-clock threshold. If a counter can show the view is not built when no word triggers, that is the test.
6. **Plants**, each in its own scratch copy with its own Zig cache: the eager build put back (the new test must fail); the lazy view built from the wrong scope (a visibility or golden test must fail).
7. **Natives.** Rebuilt with the documented toolchain and stamped; sizes, digest, `check_native.sh` and the freshness test. The Report says the app needs a pin to carry the change and names the numbers the pin task will need.
8. **Suites and CI.** Zig Debug and ReleaseSmall, C ABI, Python with and without Zig, Dart; the home-path check; CI green on the final commit.
9. **Documents.** The two 03-next rows closed or re-stated with what remains; `PROJECT-STATE.md`; `EXPERIMENTS.md`; R07 marked landed by the verifier. `IMPROVEMENT-BOARD.md` is not edited.
10. **Held-out judgment.** The verifier, not the builder, chooses three further queries (one with no triggering word, one grouped, one fuzzy-expanded) after reading the change, and measures them before and after.
