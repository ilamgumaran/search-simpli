## Source

The objective asks for an engine that can search local files directly, and builds an index only when the documents are many. Today every query needs a published index directory. This task adds the direct path to the CLI.

## Rulings

1. **Inventory first, in the Report, before code.** How `index` builds a generation and how `query`/`evidence` open and answer one; which steps touch the file system; whether the engine can be opened over sections held in memory today, and what the smallest change is that allows it.
2. **The command.** `searchd search <folder> "<query>" [--top-k N] [--json] [--evidence] [--search-field content|filename|both] [--max-file-bytes N] [--max-total-bytes N]`. It walks the folder by `index`'s rules (same extensions, same ignored directories, same analyzer default, same chunker), answers, and exits.
   - **Same answers.** For any folder and query, the results (order, scores, citations, matched terms, warnings, sections) are what `index <folder> --out X --filename-index` followed by `query X` / `query X --json` / `evidence X` with the same options return, apart from fields that name the index itself (generation, directory). A test proves this over the J2 corpus and the fixtures, on all three fields.
   - **Writes nothing in or beside the folder**, and leaves nothing behind anywhere. Preferred: the sections are built and opened in memory. Accepted if the inventory shows that needs more than a moderate, behaviour-neutral change to the core: a private directory under the system's temporary directory, created with owner-only permissions and removed on every exit path including errors; if you take this, say so plainly in the document and file a 03-next row for the in-memory path. A test asserts the folder's tree (names, sizes, modification times) is identical before and after, and that no temporary directory remains.
   - **Errors** are usage-class with one stderr line: missing folder, a file where a folder is expected, an empty query. An empty folder answers with no results and exit 0, as an empty index does.
   - No new C ABI function, no wire or schema change, no Dart change in this task. `index`, `query`, `evidence` and every other command are unchanged; a test over their existing outputs shows it.
3. **Any core change is behaviour-neutral for existing callers**: every existing Zig, C ABI, Python and Dart test passes unmodified, and the J2 gate on `searchd` is clean without re-recording.
4. **The crossover, measured.** On the timing corpus at 100, 1,000, 5,000 and 10,000 files (and one mid-size ordinary-prose folder you generate from invented text): wall time and peak memory of one `search`, against `index` once plus one `query`, and against one `query` on an existing index. `ReleaseSmall`, five runs each, medians and ranges, quiet machine (5-minute load below 4.0; say what the load was). The document states, from these numbers, the folder size up to which direct search answers within 100 ms and within 1 s on this machine, and tells the reader to build an index past that. No automatic caching in this task.
5. **Capability.** Draft `docs/requirements/cap-20-direct-folder-search.md` from the template and register it so the requirements validator passes. Its approval line reads: approved by the orchestrator under the maintainer's instruction of 16 Nov 2026 (see the plan); the maintainer may overrule. Do not mark it Validated; the verifier's Verdict decides what the status becomes.
6. **Plants**, each in its own scratch copy with its own Zig cache: the walk using a different ignore rule than `index` (the equivalence test must fail); a leftover file in the folder or temporary directory (the leaves-nothing test must fail); `--search-field` parsed but not applied (the field test must fail).

Contracts and the Dart version do not move unless a core change alters library bytes in a way a binding can observe; if you think they must, stop at the Report.
8. **Suites and CI.** Zig Debug and ReleaseSmall, C ABI, Python with and without Zig, Dart; the home-path check; CI green on the final commit, native J2 included.
