# S1-T3 · Incremental folder indexing in the core

**State:** ready (round B, alongside S1-T2) · **Depends on:** S1-T1 · **Size:** M · **Builder:** Sonnet 5 · **Tester:** Opus 5

## Acceptance criteria
1. `ss_index_folder(handle, path, opts)` and `searchd index --update`: content hashes per file, unchanged files skipped, deleted files tombstoned, new generation published atomically (existing publication/recovery path), report JSON (added/changed/removed/skipped/too-large).
2. Caps: per-file size cap and total cap from opts; unreadable files listed, never fatal.
3. Tests: a fixture folder mutated in five steps (add, edit, delete, rename, oversize) with the expected report and query results after each; recovery from a crash mid-publication proven with the existing scanner.
4. Timing on a 1,000-file folder: full vs second run with one change, pasted.
