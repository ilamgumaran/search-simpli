# S1-T15 · Zig's NFC is incomplete: singleton decompositions and Hangul

**State:** ready (2026-10-10) · **Series:** S1 · **Depends on:** S1-T14 · **Size:** S · **Builder:** Sonnet 5.5 · **Tester:** Opus 5.5

**From the S1-T14 Verdict, finding 1.** The Zig NFC (`zig/src/nfc.zig`, tables from `gen_unicode_tables.py`) skips singleton decompositions (a wrong comment at `gen_unicode_tables.py:112`) and does not recompose Hangul; S1-T14 made the Python reference normalize too, so Zig and Python now differ on 1,020 singleton codepoints (mostly CJK compatibility ideographs) and on all 11,172 Hangul syllables written decomposed. No fixture contains them; the app is unaffected today. Two more S1-T14 findings ride along: variation selectors now stay on a token (`1️⃣` → `1`+U+FE0F, so a query for `1` no longer finds it); the casefold gap known since S1-T1 (two cases in the tester's table).

## Rulings
- **NFC is made correct** (singletons, Hangul composition per UAX #15) in Zig, matching Python's `unicodedata.normalize("NFC")` on every codepoint and on the standard NormalizationTest cases that apply to NFC. The analyzer id **stays `analyzer-v2`** if every ASCII, Latin and Tamil golden and ranked list is byte-identical (the same test as S1-T14's ruling 2); if any moves, stop: `analyzer-v3` is the orchestrator's call.
- **Variation selectors (U+FE00–FE0F, U+E0100–E01EF) are dropped from tokens** (category Mn but semantically presentation only), so `1️⃣` tokenizes as `1`. Test both directions.
- The casefold gap: document it in `docs/cooccurrence-semantics.md` or the analyzer doc; fix only if it fits in the size; otherwise its own task.
