# S1-T4 · Round-C hardening (from the round-B verdicts)

**State:** ready (round C, alongside simpli-helper M12-T0) · **Depends on:** S1-T2, S1-T3 · **Size:** S · **Builder:** Sonnet 5 · **Tester:** Opus 5

## Acceptance criteria
1. Dart binding for `ss_index_folder` (`SearchSimpli.indexFolder(dir, path, opts)` returning a typed report) with a test on the Mac and in the example app's instrumentation test on the emulator (private storage).
2. macOS/Linux library loading is package-relative (resolved from the package root via `Isolate.resolvePackageUri` or the `native/` layout), so a path dependency works without `SEARCH_SIMPLI_LIBRARY_PATH`; the env var stays as an override; README install steps followed literally must pass.
3. Report JSON lists the paths of `unreadable` and `too_large` files; `skipped` split into `unchanged` and `budget_exhausted`; an empty folder or last-file deletion publishes an empty generation instead of `NoDocuments`; `lifecycle.scan` knows `INDEX-STATE.json`; a file grown past the cap is reported as `too_large` AND its old chunks tombstoned (never silently kept or lost); tests for each.
4. Docs: the four "API 37" labels corrected to API 34 (Android 14); `docs/incremental-indexing.md` rewritten to the shipped design; README full-rebuild figure re-measured; `gen_timing_corpus.py` dead code removed; the four schema-optional fields get Dart members.
5. All suites green (`zig build test`, `test-abi`, `lib`, Python, `dart test`), run after the Report; prebuilt libraries rebuilt and committed with sizes.

### Criterion 1 — `SearchSimpli.indexFolder`

Added as a **static method** on `SearchSimpli`
(`bindings/dart/search_simpli/lib/src/search_simpli_base.dart`), not an
instance method: it takes a directory path, not an open handle, the same
shape as `importSnapshotJson` and `ss_index_folder` itself — the S1-T3
tester's verdict (criterion 1) already accepted this shape for the same
reason. Signature: `SearchSimpli.indexFolder(String dirPath, String
folderPath, {IndexFolderOptions options = const IndexFolderOptions(),
DynamicLibrary? library}) -> IndexFolderReport`.

- Mac test: `bindings/dart/search_simpli/test/search_simpli_test.dart`,
  new group `SearchSimpli.indexFolder` — publishes a queryable generation
  and checks every report field; an empty folder publishes an empty
  generation (0 documents) instead of throwing; an `update: true` run
  reports an unreadable file by relative path; a folder that fails to index
  throws `SearchSimpliException`.
- Emulator instrumentation test:
  `example/integration_test/app_test.dart`, new test `SearchSimpli.indexFolder
  indexes and publishes into private storage` — writes a source file and
  calls `indexFolder` with the app's own `getApplicationSupportDirectory()`
  as both the source and output directory (the same directory
  `ss_import_json` used to fail on with `AccessDenied` before S1-T3's
  portable atomic publish fix), opens and queries the result, then runs a
  second `update: true` publish into the same directory and checks
  `generation: 2`/`unchanged: 1`. Run on the `vizhi-phone` emulator
  (Android 14, API 34) — both tests pass, tail below.

### Criterion 3 — report shape and tombstoning

Zig side inherited complete from the `wip` commit, with one gap found and
closed: the five-step fixture's "oversize" step only covers a file that is
**new and already oversized** (`huge.md`, never previously indexed), not
"grown past the cap" — the exact wording of the criterion. Added
`zig/src/incremental_indexing_test.zig`'s `"a file grown past max_file_bytes
is reported too_large and its old chunks are tombstoned"`: indexes a small
file normally, grows it past `max_file_bytes`, re-indexes, and checks
`too_large: 1`/`too_large_paths: ["grows.md"]`, `documents` dropping from 2
to 1, the old query no longer finding it, an unrelated second file
untouched (`unchanged: 1`), and that a third run does not silently re-admit
it. `docs/incremental-indexing.md`'s table already documented this policy;
now there is a test for the "grown past the cap" case specifically, not
only "born oversized".
