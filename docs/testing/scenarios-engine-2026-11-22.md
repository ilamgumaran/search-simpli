# Engine usage scenarios, 22 Nov 2026

Status: **observed**. One independent usage run of `searchd` at `main` `87bfd35`, built
`ReleaseSmall` as the README says, on macOS arm64 (18 cores) while other agents ran builds
and tests on the same machine. Nothing in the product was changed. Every name, place and
number in the test folder is invented.

What was tested: the everyday things a person at a terminal, a calling program (JSON-RPC,
MCP, the Dart binding) or an LLM host does with a folder of household and small-project
text, followed from the documents as a newcomer would (README, CONTRIBUTING,
`docs/direct-search.md`, `docs/incremental-indexing.md`, `docs/mcp-server.md`,
`docs/zig-rpc-service.md`, `docs/generation-lifecycle.md`, `searchd --help`).

## How to repeat it

```sh
# from the repository root, Zig 0.16.0 on PATH (and `dart` on PATH for B01-B02)
sh docs/testing/scenarios-engine/run.sh <new-scratch-folder>          # about 40 s
sh docs/testing/scenarios-engine/run.sh <new-scratch-folder> --skip-scale --skip-dart
```

`run.sh` builds `searchd` and runs `run_scenarios.py`, which writes the test folder with
`gen_corpus.py`, runs every scenario, judges it with the check written beside it, and
writes `results.md` (the table below) and `results.json` into the scratch folder.
`http_probe.py` drives `serve --http`; `mcp_probe.py` is an MCP host session;
`dart_probe/` is a calling program on the Dart binding. The only writes outside the
scratch folder are the README quick start's own `.search/demo` and `.search/index.json`
(ignored by git).

**The test folder** (`gen_corpus.py`): 36 files and 3 links. Notes, lists, recipes
(English and Tamil), a `.log`, a `.csv`, `.json`, `.yaml`, HTML, CSS, Python, C, TOML, a
`README` and a `Makefile` with no extension, a Tamil file name, names with spaces, an em
dash and an accent, an upper-case `.TXT`, a CRLF file, a BOM file, an empty file, a
22 KB one-line file, a 5,000-line diary, binary bytes behind `.txt`, an 11 MiB file (over
the 10 MiB default cap), a dot-folder, `node_modules`, a link to a file, a link to a
folder and a dangling link, nested six folders deep. The scale folder is 10,000 generated
Markdown notes (16.4 MB, a 3,000-word invented vocabulary, one planted word).

## Counts

113 scenarios in 16 groups: **81 PASS, 25 SURPRISE, 7 FAIL**. No crash, hang or
non-zero exit where the documents promise success. PASS means what the documents (or,
where they are silent, a household user) lead one to expect happened; SURPRISE means it
works but not as a reader of the documents or a household user would expect; FAIL means
a wrong result or a promise not kept.

Not run: the Dart example app (`bindings/dart/search_simpli/example`) is a Flutter
Android instrumentation test that needs a device or an emulator; the Android and iOS
libraries were not built (`SS_ANDROID_NDK` not set, as the README says to expect).

**Timings are indications from one run.** At 18:42 the 10,000-note index took 1.15 s
(peak 218 MiB), a whole `query` process 0.02 s and a direct `search` 1.18 s. From 18:50
on, with another agent's Flutter tests and `fseventsd` each at about 100 % CPU, the same
binary on the same index took 0.14 s of CPU per `query` (seven times more), and the
table's S02 row (query 152 ms, direct search 6.3 s) is from that period. The 18:42
numbers agree with the README's; the later ones say the machine was slower, not the
engine (`pmset -g log`: no sleep in between; user active).

## Findings, ranked

Each has a one-line reproduction over a folder `f` (or the scenario's own folder,
`home` and its index `idx`, which `run_scenarios.py` builds with
`searchd index home --out idx --filename-index`).

### Wrong results

1. **A question typed whole is answered from the wrong file when one of its question
   words is close to a word in another file** (C20, M02). `where` is corrected to `were`
   by fuzzy-v1 and scores 7.95 in the running-club note; `compass`, the word that
   matters, scores 4.95 in the diary. The same through MCP `search_knowledge`, the Python
   reference agrees (it is a shared rule, not an engine bug).
   `searchd query idx "where did I find the compass"` → `notes/running club.txt` first.
2. **Common words decide the ranking of a question in a small folder** (C21, C22). There
   is no down-weighting of question words, and in a folder of a few dozen files `does`
   or `read` is rare enough to outweigh the content word: `when does the insurance renew`
   puts the café note (`does a good flat white`) first; `what did Pip read in February`
   puts `main.py` (`handle.read()`) first, the reading log third.
   `searchd query idx "when does the insurance renew"`.
3. **A question with no answer looks like an answer** (C26). `what is the capital of
   France` returns three hits on `is`, `the`, `of`; the human output shows the same
   `score=0.016393 / 0.016129 / 0.015873` for every query's first three hits (they are
   reciprocal-rank-fusion values, so they never say how strong a match was), and the
   evidence carries no field that says the match is weak, although its
   `answer_policy` asks the model to "say when evidence is insufficient".
   `searchd evidence idx "what is the capital of France" --top-k 3`.
4. **Whole kinds of household text are silently invisible** (I02, I10, C24, C25). Only
   19 extensions are read (`zig/src/core/indexer.zig`, `default_extensions`). Not
   indexed, and not counted anywhere: `.csv`, `.tsv`, `.log`, `.xml`, `.ini`, `.org`,
   `.srt`, `.text`, a `README` or `Makefile` with no extension, and **`.markdown`**,
   although `docs/incremental-indexing.md` says Markdown is chunked by `md-section-v1`
   "for `.md`/`.markdown`". So `furnace filter` answers from the vacuum manual, the
   furnace log never appears; `where is the spare house key` gets three unrelated hits
   while the answer is in `README`. `printf '# T\nkindword\n' > f/a.markdown; searchd search f kindword` → nothing, exit 0, no stderr line.
5. **File-name search does not fold accents; content search does** (F05). `cafe` finds
   `café notes.md` by content but not by name. `searchd query idx cafe --search-field filename` → no result.
6. **A decimal number is split** (C27). `142.50` finds the receipt first, then diary lines
   `Day 142` and `Day 50`. `searchd query idx 142.50`.
7. **`renew` does not reach `renewal`** (C07): word forms cover `ran`/`running`,
   `swim`/`swimming`, `battery`/`batteries`, not this derivation. `searchd query idx renew` → nothing.

### Crashes and unclear errors

No crash, hang or wrong exit code for a documented success. The errors a normal user
meets are unclear in four ways:

8. **`error: FileNotFound` / `error: AccessDenied` with no path and no hint** (X01, X02).
   `searchd query home x` (a folder that is not an index) and `searchd query missing x`
   both print `error: FileNotFound`; `searchd index missing --out x` the same;
   `searchd index noread --out x` prints `error: AccessDenied`. `searchd search` names
   the folder for the same mistakes (D06).
9. **Three error formats** (X04): `error: FileNotFound`, `searchd: SS_ERR_INVALID_ARGUMENT: empty query`,
   `searchd: unknown flag for query: ...`, `error: FilenameIndexUnavailable: ...`. A script
   cannot match one prefix.
10. **The empty query has three outcomes** (N05): `search` exit 2 (documented), `query`
    and `evidence` exit 0 (documented), `find` exit 1 (`SS_ERR_INVALID_ARGUMENT`). A bad
    `find --cursor` is also exit 1, while other bad values are exit 2.
11. **`find` says `truncated: a file in scope was not indexed in full` on every query**
    once any file of the index was skipped (N06), here the 11 MiB file and the binary
    file, even when the one answer is complete. `searchd find idx faucet`.
12. `WriterBusy` (U08) is one line, exit 1, with no word that the other writer will
    finish and a retry will work.

### Document mismatches

13. **README: "`query` prints ranked passages for a person"** (Q02). It prints
    `path:lines score=...` only; the Python reference prints the passage text.
14. **`searchd --help` leaves out flags the README names** (Q06): `index` does not list

15. **`.markdown`** (finding 4): `docs/incremental-indexing.md` names it; the extension list

16. **`docs/direct-search.md`'s comparison table says an index is "about 4.4 times the

17. **The README's size, 1,151,208 B, is S6-T9's**; `main` `87bfd35` builds 1,151,720 B.
18. **The Python reference does not select the same files** (B03): it indexes the link to
    a file and the 11 MiB file that `searchd` skips. The README calls it the behavioural

19. **`serve --http`** (R04): a `GET` is answered `200` with a JSON-RPC parse error, and

    say neither.

### Rough edges

20. **No-op `--update` publishes a new generation** (U01, U06): every section written
    again; with the default (no `--keep-generations`) five updates of an unchanged
    566 KB index left 3.4 MB on disk. `--keep-generations 2` brought it to 1.1 MB.
21. **Paths differ between outputs** (Q04, E04): `find` prints `r-legacy/notes/...`,
    `query` prints `notes/...`; `query --json` carries no `root_id` and no content, so a
    caller that wants to read the cited span must know the root is `r-legacy`.
22. **The full `index` summary does not name the files it left out** (I06); only
    `--update` lists `too_large_paths` and `unreadable_paths`; `search` counts them on
    stderr without names.
23. **Links are silently skipped** (I03): a link to a file, a link to a folder (common in
    synced folders) and a dangling link are neither indexed nor counted.
24. **An index directory inside the folder indexes itself** (I07): `INDEX-STATE.json` is a
    `.json` file and is indexed on the next `--update` unless the directory is named
    `.search` or starts with a dot.
25. **No matched terms on content results** (E02): when `vaccum` is corrected to
    `vacuum`, or `battery` matched `batteries`, neither the text output nor the evidence
    says which word matched; only `--search-field both` and `find` carry terms or offsets.
26. **A BOM file's evidence content starts with U+FEFF** (E08); `read-span` strips it.
27. **File-name search is the base name only, exact** (F06, F07, F08): a folder name
    (`weather` for `weather-station/`), a misspelling (`plumbr`) and a word form
    (`gardens`) find nothing.
28. `--top-k 500` is accepted on the command line (C31); the RPC refuses over 100.

## Gaps for the text-search priority

What a household user would expect of "find the relevant files for a question and answer
from the relevant parts", that the engine cannot do today:

- **Read the files a household has.** CSV, TSV, logs, `.markdown`, `.text`, XML, INI,
  subtitles and files with no extension are not read and not reported; there is no
  content sniffing (a text file with an unknown extension is skipped, a binary file named
  `.txt` is only caught by its invalid UTF-8). Links are not followed. A file over
  10 MiB is dropped whole, not read in part.
- **Treat a typed question as a question.** No stop words or question-word handling, and
  fuzzy correction applies to short common words (`where` → `were`), so in a small folder
  the function words choose the file (findings 1-2).
- **Say "not found".** No score threshold or confidence on content results, uniform RRF
  scores in the human output, no field for weak evidence (finding 3); a caller cannot
  tell an answer from noise.
- **Point at the answer, not the chunk.** `query` and `evidence` cite a chunk (26 lines
  of the diary for a one-line answer); only `find` gives match offsets. The human
  `query` shows no text at all.
- **Phrases and proximity in the search box's ranked mode.** Phrase matching exists in
  `find` only; `query` ranks `compost bin` and `bin compost` alike.
- **Match names as people type them.** File-name search has no accent folding, no
  fuzzy, no word forms and no folder names (findings 5, 27).
- **Numbers and dates as written.** Decimals are split (`142.50`); `March 2027`,
  `2027-03` and `03/2027` are different tokens.
- **Related words.** Lexical only: `renew`/`renewal`, `cost`/`paid` do not meet (the
  README says semantic matches are not there yet).
- **Keep up with a folder.** No watcher; every `--update` reads and hashes every file
  and publishes a generation even when nothing changed.
